# Environment reference

`.env.example` is the single template. Copy it to `.env.local` for development.
It includes application settings and commented inventories for optional tooling,
the experimental worker, and Bridge release CI. Uncomment these only in their
intended runtime. Do not copy all development settings into production.

This inventory was checked against the working tree on 2026-10-22: Next.js,
Convex, Node scripts, the Rust Bridge, the Cloudflare worker, tests, and GitHub
workflows. It covers direct reads, dynamic model configuration, and the local
instance environment. Values supplied by operating systems and platforms, or
generated internally by launchers, are listed separately at the end.

## Application and Convex

| Key | Value |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | Browser origin, `http://localhost:3000` locally; the HTTPS app origin in production. |
| `SPECTRA_APP_URL` | App origin reachable **from Convex**, used for scheduled AI and ManageBac callbacks. Blank keeps AI runs inline locally. A local Convex backend can reach a local app; hosted Convex needs a publicly reachable URL. Required HTTPS origin in production. |
| `SPECTRA_WEB_HOST` | Bind address; `localhost` locally, `0.0.0.0` when the server must accept external connections. |
| `SPECTRA_WEB_PORT` | Web port, `3000` by default. Keep browser URLs in sync. |
| `CONVEX_DEPLOYMENT` | Exact deployment selector written by `npx convex dev`, for example `local:<name>`, `dev:<name>`, or `prod:<name>`. Let the CLI choose it; do not guess from the port. |
| `NEXT_PUBLIC_CONVEX_URL` | Convex client API URL. Current root setup uses `http://127.0.0.1:3002`; hosted deployments use their `.convex.cloud` URL. |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | Convex HTTP-actions URL, local port `3003` in the default instance; hosted deployments use `.convex.site`. Generated by the local harness/Convex CLI, currently no direct application read. |
| `SPECTRA_CONVEX_URL` | Optional server health-check URL override; also the native Bridge runtime/build deployment URL. For Bridge, use the same Convex deployment as the app. Root `.env.local` is not automatically loaded by Rust. |
| `CONVEX_URL` | Compatibility alias for the gateway/load-test client. Omit when `NEXT_PUBLIC_CONVEX_URL` is set. |

## Authentication, encryption, and roles

| Key | Value |
| --- | --- |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | Publishable key from the matching Clerk application: development `pk_test_...`, production `pk_live_...`. |
| `CLERK_SECRET_KEY` | Matching Clerk server key, `sk_test_...` locally or `sk_live_...` in production. |
| `CLERK_JWT_ISSUER_DOMAIN` | Clerk JWT issuer URL for that application; configure in Convex as well. |
| `CLERK_WEBHOOK_SECRET` | Signing secret for the Clerk webhook endpoint `/api/webhooks/clerk`. Needed when account-sync webhooks are delivered. |
| `CLERK_PUBLISHABLE_KEY` | Legacy server-side alias. Leave unset when the public key is configured. |
| `SPECTRA_MASTER_ENCRYPTION_KEY` | Exactly 32 random bytes encoded as base64. Preserve an existing value: changing it affects decryption of stored secrets. |
| `SPECTRA_SECRET_BRIDGE_KEY` | Independent random string of at least 32 characters; same value in Next.js and Convex. |
| `SPECTRA_CONNECTOR_BRIDGE_KEY` | Another independent random string of at least 32 characters; same value in Next.js and Convex for ManageBac. |
| `SPECTRA_COLLAB_BRIDGE_KEY` | Another independent random string of at least 32 characters; same value in Next.js, gateway, and Convex. Also signs scheduled callbacks. |
| `SPECTRA_COLLAB_TOKEN_SECRET` | Another independent random string of at least 32 characters; same value in Next.js and collaboration gateway. |
| `SPECTRA_AGENT_EVAL_BRIDGE_KEY` | Optional independent secret of at least 32 characters, matching Next.js and Convex. **Leave unset/commented**, rather than assigning an empty value, to fall back to `SPECTRA_SECRET_BRIDGE_KEY`. The current code uses `??`, so an empty string blocks the fallback. |
| `SPECTRA_AGENT_MANIFEST_SIGNING_KEY` | Optional independent secret of at least 32 characters; unset uses `SPECTRA_SECRET_BRIDGE_KEY`. |
| `SPECTRA_MANAGEBAC_WORKER_HTTP_KEY` | Optional independent secret of at least 32 characters; unset derives a key from `SPECTRA_CONNECTOR_BRIDGE_KEY`. |
| `SUPER_ADMIN_EMAILS` | Comma-separated platform operator emails; same list in Next.js and Convex. |
| `ADMIN_EMAILS` | Optional comma-separated legacy admin list. The helper is still present; leave blank if unused. |

Generate a new secret only when needed with
`node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`.
Each trust boundary should receive its own value. Existing local secrets were
preserved during consolidation.

## AI and embeddings

| Key | Value |
| --- | --- |
| `OPENROUTER_API_KEY` | OpenRouter API key for the app and Convex AI actions. |
| `SPECTRA_MODEL_ID` | Required OpenRouter model ID in `vendor/model` form. Keep your chosen available model. |
| `SPECTRA_REASONING_PROFILE` | Required: `none`, `minimal`, `low`, `medium`, `high`, or `xhigh`, supported by the selected model. |
| `SPECTRA_MODEL_PROVIDER` | Required OpenRouter provider name that actually serves the primary model. |
| `SPECTRA_FALLBACK_MODEL_ID` | Optional recovery model; blank uses the primary model. |
| `SPECTRA_FALLBACK_PROVIDERS` | Comma-separated providers that serve the recovery model; blank uses the primary provider. The list is a strict provider allowlist, so it must be compatible with the recovery model. |
| `SPECTRA_ALLOW_PROVIDER_FALLBACKS` | `true` enables the recovery route; `false` disables it. |
| `SPECTRA_JUDGE_MODEL_ID` | Optional independent evaluation model; blank grades with the primary model and reports self-evaluation. |
| `SPECTRA_DAILY_MODEL_ID` | Optional daily-brief model ID; blank uses the primary model. |
| `SPECTRA_SEARCH_MODEL_ID` | Optional web-search model ID; blank uses the primary model. |
| `SPECTRA_MODEL_CONTEXT_TOKENS` | Optional numeric context-window override, greater than `8000`; blank queries model metadata and falls back to `128000` tokens. |
| `ARTIFICIAL_ANALYSIS_API_KEY` | Optional Artificial Analysis key for the Convex model catalog integration. |
| `SPECTRA_EMBEDDING_MODEL` | Optional Convex embedding model supporting 256-dimensional output; the previous template used `openai/text-embedding-3-small`. Blank disables vectors and keeps full-text retrieval. |
| `SPECTRA_EMBEDDING_PROVIDER` | Optional pinned OpenRouter embedding provider; the previous template paired the model above with `OpenAI`. Blank permits normal routing. |
| `OPENROUTER_APP_NAME` | Legacy metadata setting accepted by the env schema and evaluation loader. No current request path uses it to choose the request title. Safe to omit; existing value preserved. |
| `OPENROUTER_SITE_URL` | Legacy metadata setting accepted by the env schema and evaluation loader. Current request paths use `NEXT_PUBLIC_APP_URL` for the referrer. Safe to omit; existing value preserved. |

The model/provider pairs above describe project configuration, not a live check
of provider availability. If you change embedding configuration, reindex with
`npx convex run semanticIndex:startBackfill` and
`npx convex run memory:backfillEmbeddings '{"limit":200}'`.

## Runtime placement

Next.js reads root `.env.local`. Convex has a **separate deployment environment**;
adding a key locally does not configure hosted Convex. Configure these in the
selected Convex deployment when their feature is enabled:

- `CLERK_JWT_ISSUER_DOMAIN`, `OPENROUTER_API_KEY`, `SUPER_ADMIN_EMAILS`.
- `SPECTRA_SECRET_BRIDGE_KEY`, `SPECTRA_COLLAB_BRIDGE_KEY`, `SPECTRA_CONNECTOR_BRIDGE_KEY`.
- `SPECTRA_APP_URL` for scheduled work.
- `SPECTRA_AGENT_EVAL_BRIDGE_KEY` only if choosing an explicit independent key.
- `ARTIFICIAL_ANALYSIS_API_KEY`, `SPECTRA_EMBEDDING_MODEL`, `SPECTRA_EMBEDDING_PROVIDER` when enabled.
- Local fixture/rehearsal controls only in the corresponding local deployment.

The local-instance harness mirrors the first five groups through
`CONVEX_ENV_KEYS` in `scripts/local/stack-config.mjs`, including the embedding
settings added during this audit. It only mirrors nonempty values; disabling a
previously configured Convex setting may require explicitly removing it there.

The following are supplied or generated by their runtime and intentionally
have no configurable entries in `.env.example`:

- `NODE_ENV` and `VERCEL_ENV`: Next/launcher and hosting platform mode.
- `PATH`, `SystemRoot`, `HOME`, `APPDATA`, `LOCALAPPDATA`, `TEMP`, `COMPUTERNAME`, `HOSTNAME`,
  and `TZ`: operating-system environment; a test temporarily changes `TZ`.
- `GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_OUTPUT`, `GITHUB_REF_NAME`, `RUNNER_OS`,
  `RELEASES_REPO`: supplied by GitHub Actions or mapped internally from release
  repository configuration.
- `CARGO_PKG_VERSION`: Cargo-generated version metadata.
- `CONVEX_LOCAL_BACKEND_STARTUP_TIMEOUT_SECS`: set to `900` by the local launcher.
- `SPECTRA_COLLAB_SERVED_BY`: internal supported-gateway launcher marker.
- `SEMANTIC_EVAL_ENV_SOURCE`: evaluation loader's output metadata.
- `SPECTRA_BRIDGE_EXE` and `SPECTRA_BRIDGE_WORKDIR`: set by Bridge when creating
  the Windows autostart task.
- The single-letter `S` env read occurs only in an inline env-loader test.
