## Efficiency and implementation boundaries

- No schema/index changes, additional Convex subscriptions, periodic API polling or new background queries.
- Publication uses the already prepared projection in the existing append. Native comparison reuses JSON already parsed for region analysis; the legacy path reuses its changed-region calculation. Other artifacts and ordinary native quiz edits retain checkpoint batching.
- The document fix marks at most two top-level selection endpoints. Other blocks retain the existing offscreen layout optimization; no document-wide rendering fallback, observer, timer or private ProseMirror API was added.
- Quiz submission tracks already running promises and retains the existing final save pass. Same-question saves are ordered without adding requests; a failed earlier request does not prevent the later edit from saving. It does not add a save request per keystroke. Question types use a memoized lookup so the synchronization indicator does not introduce a repeated linear search for each answer. Failed final saves stop submission rather than initiating a polling/retry loop.
- Semantic output-contract checks add a judge completion during an explicitly requested evaluation, through the existing metered evaluation path. They do not add ordinary page-load or Convex work. These scores still do not establish independently verified truth. No arbitrary phrase check was weakened or existing failure declared a pass.
- Native changes perform local settings/permission checks around connection operations and startup. No sync scan, payload hashing, polling cadence or reconciliation interval was broadened.
- Local output isolation affects build files only, with no added application loading or Convex work.

## Native runtime boundary

The Rust workspace and current Windows debug executable compile. However, the execution tool rejected the attempt to temporarily stop the running original Bridge and start the new executable against a disposable journal. The raw error was `exec_command failed: CreateProcess … Rejected … rejected: blocked by policy`. This establishes a process-launch rejection before the command executed. It supplies no policy identifier or detailed reason, and does not establish whether an automatic reviewer agent or another execution-policy component made that decision. Earlier conversation wording attributing it specifically to automatic approval review was too definite. The original helper remained at its original PID/path; the rejected command did not change its journal, credential or selected files. No retry through another process-control mechanism was made.

Consequently, **the running installed helper does not contain these new native changes**. The new debug build is `bridge/target/debug/spectra-bridge.exe`; the original running binary is `bridge/target/local/release/spectra-bridge.exe`. Before launch, package/install the intended build and rehearse: same-owner reconnect with selections; cancelled/failed pairing; keyring unavailable versus genuinely deleted key; revoked device; account switch; deployment switch; unavailable legacy folder; individual/multi-file selections; restart; disconnect while a picker is open; and active watchers/pending writes during ownership change. Use disposable files, preserve owner cloud devices, and verify neither old folder permissions nor cloud mount IDs migrate to a new owner. A safety guard passing unit tests is not a substitute for that rehearsal.

Windows and macOS are both required launch targets in the existing audit charter. This Windows source/build/test work does **not** verify macOS packaging, keyring behavior, native prompts or file synchronization. Real Mac acceptance remains required.
