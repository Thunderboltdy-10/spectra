## Delivered contract

Normal asset and Office-original routes call `beginUpload`, stream request bodies directly to Convex generated storage upload URLs, and invoke a server-side verification action. They no longer place whole product files in `v.bytes` action arguments. The verifier reads the stored object, checks exact byte count, normalized SHA-256, MIME and magic-byte signature, then performs one receipt-bound internal commit. Current artifact capability and active state are rechecked at intent, verification, and commit. Editing peers with `modify` capability may upload; artifact ownership is not required.

Convex documentation checked during implementation: storage upload POSTs have no file-size limit but a two-minute POST timeout; HTTP action requests/responses are 20 MiB; ordinary function arguments are 16 MiB and Node action arguments are 5 MiB. Product ceilings therefore remain `100,000,000` bytes for assets and `80,000,000` bytes for import originals, while legacy direct `v.bytes` compatibility actions reject payloads above 4 MiB with an explicit transport error.

Storage checksum metadata is normalized through `shared/intake-integrity.ts`: accepted hex and base64/base64url SHA-256 encodings are converted to one lowercase hex representation; base64 is never lowercased as text. Both HTTP-upload verification and direct action materialization use the same MIME/signature validator. Quarantine records retain only server-created candidates, and metering/audit writes use idempotency keys.

Imports capture target version and live Yjs state-vector preconditions, immutable parsed-content hashes, and a commit receipt. `complete(imported)` requires content and rejects hollow default content. `commitImport` rechecks the active artifact and both preconditions before creating the canonical version; identical committed retries still return the existing version before obsolete-base checks.

Rich imported image data URLs are materialized through durable asset identities with dimensions, alt text and source reference, then persisted as `/api/spectra/assets/content?assetId=...` references. Failed/quarantined materialization never replaces content with an image URL. The existing authorized content route resolves bytes server-side and remains private.

`releaseArtifactIntakePage` is typed, bounded, cursor-resumable, owner/tombstone checked in the transaction, and uses one receipt per physical storage object. It traverses asset/import rows with Convex pagination, skips rows with an explicit retention owner, and releases normal successful objects, originals, abandoned attempts and duplicate candidates exactly once. Physical-byte metering is separate from row mutation.

## Migration and legacy policy

Existing rows without the new revision/hash/retention/commit fields continue through narrow legacy branches. They are never given new ownership authority from a caller-supplied storage ID. New jobs always bind upload and commit receipts and capture the live base.
