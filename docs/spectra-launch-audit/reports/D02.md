## Delivered

- Direct delete and owner Trash purge now share the durable deletion coordinator. The front door tombstones the artifact, increments `deletionGeneration`, cancels/hides embeds, creates an `artifactDeletionJobs` receipt, and removes only the requested peer placement from the tree. The deleted artifact row remains the owner authorization/retry anchor.
- Deletion runs finite, job-scoped cursor phases for placements, versions, D01 intake receipts, runtime builds, user state, comments/notifications, memory claims/evidence/relations, links, replicas, sync operations/conflicts, Bridge write/filesystem requests, collaboration rooms/updates/snapshots/claims, and artifact-scoped runs/results. Cursors are versioned and reject cross-artifact or cross-generation reuse. Retained versions and terminal Bridge rows advance traversal and contribute explicit counters.
- Worker generation checks are performed before every page. Retryable failures persist `attemptCount`, `lastError`, and exponential `nextAttemptAt`; the authorized owner can call `spectraArtifactDeletion.retry`. Tight failure loops are avoided.
- Runtime build storage is released with idempotent negative storage metering. D01 intake release remains the only owner of asset/import receipt bytes, preserving pinned/native/shared retention owners.
- Embed creation accepts an operation key, stores a provisional row for editor-backed artifact placements, rejects conflicting reuse, and exposes `confirmPlacement`. The document, whiteboard, and references panel callers now pass operation identity and confirm only after their canonical writer completes. Source deletion or access revocation causes truthful confirmation failure.

## Family disposition

| Family | Disposition and eventual release |
| --- | --- |
| Tree placements | Owner traversal removes all work placements and their links; peer purge removes only that peer node. |
| Versions/snapshots | Unpinned versions are deleted and snapshot references released through `releaseSnapshotObject`; pinned references survive until their last owner disappears. |
| Assets/import originals | Delegated to D01 `releaseArtifactIntakePage`; retained/native/pinned rows remain with their documented retention owner. |
| Runtime builds | Build rows and owned storage are released once with `runtime-release:<buildId>` metering keys. |
| User state/comments | Artifact-scoped state, comments, comment preferences, and notification rows are removed. |
| Memory | Claims are redacted, evidence and both relation directions are traversed in child pages; capsule authorization is never inferred from stale claim rows. |
| Links/replicas/sync | Artifact links, replicas, sync operations, and conflicts are traversed by artifact indexes. |
| Bridge | Queued/claimed requests become terminal `failed` with `work-deleted`; existing terminal audit rows are counted and skipped. |
| Collaboration | Region claims, updates, snapshots, and empty rooms are drained without removing surviving artifacts. |
| Runs/results | Descendants are removed only for the deleted target; result cards explicitly tied to another artifact remain. |
| Embeds/access | Placement tombstones and pending access-request cancellation preserve identity while denying deleted-source access. |

## Recovery and migration

Deploy the schema/backend together, then allow scheduled `spectraArtifactDeletion.process` invocations to advance each receipt. For a terminal repair, an authorized owner invokes `spectraArtifactDeletion.retry({ jobId })`; the same generation and cursor continue safely. Do not remove deleted artifact tombstones until retained snapshot/intake/runtime owners have their independent release path.
