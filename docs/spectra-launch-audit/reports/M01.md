## Changed contracts

- `spectraThreads:list` returns display metadata and a bounded `contexts` projection. It no longer discovers runs/created artifacts per thread.
- `spectraThreads:get` keeps `messages`/`traces` compatibility, but the initial message page is bounded and trace children are bounded. New fields: `messagePage`, `tracePage`, `activeExecution`, and per-trace `historyTruncated`.
- `spectraThreads:listMessages(threadId, before?, limit?)` returns `{ messages, hasOlder, olderBefore }`. Authorization remains `requireOwnedThread` in the same transaction.
- `spectraThreads:getRunTrace(threadId, runId, eventAfter?, limit?)` verifies the run belongs to the authorized thread before reading children and returns sequence-aware `eventPage` metadata.
- `spectraThreads:backfillReadMetadata({ limit? })` is an idempotent rollout helper. `readSchemaVersion=1` marks rows migrated; `previewText`, `contextWorkspaceIds`, and `contextArtifactIds` are bounded caches, not content authority.
- `artifactDeletionJobs` records generation, phase, cursor-compatible state, row/byte counters, and terminal error. Owner rows are tombstoned and primary placements removed before the job is scheduled; descendants/storage are deleted only by authorized owner cleanup.
- `artifactEmbeds.create` accepts `placementOperationId`; repeated calls for the same container/op return the existing live embed. `placementState` distinguishes confirmed and removed rows.

M02 integration boundary remains unchanged: its asset/import receipt and release hooks can be consumed by the `children` phase without moving upload finalization into M01.

## Migration and rollback

2. Run `spectraThreads:backfillReadMetadata` in bounded batches until `complete=true`; retrying a batch is safe.
3. Rebuild the local Convex runtime, then run the changed-path browser check against the rebuilt functions.
4. Keep the old full-detail response consumer contract during rollout; migrate any remaining callers to `listMessages`/`getRunTrace`, then remove legacy fan-out only after caller search is empty.
5. To roll back read shaping, keep `get` available and stop calling the new page endpoints; cached metadata can remain because it is versioned and non-authoritative.
6. To roll back deletion scheduling, disable new front-door requests and drain existing `artifactDeletionJobs` with `process`; do not restore tombstoned owner rows without a reviewed recovery procedure. Placement removal and source-object deletion remain distinct.

## Workload and cost worksheet

The reproducible fixture in `convex/spectraThreads-read-cost.test.ts` uses one authorized account, a 40-message thread, a 32-message initial read and an 8-message older page. For the parent combined run, use account-scoped samples covering: 4-message and 2,000-message threads, 100/1,000 library items, active and idle Bridge, and a dense document/workbook. Record cold/warm latency, Convex function calls, response bytes, and the deployment's actual database I/O counters at the same concurrency before and after.

Use current official price inputs at measurement time rather than embedding a stale estimate:

- `DB_IO_price` = Convex documented database read/write unit price.
- `Storage_price` = Convex file-storage GB-month price.
- `Egress_price` = Convex documented egress price.
- `Compute_price` = Fly machine class/seconds actually used by the local-equivalent hosted deployment, if applicable.

For a measured interval:

```text
database_io_cost = (db_read_units * DB_IO_price) + (db_write_units * DB_IO_price)
storage_cost = (stored_GB_months * Storage_price)
egress_cost = (egress_GB * Egress_price)
compute_cost = (machine_seconds * Compute_price_per_second)
total = database_io_cost + storage_cost + egress_cost + compute_cost
```

Keep database I/O, storage, egress, and compute separate. Do not convert the shared W3 20–30 second traffic windows into a monthly per-user forecast.
