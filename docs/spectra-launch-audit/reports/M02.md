# M02 — durable intake and evidence

Date: 2026-09-10 Europe/Madrid

## Implemented contracts

### Asset receipt

`artifactAssets.beginUpload` authorizes the authenticated `modify` actor for a
specific artifact and records `uploadedByAccountId`, target artifact, path,
normalized media type, expected byte count, hexadecimal SHA-256 and a
server-generated `uploadReceipt`. The route validates request bytes, digest and
content magic before uploading through the existing Convex file-storage URL.

`artifactAssets.finalizeUpload` requires the receipt and re-checks owner,
artifact capability, stored byte count, normalized content type and Convex
storage SHA-256 (hexadecimal). It is retry-safe: active assets return the same
terminal result, and quarantined uploads remain quarantined. A mismatch commits
`status: quarantined`, records the candidate storage id for audit/reconciliation,
and returns `errorCode: ASSET_UPLOAD_INTEGRITY_FAILED`; it does not throw after
mutating state and it never deletes an arbitrary caller-supplied storage id.
`failUpload` follows the same rule. Cleanup remains an owner- and reference-
checked lifecycle hook for M01.

### Import receipt

`artifactImportJobs` retains the original upload by Convex storage id, original
size and digest, parser/fidelity state, and the target version captured at
begin. Completion accepts the existing canonical import content path but now
sanitizes inline `data:` media references to stable `inline-media:<sha256>`
references before persistence and enforces UTF-8 encoded size at 900,000 bytes,
below Convex's 1 MiB document limit. The 2,000,000-byte request ceiling allows
the real W3 DOCX completion payload (1,108,195 bytes) to be received while the
large inline image data is removed before the job row is written.

`changeGroups.commitImport` remains the sole canonical artifact writer. It is
idempotent through `artifactVersionId`, clears converted content after commit,
and rejects a late import with `ARTIFACT_IMPORT_REVISION_STALE` when the target
version no longer matches the artifact's current version. This preserves a
newer user draft for a safe retry/reopen instead of overwriting it.

### Evidence

Failed full-source fetches now produce `verified: false` source records with
their true URL/provider/snippet provenance. Evidence spans remain available for
diagnostics, while `verifyCitation` still rejects unverified sources. Full fetch
redirects are revalidated, DNS destinations are checked for IPv4, IPv6,
mapped/private/link-local ranges, and bounded response reads remain in force.

## Compatibility and remaining limits

- Existing Office lenses and the canonical Yjs/change-group save path remain
  authoritative. Broad native Office editing/export parity, image asset
  materialization from converted Office media, and unsupported feature coverage
  remain M03 scope; the sanitizer deliberately prevents inline base64 from
  reaching hot rows rather than claiming native image parity.
- PDF extraction keeps scripting disabled and bounded body reads in existing
  consumers. `pdfjs-dist`, Mammoth/XML, TipTap, ExcelJS/PPTXGenJS image-size
  and AI SDK advisories remain reachable consumer work for M03/M04; no blind
  `npm audit fix` or hosted parser was introduced.
- AI retry/lifecycle consumption of durable attachment/evidence references is
  M04 scope. M01 owns general deletion/read coordination; this package exposes
  only the receipt state and candidate/reference fields needed for that
  reconciliation.
- DNS resolution is validated before each fetch destination. A production
  transport that binds the validated address to the actual connection should be
  the next network-layer hardening step if the runtime's fetch dispatcher can
  support it without changing the existing source abstraction.
