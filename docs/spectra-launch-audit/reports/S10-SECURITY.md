## Repairs and reproduction

### P1 — publisher could delete unrelated stored bytes

`spectraRuntimeBuilds.fail` authenticated ownership of a pending runtime build, then deleted **any supplied storage ID**, without binding it to that build. A student owning an ordinary code artifact could create a publish attempt and call `fail({buildId, storageId: knownVictimId, reason})`. The victim's identifier must be known (for example, from a previously available download); this is not an ID-enumeration finding.

`convex/runtime-storage-security.test.ts` invokes the real public begin/fail handlers. Before repair, both an independent in-flight upload and a retained payload belonging to a different school's account became physically absent while the fail call returned `{failed:true}`. The unrelated retained row remained. These are deterministic disposable fixtures, not a live attack.

Repair: failure reporting never deletes client-named bytes. Finalization rejects a storage object already bound elsewhere through `storageHasOtherBinding`; this prevents introducing new cross-owner/cross-family aliases. The Bridge commit dedup branch also no longer deletes a caller-supplied redundant upload, because absence of a binding does not prove upload ownership. Caller-driven cleanup on rejected Bridge uploads was removed as well. Legitimate failure status and upload/dedup behavior remain available.

Residual: failed/redundant unbound uploads may remain until cleanup can prove provenance. This intentionally trades potential temporary storage cost for protection against arbitrary deletion. No retention interval was shortened or cleanup policy weakened for objects with established owners.

### P1 — Bridge trusted declared native hashes and poisoned dedup rows

`bridgeSync.beginPayloadUpload` and `commitPayloadUpload` trusted an active hash slot without verifying its storage bytes. New commits compared size only. A paired credential holder could submit a same-size body with an unrelated 64-character digest, and the real handler returned success and advanced local/cloud replica truth and the external receipt. A historical or maliciously poisoned active row was also returned as a dedup hit, even when a separate genuine upload was supplied.

Repair: compare actual storage SHA-256 using the shared base64/hex normalizer and verify declared, row and physical sizes before either adoption or dedup success. Recheck the existing slot at both begin and commit; no replica, payload row or receipt is advanced after an integrity rejection. This requires an active paired device and current artifact modify/cloud-content authority; it is not an unauthenticated remote write finding. Native consumers' independent digest checks remain relevant defense in depth.

`convex/bridge-payload-integrity.test.ts` reproduced the same-size false digest, poisoned begin/commit dedup, and inconsistent dedup sizes before repair. Current cases also verify genuine retries, single receipt with a known base, independent upload preservation, deactivated-account/revoked-device denial at both entry points, rejection of another device's replica, and rejection of another account's retained storage binding.

### P2 — genuine runtime publish failed digest representation check

`spectraRuntimeBuilds.finalize` compared Convex's encoded storage digest directly with caller hex. The genuine public begin/finalize fixture failed with `RUNTIME_UPLOAD_INTEGRITY_FAILED` before repair. It now uses `normalizeSha256`, matching the intake/native contract. Genuine publication/retrieval passes; foreign-account retrieval and false integrity remain denied. The new ownership check is verified separately; the prepatch malformed digest comparison already prevented the tested foreign finalization, so no prepatch successful alias is claimed.

### P3 — unnecessary device verifier disclosure

`bridge.devices` returned `credentialHash` to the owning web account while `overview` already removed it. The listing now omits the verifier. This was a high-entropy hash, not the paired credential itself; no credential recovery or cross-account leak was established. Real query regression failed before repair and passes now.
