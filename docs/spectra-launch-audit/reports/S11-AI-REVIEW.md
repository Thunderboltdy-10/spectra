## Persistent continuation recommendation

Use one existing run/operation protocol. Before requesting clarification, persist a candidate graph with stable operation indexes, full active request, compatible steering, source handles and authoritative receipt references. Candidate storage is not authorization and is not a saved artifact. A rejected approval must remain rejected for its exact scope, and a changed scope requires a fresh decision. On continuation, reload the graph, reconcile committed receipts, re-read changed artifact revisions, then validate only the remaining candidate work. Keep actual receipts separate from model-authored summaries.

Deliver compatible steering at a safe model/tool/execution boundary. Cancel pending work only where the steer conflicts, and keep already committed receipts. Stop remains an explicit durable cancellation transition. Compaction should summarize expendable evidence while preserving the current user instructions, outstanding graph, decisions and receipts as lossless structured state, with recoverable references to omitted sources. This is one coordinated backend/runtime/context change; splitting it into prompt-only patches would leave the loss paths intact.
