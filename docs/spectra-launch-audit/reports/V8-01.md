## Outcome 4 — blocked: resource import/reopen/revocation and peer proof

Provider resource metadata was fetched for the selected class and is present in the provider logs, but the current product surface does not expose a clickable provider-resource import action. `RecordLine` renders provenance metadata; it does not create a student artifact. `ensureResourceProjection` currently keeps the projection keyed to the provider source and explicitly does not create a local tree node/artifact. The fixture URL is intentionally invalid, and no provider-resource byte download occurred.

Consequently, the following were not honestly passable in this phase:

- click provider resource → import a saved artifact → reopen it;
- missing/revoked provider resource recovery through the normal UI;
- a second real peer account opening a shared resource.

The peer permission/visibility contracts were covered by deterministic local tests, not a second live user: 6 focused test files, 25 tests passed across authority, public-share return, artifact access copy, agent publish gates, and presentation-native access.
