# W1-03 — Spectra AI reliability and prelaunch audit

## Result

**CONDITIONAL — not ready for a broad AI-quality launch claim.**

The run machinery has a credible bounded execution core: leases, heartbeat/cancellation, staged operations, approval/authority checks, act/verify settlement, durable terminal ordering, retry/recovery guards, target-resolution rules, model/tool budgets, and meaningful unit coverage. A narrower launch of targetable, no-attachment operations is plausible after the two transport fixes in this audit are shipped and the blocked dependency suites run in a correctly installed checkout.

The following remain release blockers for claiming the corresponding capability: attachment-aware retry, source-backed research artifacts, reliable resolution of vague/large-library targets, exact clarification continuation, transient read failure handling, and Windows/macOS bridge-backed Office workflows. The landing page is excluded from this audit. Deep bridge packaging is owned by W1-05; this report records only the AI-run dependency it creates.

## Scope and current architecture

In scope: the student-primary / student-teacher-peer Spectra AI run path, including school setup and ManageBac-facing retrieval, target/context gathering, model/tool turns, operations, retry/steer/stop, durable event delivery, research evidence handoff, attachment handling, and the bridge dependency for native file/Office work.

The effective lifecycle is:

`POST /api/spectra/run` → begin run / lease / heartbeat → bounded gather and target resolution → plan or agent loop → approval / act / verify → settle durable artifacts → terminal status and final event → client live stream plus durable polling.

Key implementation seams reviewed:

- `src/app/api/spectra/run/runtime.ts`: claim, lease, cancellation signal, context snapshot, operation execution, settlement, retry and recovery.
- `src/app/api/spectra/run/loop/gather.ts`, `resolve.ts`, and `plan.ts`: bounded discovery, exact/ambiguous target policy, agent prompt and direct read tools.
- `src/features/spectra/ai/agent-loop.ts`: turn, tool-call, repetition, elapsed-time and token budgets.
- `src/features/spectra/ai/openrouter-stream.ts` and `use-spectra-run.ts`: SSE/NDJSON parsing, live updates, durable observer and continuation/steering.
- `src/features/spectra/quality/rubrics.ts` and `sources/research/*`: quality/source contracts and research output.
- `bridge/bridge-app/tauri.conf.json` and `bridge/bridge-core/src/platform.rs`: only as an AI-run launch dependency; W1-05 owns the detailed bridge audit.

## Findings grouped by root cause

### A. Run inputs and evidence are not durable across the full lifecycle

#### W1-03-F01 — Retry drops all original attachments

- **Severity / confidence:** P1 for attachment-dependent launch claims; high confidence.
- **Code chain:** `handleSpectraRunRequest` prepares attachment bytes and `beginRun` stores only attachment metadata. The context snapshot likewise does not retain reusable attachment bytes or an object reference. In `runtime.ts`, the retry path constructs `retryPayload` with `attachments: []` at both the scheduled and inline retry call sites.
- **Impact:** A stopped, failed, or provider-retryable run that used an image, PDF, DOCX, XLSX, or PPTX cannot re-read the original source. The retry may fail, produce a context-degraded answer, or act on incomplete content while appearing to be a normal retry.
- **Neighboring contracts:** Attachment preprocessing has explicit size/page/media limits and native/visual routes, but those guarantees end at the first run. This is a lifecycle/storage seam, not an attachment parser defect.
- **Remedy:** Store a short-lived, permission-bound attachment object reference plus retention/expiry and content hash in the run input envelope, or make retry explicitly require reattachment. Do not put base64 bytes in the durable run row. Disable or label retry as unavailable when the source envelope has expired.

#### W1-03-F02 — Web research is not connected to the verified-source artifact contract

- **Severity / confidence:** P1 for source-backed artifact claims; high confidence.
- **Code chain:** `plan.ts` `web_search` returns titles, canonical URLs, snippets, authority labels, and partial/stopped-early state from `conductParallelResearch`. `full-source.ts` defines `buildResearchEvidence`, but the audited AI route has no call site that turns those results into durable evidence/source records. The quality rubric requires `document.sources` to be non-empty for source-driven work and requires each source to be verified, titled, and timestamped.
- **Impact:** The model can cite returned URLs in prose, but a created research document may lack durable source records and fail quality/repair, or rely on model-authored source metadata. Search snippets are not equivalent to fetched, verified evidence.
- **Remedy:** Make research a typed pipeline: search result → bounded fetch/verification → durable evidence/source IDs → operation `sourceRefs` bound server-side. Preserve `partial` and fetch failures in the artifact. The quality gate should accept only server-derived source IDs, never a model-claimed `verified` flag. Until then, label web search as answer-only/partial for artifact creation.

#### W1-03-F03 — Clarification continuation is identified by title substring, not an exact choice

- **Severity / confidence:** P2; high confidence.
- **Code chain:** `gather.ts` scans prior assistant metadata for the latest `choiceSelection`, then treats it as active when the current prompt contains `selection.title` as a case-insensitive substring. The selected run ID is used to locate the trace, but the client follow-up does not carry an opaque choice/clarification ID that must match the pending run/thread.
- **Impact:** A later, unrelated prompt containing an old option title can resurrect a stale clarification choice. Duplicate titles and natural language references make this especially risky for school libraries and ManageBac work items.
- **Remedy:** Return/store an opaque clarification ID and option ID; accept a selection only when it matches the pending clarification run and thread, with an explicit expiry. Keep title text for display only.

### B. Bounded context and unavailable reads can look authoritative

#### W1-03-F04 — Target discovery is bounded before deterministic search is guaranteed

- **Severity / confidence:** P2 for general-library edits; medium-high confidence.
- **Code chain:** Initial context loads an artifact catalog capped at 48, a thread map capped at 40, and a workspace index capped at 48. Prompt-derived search uses only the first three terms with a bounded result count. Hard context compaction can drop catalog/maps. The model can call `search_objects`, but a vague request must successfully choose that tool before the target is known.
- **Impact:** “Finish the older biology deck” or “fix this” can work when focus/thread/selection supplies identity, but a target outside the bounded orientation can be missed or can enter clarification without a deterministic search. The risk rises in larger student libraries and school setup workspaces.
- **Remedy:** Add a server-side bounded continuation: if the target is absent from orientation, run authoritative search using title/subject/time signals before planning a mutation; return an explicit context-degraded/unavailable result when search cannot establish identity. Preserve exact IDs and parent/path identity for duplicate names.

#### W1-03-F05 — Direct AI reads bypass the common retry/error policy

- **Severity / confidence:** P2; high confidence.
- **Code chain:** `plan.ts` calls `executeAgentReadTool` for `search_objects`, `read_artifact`, workspace/thread reads, school data, and memory. Several branches catch backend errors and return `[]`, `null`, or `*_unavailable`. The generic `SpectraToolExecutor` registry/retry path is used for application/mutation branches, not these direct reads.
- **Impact:** A transient Convex/provider read failure can look like an empty library, missing artifact, or no school records. The model may answer, clarify, or proceed with an incorrect “none found” interpretation rather than retrying or stating unavailable/partial.
- **Remedy:** Route direct reads through one bounded read executor with typed `unavailable`/`retryable` outcomes and a small retry budget, or preserve those outcomes explicitly in the agent tool result. Never collapse an infrastructure failure to a successful empty result.

### C. Terminal and event transport consistency

#### W1-03-F06 — Mixed terminal tool turns silently discarded sibling calls — fixed

- **Severity / confidence:** P2 before fix; high confidence.
- **Original code chain:** `agent-loop.ts` selected the first terminal tool and returned immediately, dropping sibling reads/actions emitted by a provider despite the prompt requiring one tool call per turn. The request body does not explicitly set `parallel_tool_calls: false`.
- **Fix:** A terminal tool now must be alone. In a malformed mixed turn, parallel-safe read siblings execute, terminal calls receive a structured `terminal_tool_must_be_alone` correction, and non-read siblings receive `terminal_mixed_turn_action_not_executed` without side effects. The model can use read results and retry the terminal tool alone.
- **Evidence:** New `agent-loop.test.ts` regression; focused suite passed.

#### W1-03-F07 — Final SSE/NDJSON record could be lost without a trailing newline — fixed

- **Severity / confidence:** P2 operationally; high confidence in parser defect, medium operational likelihood.
- **Original code chain:** The server public/agent SSE readers and client NDJSON reader retained the final split fragment as an incomplete buffer even after `done === true`. A provider/proxy closing immediately after a valid final record could therefore drop a terminal tool call or final event. The normal server NDJSON writer currently appends `\\n`, so this is defensive for upstream/proxy behavior.
- **Fix:** On stream close, process the residual line instead of retaining it; added an agent SSE regression that closes after a final tool-call record with no newline. Focused suite passed.
- **Impact if unfixed:** Stale live exchange, missing terminal card/final event, or disagreement between durable status and live UI.

#### W1-03-F08 — Durable observer hides malformed events and poll failures

- **Severity / confidence:** P2; medium confidence pending browser evidence.
- **Code chain:** `use-spectra-run.ts` skips malformed durable payloads with a bare parse catch and swallows the outer observer failure as a transient error. Authoritative status polling can continue, but there is no explicit degraded/re-sync state for a live exchange or final callback that missed an event.
- **Impact:** The run may eventually settle correctly in durable state while the active tab remains stale or misses a final card. This is a recoverability/observability gap rather than an authority bypass.
- **Remedy:** Record observer degradation, force a bounded cursor/status resync, and expose a small “reconnecting / refreshed from durable state” state. Add malformed-event and reconnect browser tests.

### D. Steering and platform-dependent execution

#### W1-03-F09 — Steering is stop-plus-new-run without a durable supersession contract

- **Severity / confidence:** P2 for long-running/interactive runs; medium confidence.
- **Code chain:** Client steering posts stop for the target run, refreshes tabs, then starts a new run in the target thread. One queued steering prompt is retained; there is no durable steering/supersession event visible in the run contract. Old and new event delivery depends on stop timing and cursor relevance.
- **Impact:** A late old-run event or stop response can race the new run and overwrite live state, especially while a model read or visual prepass is in flight. The server’s cleanup guards reduce risk, but this needs a live scenario.
- **Remedy:** Add server-side supersedes/superseded-by identifiers and idempotent client filtering; make the new run authoritative for the thread only after the old run reaches a terminal cancellation state.

#### W1-03-F10 — AI Office/file workflows depend on unproven Windows/macOS bridge launch support

- **Severity / confidence:** P1 for cross-platform Office/file claims; medium-high confidence as a launch dependency, W1-05 owns the deep finding.
- **Code chain:** The AI can stage native file/Office operations, but the inspected bridge bundle declares an NSIS Windows target and Windows-specific autostart/identity/file-lock paths. The non-Windows Rust implementation is a generic fallback, and no macOS bundle/sign/notarization/autostart acceptance evidence was found in the audited source. The app CSP also names the loopback bridge endpoint.
- **Impact:** AI quality/authority may be correct while the actual Windows and macOS launch, connection, lock/save, or recovery workflow fails. This is particularly material for student/teacher Office artifact operations and school setup.
- **Remedy / ownership:** W1-05 must verify signed Windows and macOS packages, first launch, autostart, bridge-disconnected behavior, file locks, Office save collisions, and recovery. W1-03 should add AI scenarios against the connected/disconnected bridge and report the operation as unavailable/partial when the bridge is absent.

## Next-wave tests and implementation implications

Run these as browser/integration scenarios on both student and teacher peer accounts where applicable:

1. Create duplicate artifact titles, ask “rewrite the conclusion in [title],” choose one, then send an unrelated prompt containing the title. Confirm the old choice is not reused; verify exact artifact ID and clarification expiry.
2. Seed more than 48 artifacts with the intended target outside the initial catalog. Test a named request and a focused “fix this” request; verify deterministic search, read, and durable resolution without updating a same-title neighbor.
3. Attach an image, PDF, DOCX, XLSX, and PPTX in separate runs. Stop or induce a provider failure, click Retry, and verify the original source is restored or retry is explicitly blocked with a reattach message.
4. Request “write a source-backed brief with references.” Inspect durable `document.sources`, source URLs/evidence, quality state, partial search, and fetch failure. Confirm no model-authored source is marked verified.
5. Close provider SSE and run NDJSON after a valid final record with no newline; inject one malformed durable event and reconnect. Confirm live UI, durable status, final event, and cards converge.
6. Steer while a long read or visual prepass is active. Confirm the old run is terminally cancelled, the new run is the only final authority for the thread, and no late old event overwrites it.
7. Stop during provisional shell creation, visual prepass, act, and verify. Confirm no late staged/pending artifact resurrects and permissions remain intact.
8. Exercise ManageBac for ordinary student and teacher peers: disconnected, identity-required, stale cached, and refresh cases. AI must say unavailable/partial rather than “no classes/deadlines.”
9. On Windows and macOS, run a bridge-connected Office artifact operation, then repeat bridge-disconnected. Verify launch/package/autostart, lock/save collision, recovery, and explicit unavailable behavior. Coordinate with W1-05 for package evidence.

Implementation seams, in recommended order:

- Durable run-input/source envelope with permission-bound attachment references and retry expiry.
- Evidence-backed research contract from search to fetched evidence/source IDs to server-bound `sourceRefs`.
- Deterministic bounded target-search continuation plus exact clarification/option IDs.
- One typed read executor preserving unavailable/retryable outcomes, plus client observer degradation/resync state.
- Steering supersession/idempotency and cross-platform bridge acceptance criteria.

## Decisions for parent / Pablo

- **Release posture:** hold a broad launch claim for attachment retry, source-backed artifacts, vague/large-library edits, and bridge-backed Office workflows until F01–F05 and W1-05 are resolved and exercised live.
- **Permissible narrower scope:** targetable, no-attachment operations may proceed to a staged validation once the committed F06/F07 fixes are included and the missing dependency suites are rerun from a complete install.
- **Student/teacher and school setup:** preserve the peer model and require ManageBac connected/disconnected/identity-required scenarios; do not infer empty school data from failed reads.
- **Evidence handling:** keep this report and the private check log; do not publish private evidence or put attachment bytes in durable run records.
