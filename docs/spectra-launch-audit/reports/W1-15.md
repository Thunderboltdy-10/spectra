# W1-15 — bounded student/library, creation, persistence, and bridge recording audit

## Result

The ten assigned recordings (01–09, including 04b) show a usable core student workflow: library list/board navigation, creation of the advertised artifact types, folder move/rename/share, simple native document/sheet/presentation/card edits, readback for several native artifacts, and a simple native Undo. The recordings also expose two launch-relevant follow-ups: bridge/Office replica divergence is visible in the UI, and the school-class chooser is shown without loaded choices in the import flow.

This is recording evidence only. It is not a current-runtime, multi-user, Office round-trip, or ManageBac acceptance verdict. No app/source fixes were made.

## Findings grouped by root cause

### Bridge/Office state and school-shelf setup

#### W1-15-F01 — Bridge replica divergence is visible, with recovery semantics still unverified

- **User consequence:** A student or teacher opening a native Word resource can be told that the local device has newer edits while Spectra is waiting for a latest copy, or see multiple conflicts, without this recording proving which copy is authoritative or that a safe resolution/readback completes.
- **Severity:** important.
- **Confidence:** high that the states were visibly recorded; medium on the underlying defect because the capture does not identify whether the divergence was intentionally seeded, stale test data, or a live sync failure.
- **Recording evidence:** At approximately 14–18s in 04, `_bridge-sacrificial` shows `complex-structure.docx` with `3 conflicts`, then the opened resource shows `4 conflicts`, “This device · Has newer edits,” “Spectra · Waiting for the latest copy,” and a `Keep on this computer` action. The preview explicitly says unsupported Word features remain in the original package. See [04 bridge folder](<local-workspace> and [04 conflict details](<local-workspace>
- **Source correlation:** The recorded labels match `bridge/humanize.ts:187–188` and the native-copy action in `artifact-studio.tsx:5606`; this confirms the surface exists at the audited baseline, not that the state machine is correct.
- **Affected neighbors:** Bridge file watching, DOCX projection/merge, local/cloud replica truth, import/export, file-details status, and original-package preservation.
- **Bounded remedy:** Make the next bridge pass a deterministic two-sided state-machine test. Seed a known DOCX/XLSX/PPTX, edit one side, verify the other side’s status and revision, choose each available resolution action, and reopen from both Library and the native app. Hash the original package before/after. Do not collapse “has newer edits,” “waiting,” “conflict,” and “up to date” into one green success state.

#### W1-15-F02 — Class-shelf chooser shows no loaded classes in the Maths EE import recording

- **User consequence:** A student importing schoolwork may be asked to choose this year’s classes but see only a spinner/empty chooser and a generic `Continue`, making it unclear whether the school setup loaded, whether the work will be filed correctly, or whether skipping is safe.
- **Severity:** important, because school setup/ManageBac is a stated launch priority.
- **Confidence:** medium. The recording proves the sampled dialog state; it does not prove a persistent backend failure, delayed network response, or missing class data.
- **Recording evidence:** At approximately 26s in 04b, `Choose this year’s classes` is visible with loading state and no class rows in the sampled interval; the only visible action is `Continue`. See [04b class chooser](<local-workspace> Earlier/later frames show the import toast and readable Maths EE content, so the gap is localized to setup choice loading rather than a total import failure.
- **Source correlation:** The dialog title/action match `class-shelf-onboarding.tsx:116–128`.
- **Affected neighbors:** Student first-run, school/teacher setup, class shelves, ManageBac sync, import filing, General fallback, and role-specific visibility.
- **Bounded remedy:** Run seeded-school tests for populated classes, empty classes, delayed class response, retry, skip-to-General, and a second login. Assert the selected class shelf, General fallback, and ManageBac-linked identity after import. Capture both student and teacher roles.

### Collaboration/conflict recovery

#### W1-15-F03 — Native presentation conflict recovery appears, but the capture cannot separate true collaboration from same-session echo

- **User consequence:** While editing a presentation, a student sees `A newer saved version arrived while you were editing` and must choose between `Keep local edits` and `Reload latest`. The banner protects local text in the recording, but a real two-user convergence result is not shown.
- **Severity:** important.
- **Confidence:** high for the observed banner and preserved-local-edit affordance; medium for cause and end-to-end correctness.
- **Recording evidence:** At approximately 22–30s in 07, the banner appears while editing `Add a clear idea`; later local text includes `QA07-slide` and `QA07-B`. The deck later shows two slides and can be reopened, but the recording does not show a second account or a completed choice on both peers. See [conflict banner](<local-workspace> [local edit](<local-workspace> and [readback](<local-workspace>
- **Source correlation:** The copy matches the conflict bar in `artifact-studio.tsx:5856–5871`, including both recovery choices.
- **Affected neighbors:** Yjs/native model collaboration, incoming snapshot rebasing, presentation local undo, Live Dock/session identity, conflict persistence, and multi-user permissions.
- **Bounded remedy:** Re-run with two actual school users and a separate browser/device: independent slide edits should merge; same-region edits should conflict with both previews/choices; each choice must converge on both peers after reopen. Add a single-user control run to rule out self-collaboration/session echo before classifying this as a product defect.

### Identity, density, and parity boundaries

#### W1-15-F04 — Repeated same-name artifacts make search/readback ambiguous in the captured account

- **User consequence:** Searching `QA05 Persist Doc`, `QA06 Persist Sheets B1v2`, or `QA07 Persist Deck` shows repeated QA items and/or multiple same-name artifacts. A student can reopen the wrong copy and still believe persistence succeeded.
- **Severity:** small for production users, important for test validity.
- **Confidence:** medium. The duplicates are clearly visible, but repeated recording runs in one shared account are a plausible explanation rather than proof of an uncontrolled production duplication bug.
- **Recording evidence:** 05 search shows three `QA05 Persist Doc` results; 06 shows the B1v2 sheet alongside other QA06/new-sheet items; 07 shows multiple `QA07 Persist Deck` results. See [05 search](<local-workspace> [06 search](<local-workspace> and [07 search](<local-workspace>
- **Affected neighbors:** Library search, stable artifact identity, test isolation, duplicate-title handling, and destructive actions such as move/trash.
- **Bounded remedy:** Use one clean account per run and unique IDs in test titles. Separately test whether production users can create same-name artifacts, then expose type/location/updated metadata or an explicit duplicate-choice rail if ambiguity is expected.

#### W1-15-F05 — Live AI cards and split studios consume the lower/center working area

- **User consequence:** In 04 and 08, prior AI result cards remain across the bottom of the shell while the student works in Library or a studio; in 04b, Library + document + AI columns leave a narrow reading surface. The captured shell makes the primary student task compete with conversation history and reduces document width.
- **Severity:** small in a clean session; important if these cards are persistent by default for students.
- **Confidence:** medium. The density is directly visible, but the recording account is contaminated with prior QA/AI activity and does not establish the default first-run state.
- **Recording evidence:** 04 begins with a right-side AI conversation and action card; 08 contains several bottom result cards while Quiz/Flashcard/Whiteboard are used. 04b’s imported document header truncates `Maths-EE-3-31...` in the narrow pane while its body remains readable. See [04 AI card](<local-workspace> [08 lower dock](<local-workspace> and [04b imported body](<local-workspace>
- **Affected neighbors:** Student information hierarchy, Live Dock persistence/collapse, split-pane sizing, imported-document reading, and keyboard focus.
- **Bounded remedy:** Capture a clean student session with no prior action cards, then repeat with one active AI task and with the dock collapsed. Keep the primary artifact surface readable at 1280×800 and ensure the conversation/action surface has an obvious collapse/restore state.

#### W1-15-F06 — Native Office fidelity and round-trip claims remain unproven by these recordings

- **User consequence:** The imported Maths EE text is readable, but the sample does not tell us whether equations, fonts, tables, formulas, charts, slide themes, or edits survive a DOCX/XLSX/PPTX round trip. 05–07 prove native Spectra artifacts, not Office-file parity.
- **Severity:** important for any launch messaging that promises native Office continuity; future if the claim is explicitly deferred.
- **Confidence:** high for the coverage gap; not a claim that the unsupported features definitely fail.
- **Recording evidence:** 04’s DOCX preview itself states that unsupported Word features remain in the original package. 04b shows readable title/research-question/contents text but no sampled equations or edit/export/readback. 05–07 use native Document/Sheets/Presentation studios and reopen native artifacts. See [DOCX preview](<local-workspace> [Maths EE content](<local-workspace> and [native presentation](<local-workspace>
- **Affected neighbors:** Bridge materialization, DOCX/XLSX/PPTX projection/merge, Office file watchers, native-copy download, and user trust in imported schoolwork.
- **Bounded remedy:** Treat Office parity as an explicit matrix: ordinary text/styles, equations and unusual fonts for DOCX; formulas/number formats/charts for XLSX; text/shapes/themes/notes for PPTX; edit in both directions, reopen, compare semantic content, and verify original-package hashes.

## Next-wave tests and implementation implications

1. **P0 — Bridge truth and recovery matrix.** Use one known DOCX, XLSX, and PPTX with hashes recorded before launch. Run clean one-device, external-edit-first, Spectra-edit-first, simultaneous same-region, and offline/reconnect cases. Expected result: status names identify the actual authority; every choice has a visible completion/readback; original package remains unchanged unless an explicitly documented export replaces it.
2. **P0 — School setup and ManageBac.** Seed a real school with student/teacher peers and populated classes. Test first login, import, delayed class response, empty classes, retry, skip-to-General, and later class assignment. Read back shelf placement and ManageBac identity from both roles.
3. **P0 — True two-user collaboration.** Use separate accounts/devices, not the same captured session. Test independent slide/document regions, same-region collisions, Keep local, Reload latest, reopen, and permissions. Add a single-session control so self-echo is distinguishable from peer collaboration.
4. **P1 — Clean student shell density.** Repeat 01/02/08 with an empty account and at 1280×800. Verify the New menu, AI dock collapse, keyboard focus, and artifact width with no prior cards. Keep one separate contaminated-account test for recovery/history behavior.
5. **P1 — Office content fidelity.** Execute the DOCX/XLSX/PPTX matrix in F06, including equations, tables/charts, themes, unusual fonts, and native-app edits. Compare semantic readback and original hashes.
6. **P1 — Non-Office durability.** Hard reload and reopen Quiz, Flashcard, Whiteboard, Planner, Code, Agent, and Presentation. Verify edited values, permissions, publish/submit state, and no accidental duplicate artifact selection. Repeat with student/teacher peers where collaboration is advertised.
7. **P1 — Undo/status.** Extend 09 through hard reload and a second actor. Confirm local Undo removes only the initiating user’s change, status/readback is honest, and redo/version history behavior is explicit.

Suggested work packages are Bridge truth + Office fidelity, school/ManageBac setup, collaboration/recovery, and clean student shell/readback. Keep test-account hygiene separate from product changes so duplicate titles do not mask persistence results.

## Decisions for parent/Pablo

- Treat the bridge conflict state in 04 as a material launch follow-up, not as a confirmed data-loss defect. The UI visibly distinguishes local newer edits, cloud waiting, and conflicts, but the recording never completes a resolution or proves cross-device convergence.
- Keep class-shelf/ManageBac setup in the next P0 wave. The empty/spinning chooser is the only direct recording evidence that a stated school workflow may leave a student uncertain where imported work belongs.
- Do not use 05–07 as evidence of DOCX/XLSX/PPTX round-trip readiness. They are useful native persistence evidence; Office parity needs a separate matrix and original-hash check.
- Treat the 07 conflict banner as a recovery behavior to validate with two actual users, not as proof of a collaboration regression. A same-session echo is plausible in this capture.
- Preserve the students-primary scope: students and teachers are peer roles; School setup/ManageBac is prioritized; landing-shell capture 25 remains out of scope.
