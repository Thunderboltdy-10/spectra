# W1-17 — Launch safety and surface completeness

## Result

This audit did not find a confirmed cross-tenant authorization bypass, invitation-token bypass, or unguarded privileged secret-store API in the inspected source. It did find four launch-relevant issues and two smaller trust-boundary gaps:

1. The required macOS Bridge path is not identity-safe or writer-safe, and the repository only packages Windows NSIS artifacts.
2. Students and teachers are modeled as peers for artifact capabilities, but native Office lens routes call owner-only replica/payload functions, blocking shared Office workflows.
3. Domain-restricted public links are supported in Convex but the public delivery route does not pass viewer-domain context, so that mode dead-ends.
4. The production dependency graph fails a high-severity audit, including server-relevant Next.js and PDF.js advisories.
5. Direct Office import and AI attachment intake have per-file limits but no aggregate request/decompression budget.

The first four should be release gates for the affected workflows. No source fix was made because the high-impact changes cross shared authorization, parser, dependency, or Bridge ownership boundaries.

## Findings

### W1-17-F01 — macOS Bridge fallback conflates files and cannot prove Office stability

**Severity:** Launch blocker for required macOS Bridge support  
**Confidence:** High  
**Owner:** W1-05

`bridge/bridge-core/src/platform.rs:152-174` places macOS in the `not(windows)` implementation. Its `file_identity` uses file length as `file_index` and hard-codes `volume: 0`; `is_locked` always returns `Ok(false)`; and `open_stable_reader` only opens a normal read-only handle. `bridge/bridge-core/src/watcher.rs:364-373,443-474` uses those methods while deciding whether an Office-owned file is stable. `bridge/bridge-app/src/main.rs:950-1009` then adopts/upserts the result.

Consequences are concrete:

- Two different same-size files can receive the same local identity and collide in the journal/resource map, allowing edits or payload state to attach to the wrong file.
- A macOS Office writer is not detected by the lock check, and a normal reader is not proof that the writer has flushed stable bytes; an in-progress snapshot can be promoted.

The release configuration independently confirms the gap: `bridge/bridge-app/tauri.conf.json:12` enables only the `nsis` bundle target. The repo has no macOS artifact/signing/notarization workflow or host-platform test target. Do not claim macOS Bridge readiness until identity, writer/stability semantics, packaging, signing/notarization, updater artifacts, and macOS tests are present.

### W1-17-F02 — Production dependency graph fails the high-severity release gate

**Severity:** Launch blocker pending dependency triage  
**Confidence:** High  
**Owner:** Coordinated W1-02/W1-03/W1-06/07/08/W1-13 release owner

The 2026-09-08 production audit reported 18 vulnerabilities. Relevant installed versions include `next@16.2.9`, `pdfjs-dist@5.7.284`, `pptxgenjs@3.12.0`, `convex@1.41.0`, and a nested `convex/node_modules/ws@8.20.1`; `convex-helpers` also reports an invalid `convex` peer expectation of `^1.43.0`.

The audit flags, among others, the Next.js App Router/Turbopack middleware/proxy bypass advisory `GHSA-6gpp-xcg3-4w24`, server-action/rewrites SSRF and DoS advisories, PDF.js arbitrary JavaScript execution when opening malicious PDFs (`GHSA-hq66-cqwq-w95`), and nested `ws` memory-exhaustion advisory `GHSA-96hv-2xvq-fx4p`. Server-side PDF parsing is used by `src/app/api/spectra/run/loop/intake.ts:772-775,1110-1114` and `src/features/spectra/compute/files/attachment-preprocessor.ts:82-84`; those calls do not show an explicit JavaScript-disable option.

No exploit was run. This is a release-gate finding because the affected packages sit on the auth proxy and untrusted attachment/import paths. Coordinate a patched, compatible dependency graph, verify Next proxy behavior and PDF/PPTX parser hardening, then rerun the production-only audit and full build/test suite. Do not apply an unreviewed broad upgrade in this worktree.

### W1-17-F03 — Shared Office peer access is blocked by owner-only replica functions

**Severity:** Launch blocker for shared native Office workflows  
**Confidence:** High  
**Owner:** W1-06/07/08 and W1-12

The peer policy grants a collaborator with `modify` capability `read, modify, restore, use, comment` in `convex/authorityShared.ts:11-18`. However, the native Office routes call owner-scoped functions:

- `src/app/api/spectra/lenses/docx/route.ts:101-106,333-345,421-428`
- `src/app/api/spectra/lenses/office/route.ts:171-178,540-547`
- `src/features/spectra/lenses/native-payload-server.ts:47-60`
- `convex/replicas.ts:512-566` (`payloadForWork`) and `570-597` (`activateLens`), both requiring `work.ownerAccountId === actor.accountId`; `replicas:forWork` is likewise used by the routes.

A teacher or student who is an authorized peer can therefore use the ordinary artifact capability model but receive `WORK_NOT_FOUND` or be unable to open/materialize a shared DOCX/XLSX/PPTX through the native path. This is a user-blocking inconsistency, not an observed data disclosure. The correct fix needs a capability-aware replica/payload contract and a complete owner/peer test matrix; changing the shared auth policy locally would be unsafe.

### W1-17-F04 — Domain-restricted public links cannot reach their intended viewer context

**Severity:** Important  
**Confidence:** High  
**Owner:** W1-09/W1-12

`convex/authority.ts:1230-1244,1266-1280` rejects a public link when its stored `domainRestriction` does not match the supplied normalized `viewerDomain`. The anonymous delivery route `src/app/api/spectra/public/route.ts:13-38` calls `authority:publicProjection` without `viewerDomain`. The current share dialog and create route also do not forward a domain restriction (`src/features/spectra/components/share-dialog.tsx:315-327`; `src/app/api/spectra/route.ts:874-891`).

Any restricted link created through another/legacy path will therefore return no projection even for the intended school-domain viewer. This is not a public-link bypass: random token generation, hashing, revocation, expiry, lifecycle checks, no-store, and noindex behavior are present. Decide whether restricted links are supported at launch; if yes, define a trustworthy authenticated/domain-bound delivery flow and test allowed, wrong-domain, expired, revoked, and anonymous cases. Do not infer a domain from an untrusted request host.

### W1-17-F05 — Office and AI attachment intake lacks an aggregate/decompression budget

**Severity:** Important  
**Confidence:** High  
**Owner:** W1-02/W1-03/W1-06/07/08

The direct Office endpoint `src/app/api/spectra/imports/office/route.ts:25-85` authenticates but reads `await file.arrayBuffer()` before parsing, with no declared file-size or request-body cap. The AI runtime reads the full request body at `src/app/api/spectra/run/runtime.ts:3208-3214` before attachment preparation. `src/features/spectra/compute/files/attachment-preprocessor.ts:193-236` has useful per-file caps (image/PDF/text/DOCX/XLSX/PPTX), but no total request budget; PDF.js, ExcelJS, and `fflate.unzipSync` are invoked at `:82-173` without a decompressed-entry/ratio limit or parser timeout.

An authenticated peer can submit a large or archive-heavy Office/PDF payload and force full buffering, decompression, and parsing in a Next worker. This can cause memory/CPU pressure, timeouts, and avoidable cost; it is not an unauthenticated route. Enforce server/body and aggregate byte limits before buffering, bound ZIP entries and expansion, reject oversized declared files before `arrayBuffer`, and isolate or time-limit expensive parsing. Add negative tests for 413/429 behavior and ZIP/PDF bombs.

### W1-17-F06 — Local Bridge update trigger is outside the authenticated router

**Severity:** Small  
**Confidence:** Medium  
**Owner:** W1-05

`bridge/bridge-core/src/server.rs:239-267` places `/v1/update` outside the protected router; `:363-375` calls `LocalBridgeControl::request_update`. The updater later verifies a signed artifact (`bridge/bridge-app/src/main.rs:1957-1970`), so this is not arbitrary-code execution. A local allowed-origin process can nevertheless repeatedly trigger update checks/install/restart behavior and disrupt Bridge availability. Require a paired session or rate-limited/idempotent updater path, while preserving the signed-artifact check.

## Assurance gaps and launch decisions

These were inspected and are not reported as confirmed exploits, but they need explicit owner decisions or live negative tests:

- **AI authority:** `src/app/api/spectra/run/runtime.ts:1368,1595+` gates normal execution; `src/app/api/spectra/run/loop/plan.ts` returns approval-required for confirmation policies; the confirmation route revalidates run ownership, state, proposed rows, intent, and claims the pending proposal. The lower-level app-command executor does not independently fail closed. Add an end-to-end test proving a missing, expired, replayed, or mismatched confirmation cannot reach the executor, and consider an executor-level approval token/state check. Owner W1-03/W1-04.
- **Agent manifest:** `src/app/api/spectra/agents/manifest/route.ts:69-119` signs a user-provided manifest for any signed-in Clerk user, up to 5 MB, with a fallback signing secret. No in-repo consumer was found. Treat this as an external-consumer trust-surface decision: either require active membership/capability or document and test the exporter contract and consumer allowlist. Owner W1-03/W1-04.
- **Deployment preflight:** `src/lib/env.ts` validates only a subset of public/runtime variables; other security secrets are validated lazily. `src/lib/boot-diagnostics.ts` logs deployment/URL mismatch warnings instead of failing readiness. Production must fail fast on Clerk, Convex, encryption, Bridge/callback, worker, SMTP, and model-provider prerequisites, and must choose/configure exactly one collaboration gateway architecture (`deploy/collaboration-gateway/fly.toml` versus `workers/collaboration/wrangler.toml`).
- **Account lifecycle:** school export/offboard/purge jobs, cancellation boundaries, legal audit retention, and storage cleanup are implemented in `convex/administration.ts:2860-3175,3390-3565` and related cron/snapshot sweepers. No personal-account deletion/portability route was found. Decide whether Clerk user self-delete/subject erasure is promised; if it is, connect it to school membership, Bridge credentials/cache, memories, and retained legal records. No billing/subscription/invoice route was found even though legal copy references billing; either assign it or remove/clarify that promise.
- **Operational retention:** `src/lib/logging.ts:115` still describes logging as a single path pending an owned, retention-bounded sink. Define retention/redaction and recovery ownership before production use.

## Covered controls and non-findings

- `requireActor`, `requireAccount`, and `requirePlatformOperator` enforce Clerk identity, verified email, active membership, and the superadmin allowlist in `src/lib/auth-server.ts`.
- ManageBac and scheduled-run callbacks use timestamped HMACs, body digests, nonce/replay checks, active-run/lease checks, and current Clerk/Convex session acquisition (`src/app/api/spectra/managebac/route.ts:1427-1492`; `convex/managebac.ts:353-394,1145-1235`; `src/app/api/spectra/run/runtime.ts:2532,3219-3233`).
- Secret operations are purpose-limited and require school-admin/operator authorization; the Bridge secret envelope uses canonical HMAC, timestamp, nonce, and AES-256-GCM (`src/app/api/operations/secrets/route.ts`; `convex/secretStore.ts`; `convex/secretBridge.ts`; `src/lib/server-secrets.ts`).
- Invitation acceptance binds the normalized token to the authenticated actor email and checks pending/accepted/expiry/school state; no bypass was confirmed in source.
- Durable artifact uploads/imports have capability checks and byte/storage budgets in `convex/artifactAssets.ts` and `convex/artifactImports.ts`. The unbounded paths are the direct Office/AI parser seams described in F05.
- Runtime embeds require an active-school actor, artifact capability, bounded bytes, credential-free fetch, hash verification, no-store, and nosniff (`src/app/api/spectra/runtime/embed/route.ts`; `convex/artifactEmbeds.ts`).
- Bridge pairing/session continuity, protected mount/status operations, and Windows core/chaos behavior passed the available tests. The macOS platform implementation and packaging did not.
