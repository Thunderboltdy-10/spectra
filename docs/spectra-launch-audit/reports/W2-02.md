# W2-02 — Unnecessary reads and loading fixes

## Result

W2-02 found one important response-size defect and one contained duplicate-read defect. The source patch adds an explicit summary mode for the library/overview and AI context-map callers, and reuses the in-flight artifact read when the native payload fallback needs the same artifact. The default full workspace contract remains intact for explicit AI read_workspace calls.

Version history and asset galleries remain complete/unbounded by design in the current contracts; they need cursor/URL-loading migrations rather than a silent server cap. Closed-panel subscription guards are already sound. The patch is committed in the audit worktree but is not live in the primary runtime.

| Asset gallery | convex/artifactAssets.ts:listForArtifact → storage.getUrl per active asset | Complete gallery plus URLs | Report and migrate; URL fetch is required by current studios |
| Native download/materialization | src/app/api/spectra/native/route.ts | Full artifact for filename and package fallback | Share the artifact promise; custom POST names can avoid the route-level filename read |

The authority boundary is unchanged. hydrateWorkNode still authenticates each artifact through evaluateAccess; summary mode reduces the returned response body, but does not eliminate the underlying per-artifact authorization/database work. workspaceContextNodes remains an unbounded .collect() and hydration remains serial, so summary mode is a bounded payload fix, not a pagination/performance rewrite.

## Findings grouped by root cause

### W2-02-F01 — Workspace UI reads return full artifact and thread execution bodies

Severity: important. Confidence: high.

The baseline overview/workspace response includes records the library does not render: artifact content, full AI effect/preview payloads, and, more significantly, each thread’s nested last run with context snapshots, prompts, usage, and execution metadata. The source chain is route.ts → listWorkspaceContentsPublic → readWorkspaceContents; before the patch, work nodes spread the full authorized artifact and thread nodes spread {...thread, run}.

The result is unnecessary response bytes and server work on a high-frequency library/workspace read, with large-workspace latency and possible timeout pressure. The same default contract is also used by explicit AI read_workspace, so truncating it would be unsafe.

The bounded remedy is now implemented: includeDetails:false uses the existing explicit artifact summary projection and an allowlisted thread metadata shape, while callers that need full workspace details omit the flag. It does not yet solve unbounded node collection or per-item authorization reads; those require a separate cursor/summary-index design.

### W2-02-F02 — Version history collects the entire history before applying limit

Severity: important for long-lived artifacts. Confidence: high.

listVersions accepts a limit, but queries all versions with .collect(), selects the tail, and computes versionNumber using findIndex in that full array. This is an output limit, not a read limit. workbench-inspector-tabs loads 60 only after a non-overview tab is selected; artifact studio history is explicitly opened; pinned embed versions load only when the embed is open and pinned.

Do not replace this with take(limit) or arbitrary truncation: reverse pagination needs an opaque cursor and a stable ordinal/sequence contract if versionNumber remains user-visible. The schema currently has no stored version sequence. A coherent migration should add cursor metadata and either a durable sequence or a contract that removes/redefines ordinal numbering.

### W2-02-F03 — Asset gallery enumeration fans out signed URLs and is unbounded

Severity: important for asset-heavy artifacts. Confidence: high.

listForArtifact collects every non-uploading asset and calls storage.getUrl per active asset. The no-filter /api/spectra/assets path is used by flashcard, quiz, presentation, whiteboard, and code studios for complete gallery rendering and refresh after uploads/revokes. getReferenced has a 100-ID cap only when callers already know referenced IDs; it does not bound gallery discovery.

A silent cap would hide assets. The next contract should paginate gallery metadata with a cursor and make signed-URL hydration explicit (for example, page URLs or a separate URL batch) while preserving upload/revoke refresh and download behavior. This wave deliberately leaves the complete-gallery contract unchanged.

### W2-02-F04 — Native fallback can duplicate the full artifact query

Severity: small/important on fallback downloads. Confidence: high.

GET fetched spectraArtifacts:get for the filename in parallel with ensurePortablePayload; if no verified payload existed, the helper fetched the same full artifact again to build the portable package. POST also always fetched the artifact even when the caller supplied a custom filename.

The patch shares the GET promise with the fallback. For POST, it only creates the route-level filename promise when no custom filename was supplied; the fallback still performs its necessary single artifact read if it must generate a package. This removes duplicate route-level reads without changing payload/hash/attach semantics.

### W2-02-F05 — Mounted-but-hidden subscriptions are guarded, not a current defect

Severity: none found. Confidence: high for inspected paths.

Comments and inspector history refresh only when open/non-overview. Embeds use a Convex “skip” query when closed and only load pinned versions when open. The chat browser is conditionally mounted only when open. LiveDock polling is shared and visibility-aware. The settled browser request list also showed no versions/assets fetch while those surfaces were closed.

Keep these guards as regression requirements. The remaining watch item is not a hidden subscription but the size of the workspace request itself (F01).
