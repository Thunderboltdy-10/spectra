# W2-07 — Word/DOCX native roundtrip depth

## Result

The DOCX lens has a sound preservation-first core and now writes Unicode font names safely across all four Word script slots (`ascii`, `hAnsi`, `eastAsia`, `cs`) while clearing theme indirection. The fix is committed in the delegated worktree and is not integrated into the primary runtime build.

The audit confirms three distinct paths rather than one roundtrip contract: ordinary import is a Mammoth-based adapted editable copy; linked DOCX uses the native preservation lens with explicit read-only boundaries; and Spectra-created DOCX export is a structural/plain copy. Native XML readback is deterministic and strong for the lens, but the live linked edit did not survive a reload into a readable workspace state, and the live generated-document Word-copy button did not produce a browser download within 90 seconds. Those live gaps remain unverified rather than being converted into a broad parity claim.

## Findings grouped by root cause

### W2-07-F01 — Unicode font guard and East Asian script slot were incomplete

Severity: important (fixed in delegated worktree). Confidence: high.

The old `safeFontName` regex at `docx-lens.ts:1263` used JavaScript ASCII-only `\\w`, rejecting valid CJK/kana/accented font names. `applyRunFormat` at the old `:1336` wrote only `ascii`, `hAnsi`, `cs`, omitted `eastAsia`, and did not clear `eastAsiaTheme`; its old list also used the malformed `cstheme` spelling inconsistently. The user consequence was a hard refusal for `游ゴシック` plus a risk that Word would continue resolving a theme font in an East Asian script slot.

The bounded fix uses Unicode property escapes with the existing conservative punctuation policy, writes `ascii`, `hAnsi`, `eastAsia`, `cs`, and removes all four theme slots plus the malformed casing. It does not change OMML, part preservation, region guards, or merge behavior. The new regression test exercises native XML and reopen projection. Neighboring rich-region tests and the full suite pass.

### W2-07-F02 — Ordinary DOCX import is adapted content, not a native-fidelity roundtrip

Severity: important/future, depending on product promise. Confidence: high.

The code chain is `document-studio.tsx:1937-1972`: original bytes are retained, but Mammoth HTML is sanitized into a new editor document at `:1948-1955`. The import explicitly lists macros, tracked-change authorship and floating layout as unsupported. Live evidence shows the adapted document renders text, headings, lists, tables, images and equations, while the source hyperlink becomes plain text (`0` editable anchors).

This is an honest product choice when labeled as “separate editable copy”; it is a fidelity defect only if ordinary import is presented as roundtrip editing. Keep the retained-original boundary visible and add a conversion-loss manifest for links, comments, revisions, notes, headers, sections and exact run formatting.

### W2-07-F03 — Native editing is paragraph/run coarse around rich Word ranges

Severity: important/future. Confidence: high.

`writableRun` at `docx-lens.ts:968-980` excludes runs carrying protected native machinery. `replaceParagraphText` at `:1002-1007` rewrites the first writable run and clears subsequent writable runs; `applyRunFormat` at `:1313-1318` applies uniformly to all writable runs. This is why a safe plain paragraph can be edited beside OMML or tracked material, while the rich range itself is preserved. It also means a future edit of a safe paragraph with multiple different writable run styles can collapse those writable runs to the first run’s text/style.

The current behavior is an intentional safety guard, not permission to remove the guard or rewrite OMML. Broad editing needs stable inline/run boundaries, selection mapping, range-aware deltas, mixed-style serialization, and a readback verifier for untouched protected runs.

### W2-07-F04 — Generated Word exports flatten the editor model

Severity: important. Confidence: high.

The UI export path at `document-studio.tsx:1746-1898` calls `blocksFromJson` and emits `new TextRun(block.text)` at `:1892`; only heading level, quote style, and reference fallback image/link handling survive. The shared `buildDocxBytes` path at `document-export.ts:201` similarly receives the low-level `GeneratedDocument` model and emits simple paragraphs/tables for its supported generated types. Neither path serializes editor run marks, native OMML, comments, tracked ranges, footnotes/endnotes, headers/sections, or original package parts.

The direct builder control reopened successfully, but the live browser Word-copy download did not produce a file, so a browser export/readback result is still outstanding. Keep this path explicitly labeled as a separate lossy copy until a structured export model and native package verification exist.

### W2-07-F05 — Legacy/unsupported media reaches a 404 instead of a declared fallback

Severity: small. Confidence: high.

The lens projection only models `image/png` and `image/jpeg` (`docx-lens.ts:523-580` and `projection-contracts.ts:69-80`). The controlled fixture carries legacy `word/media/image1.bin`, `image2.emf` and `image3.bin`; the live linked view requested `image3.bin` and received HTTP 404. The user consequence is a broken image surface and console error even though the rest of the document remains readable.

Add a typed unsupported-media placeholder/fidelity entry and ensure the media route returns that declared state (or a safe preview) rather than a failing fetch. Do not claim EMF/VML fidelity until the package renderer and browser path are both verified.

## Decisions for parent/Pablo

- Keep the preservation guards and OMML read-only boundary. The evidence shows they prevent destructive flattening and already support safe adjacent edits; removing them would trade a visible limitation for silent native corruption.
- Treat ordinary import as adapted unless the product is willing to build and maintain a native package editing path for comments, revisions, notes, headers/sections and relationships. The current retained-original behavior is the safer contract.
- Merge the Unicode font fix before broad editing work. It is small, independently tested, and removes a hard block for common East Asian typography without changing the preservation architecture.
- Do not call generated Word export “roundtrip” yet. The direct builder is valid and readable, but it is structurally lossy and the live browser download was not observed; expand the serializer and browser test together.
