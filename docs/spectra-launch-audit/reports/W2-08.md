## Findings

### F01 — ExcelJS formula cache was dropped during clean import — fixed in source

The old `importExcel` branch discarded `valueRecord.result` whenever a formula was present. That made a formula with no local evaluator support appear blank and removed the last saved Excel result. It also did not set `nativeFormulaSupport`, so the model could not distinguish a live formula from a cached-only formula.

The fix adds `projectExcelJsFormulaValue` in `src/features/spectra/components/sheets-studio.tsx:382`, preserves the saved scalar result, normalizes formula text, applies the shared XLSX support classification, and reports the number of cached-only formulas in the import caveat. A 2D `INDEX` is now included in the recognized XLSX formula set at `src/features/spectra/lenses/xlsx-formula-support.ts:7`, matching the already-corrected model evaluator.

The live screenshot is intentionally baseline evidence from the pre-fix runtime; it showed the imported value but no `XLOOKUP` formula in the formula bar. The post-fix behavior is covered by source tests and was not rebuilt into the shared runtime.

### F02 — Merged height used raw row distance across hidden rows — fixed in source

The grid used `position + endRow - startRow` to select the merge's ending offset. Because `position` indexes visible rows, a hidden or filtered row made the merge height point at the wrong track. `mergedRowEndPosition` at `src/features/spectra/components/sheets-studio.tsx:420` now walks the visible row index and the renderer uses that position at `src/features/spectra/components/sheets-studio.tsx:5143`.

The renderer test covers merges crossing hidden rows and merges ending before the next visible row. This fix is source-verified only in this pass.

### F03 — Lookup modes were ignored or falsely treated as exact — fixed conservatively in source

The model previously implemented only exact `MATCH` and `XLOOKUP`; `MATCH` ignored `match_type`, `XLOOKUP` ignored match/search modes, and `VLOOKUP`/`HLOOKUP` returned `#N/A` even for valid approximate lookups. The new helpers and branches are in `src/features/spectra/sheets/model.ts:1080`, `:1722`, `:1740`, and `:1817`.

The implementation verifies sorted ordering before approximate MATCH/VLOOKUP/HLOOKUP and refuses an incompatible vector rather than returning a plausible row. XLOOKUP supports exact, next-larger, next-smaller, forward, and reverse linear searches; wildcard and binary modes remain an explicit `#N/A` refusal. Tests at `src/features/spectra/__tests__/sheets-operations.test.ts:655` cover the corrected modes.

### F04 — Bridge-backed XLSX export drops native features — open, P1 fidelity risk

The real bridge edit/export/readback preserved formulas, cached values, frozen panes, and numeric date serials, but the exported package had no merge cells, hidden-row flags, table parts, or conditional-format rules. This is a data-fidelity loss for a normal XLSX edit, not merely a visual limitation. The clean-import path initializes `tables`, `charts`, `conditionalFormats`, `hiddenRows`, and `rowHeights` empty at `src/features/spectra/components/sheets-studio.tsx:3178-3210`, and the exported date cells had no `numFmt` on readback.

The repository's XLSX native lens already exposes the architectural boundary: cells, formulas, styles, number formats, merges, and freeze panes are `NATIVE`; charts, tables, validation, conditional formats, named ranges, dimensions, sheet structure, sheet metadata, calculation settings, and sort/filter are `PRESERVED`/read-only in `src/features/spectra/lenses/xlsx-lens.ts:263-278`. Its existing tests also prove native style/merge/freeze writes and preservation reporting. The live bridge route exercised the model import/export path, not that complete native carry path, so the product needs one deliberate routing decision before claiming full native fidelity.

### F05 — Clean import is intentionally incomplete but its UI result is easy to misread — open, P1/P2 depending on launch promise

The clean ExcelJS reader currently imports cell values, a limited style summary, formulas, notes, column widths, merged ranges, and freeze panes. It does not import charts, tables, validation, conditional-format rules, row/column visibility, row heights, workbook names, custom number-format codes, or locale-specific display intent. The live `dd/mm/yyyy` source dates rendered as ambiguous `2/3/2024`, `3/4/2024`, and `4/5/2024` in the `en-US` surface, while the package readback retained only serials.

This should either be presented as an explicit lossy “clean import” with a visible fidelity report, or routed through the native XLSX lens whenever users expect roundtrip preservation. The source already has a truthful fidelity map for native files; the bridge/open path needs to surface and honor it.
