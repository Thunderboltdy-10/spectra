Date: 2026-09-08

Scope: Spectra presentation/PPTX import, native preservation, browser editing, rendering, export, undo, and collaboration boundaries.

## Executive result

Status: **partial; not launch-safe for broad PowerPoint parity**.

The native package preservation harness is healthy for the declared narrow lane: 20 PPTX command fixtures passed, including transition/timing, master/layout, media, chart relationship, notes, OLE, and embedded-workbook preservation. A live native-created presentation also supported slide creation, text, shape, chart placeholder, table, reload, and deck-level undo.

I found and fixed one contained defect: a selected object font was visible in the toolbar but was not forwarded to the DOM object view, canvas renderer, or PPTX writer. The fix is committed in the worktree as [`e40fd585`](<local-workspace> (`fix(presentation): forward selected fonts across renderers`). It is **not deployed to the shared primary runtime**, so live evidence below that predates the fix is explicitly labeled baseline.

The broader parity claim remains unsupported. Browser import is a lossy scene conversion; chart insertion/export produces rectangles rather than a native chart part; rich run-level styles, equations, master/layout inheritance, groups/connectors, and full animation semantics are not represented as editable browser-native objects. Native preservation and browser editability are separate lanes.

## Findings

### W2-09-F01 — Selected font was UI-only before the fix (high)

The live toolbar reported Arial after selecting a text object, but the object had no inline `fontFamily` and `getComputedStyle` remained Manrope. The cause was a renderer handoff gap plus a title selector using `!important`. The patch centralizes `presentationFontFamily` and applies it to the DOM object, canvas context, and PPTX text run. It also adds direct resolver/package XML assertions.

This is a contained editor/render/export fix, not a claim that every imported PowerPoint run is now semantically editable.

### W2-09-F02 — Font forwarding does not solve full renderer parity (high)

The three paths still differ in parsing, line measurement, wrapping, and overflow. The canvas path is intentionally simple and the import path does not preserve all run-level style spans. A font-family fix reduces one divergence but does not establish DOM/canvas/PDF/PPTX visual equivalence.

### W2-09-F03 — Chart UI/export is a visual placeholder, not a native chart (high)

The live Insert → Chart control created a chart-shaped object. The patched task export contains no `ppt/charts/*.xml` chart part and contains six rectangle-shape entries for the chart visual. The preservation harness proves that an existing native chart relationship and embedded workbook can be preserved when the native lane is used; it does not prove that browser-created charts are editable PowerPoint charts. This distinction must remain user-visible or be closed with a real chart adapter.

### W2-09-F04 — Browser import is lossy for complex native features (high)

The browser parser projects text and basic geometry, while masters/layouts, equations, rich runs, groups/connectors, hyperlinks, chart series, and complete transition/animation semantics remain package-level or unsupported in the browser scene. Native preservation fixtures pass because untouched parts are carried through; that is not the same as round-tripping those features through the browser editor.

### W2-09-F05 — Unsupported native mutations need explicit refusal (high)

The strict-native capability boundary is useful, but the projection/operation lane must remain fail-closed. If a requested delete, style, rich-object, or unsupported structural edit is not represented in the native operation set, a silent no-op or partial projection can look like a successful save. The next implementation should expose unsupported operations as a user-facing refusal/conflict and preserve the original package unchanged.

### W2-09-F06 — Shared live runtime had one transient timeout (medium)

The presentation page showed `Something went wrong [Q(orgTreeBoard:column)] Server Error Function execution timed out (maximum duration: 1s)` during the shared audit session and recovered after reload. This is baseline availability evidence under concurrent activity, not a presentation regression introduced by the worktree patch. It should be tracked by the runtime/launch owner if reproducible in a clean session.

### W2-09-F07 — Direct live notes test was contaminated (low)

An active shared-account AI “Your answer…” overlay intercepted the Speaker notes interaction. Notes are present in the native preservation and generated-package evidence, but direct live notes authoring is not marked PASS. This is deliberately not classified as a product defect without a clean session.

## Architecture and ownership

The current system has four relevant layers:

1. `presentation-studio.tsx` owns selection, toolbar controls, DOM object editing, slide order, notes UI, and keyboard undo.
2. `presentation/io.ts` owns browser scene import/export plus canvas and PPTX generation.
3. `pptx-lens.ts` owns the native package projection/preservation lane and declares its native capabilities.
4. `office-content.ts` owns PPTX semantic projection and operation generation between base and edited projections.

Shared/package-level work should own relationship ordering, native run/theme/master semantics, native chart/table/equation/image parts, orphan handling, and package readback. Editor/renderer work should own selection/inspector state, DOM/canvas/PDF/PNG metrics, wrap/overflow, animation preview, and user-facing unsupported-operation messaging. The completed patch is intentionally in the editor/render/export boundary and does not rewrite the native package model.

## Required follow-up before claiming PowerPoint equivalence

1. Integrate `e40fd585` into the launch build and rerun the live font test: toolbar selection, computed DOM style, canvas screenshot, and exported slide XML must agree.
2. Run Windows PowerPoint and LibreOffice readback on the generated deck and on an untouched complex Office-authored corpus; compare slide order, visual layout, font fallback, notes, transitions/timing, media, charts, and embedded objects.
3. Add a fixture with multiple run spans, non-default master/layout fonts, equations, groups/connectors, crop/hyperlink, chart/table/notes, and animation timing. Assert both semantic package parts and rendered output.
4. Decide the chart contract: implement a native chart adapter, or label browser-created charts as visual snapshots with no implied PowerPoint chart editability.
5. Add shared line-breaking/measurement and overflow golden tests; do not park overflow in notes as a substitute for a visible warning or correct layout.
6. Test true two-user merge, undo, reload, and unsupported-operation refusal in a clean collaboration session.
7. Run the app, bridge, and Office readback on macOS. Windows source inspection cannot certify Mac packaging, bridge behavior, or installed Office compatibility.
