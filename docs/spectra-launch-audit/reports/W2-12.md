## State-transition table

The policy lattice is item > folder > workspace > mount > account. Structure propagation and physical deletion are separate decisions. `ask` is not propagation; a durable approval is required before either side changes.

| Event / policy | Disk state | Spectra/cloud state | Expected transition/status |
| --- | --- | --- | --- |
| `independent` + local edit | Keep ordinary file; watcher may observe only if content policy includes it | No automatic organization change; content direction remains policy-specific | Stable snapshot → upload/report only when content policy allows; folder move/rename is ignored. |
| `independent` + Spectra move/rename | Leave selected-folder path unchanged | Update Spectra organization | No bridge structure request; explanation says organization is independent. |
| `mirror-to-disk` + Spectra move/rename | Journal a move/rename after collision/claim checks | Spectra organization already changed | Pending → claimed → safe writer relocate → verified; actual path becomes authoritative. |
| `mirror-from-disk` + local move/rename | Watcher records native path identity | Propagate disk organization to Spectra | Stable identity continuity → cloud structure update; source/test only in this run. |
| `mirror-both` + move/rename | Journal the requested side and reconcile the other | Propagate both directions with stale-revision protection | Claim/verify on both sides; conflict rather than last-write-wins if revisions diverge. |
| `ask` + move/rename | Leave bytes/path unchanged pending decision | Leave organization unchanged pending decision | `approval-required`; durable decision precedes mutation. |
| Any policy + Spectra-to-disk physical delete | Approval required; verified delete moves real file to Recycle Bin and never recreates it | Spectra item is already in Trash; local replica becomes unavailable after verified completion | `approval-required` → claimed → recycle → verified; replay of an already absent path is now verified. |
| Local source deletion + cloud payload, `mirror-to-disk` | Missing local replica gets an idempotent restore request | Cloud payload remains available | `restore-to-disk` → bridge safe write/readback verification → current. Not live-run. |
| Local source deletion, other structure modes | Do not recreate automatically; retain unavailable state | Cloud replica may remain available | `keep-unavailable` (or `ask` for `ask` mode); no silent local recreation. |
| Storage preset `device` | Local replica required; cloud is metadata-only | Spectra listing remains; cloud payload is not required as the target | Local verified → policy transition verified. |
| Storage preset `spectra` | No new local replica; an existing physical file is retained when Spectra stops updating it | Cloud full payload required; missing payload may be materialized from an active local copy | Transition pending until materialization/upload conditions are verified. |
| Storage preset `both` | Local replica required and continuously editable | Cloud full payload required | Bidirectional; pending until local/cloud replicas agree and readback is verified. This is the UI recommendation for editable cross-device copies. |
| Storage preset `linked` / “Read, don’t change” | Protected local original required | Metadata-only/manual cloud relationship | No Spectra write to the protected original; transitions remain guarded. |

The transition planner deliberately refuses missing/unverified local targets, cloud payload absence, pending protected changes, or disagreement requiring reconciliation. The UI item control also keeps a physical disk file when switching an item to `Keep in Spectra`; a storage choice is not a delete command.

## Source inspection and fix

Windows `HostPlatform` obtains volume serial + file index and opens a read handle with `FILE_SHARE_READ` for stable hashing. `SafeWriter` journals intent, checks the grant and expected hash, uses a temporary sibling, flushes and atomically replaces, then verifies readback. The journal is SQLite WAL with full synchronous durability. Bridge sync claims target preconditions and refuses stale revisions, locked targets, missing grants, and superseded queue entries.

Finding **W2-12-F01 (fixed, important / small):** `SafeWriter::recycle` could fail a replay when the first process had already moved the target to the Recycle Bin but stopped before recording the journal transition. A retry then saw a missing path and could report failure for an already-achieved destructive action. The fix in `bridge/bridge-core/src/fs.rs:301-334` marks an absent target as `Performed` then `Verified` after the existing idempotency check. The regression test is at `bridge/bridge-core/src/fs.rs:730-766`. It is deliberately narrow: it does not recreate or overwrite an absent target.

Finding **W2-12-F02 (open environment blocker, important):** cached Bridge pairing/status survives while the web/Convex runtime is unavailable. This prevents live cloud readback and makes the cached `Ready` label insufficient for lifecycle sign-off. Parent/runtime owner should restore the existing stack and rerun this matrix without changing the shared mount.

Finding **W2-12-F03 (unresolved architecture, launch-blocking for Mac):** Unix `HostPlatform::is_locked` returns false and `open_stable_reader` is only a read-only open. The trait documentation says platforms without writer-completion proof should fail closed, but the Unix implementation still returns a reader. That is not equivalent to Windows share-mode proof. Do not mark Mac native Office/provider safety complete until the Mac implementation has an explicit safe-writer/writer-ownership strategy and a real run.

Finding **W2-12-F04 (unresolved provider/native proof):** provider folder detection, wider stability windows, `~$` exclusion, placeholder failure, and local hash tests are valuable but do not establish OneDrive hydrated-placeholder behavior or a real Office save against the provider. The provider-style files in this run are named fixtures only.

Finding **W2-12-F05 (unresolved lock semantics):** watcher comments distinguish a stale Word owner file after a crash from a live share lock, while generic stability tracking suppresses any present `~$` owner file. This conservative behavior is safer than guessing, but needs a real Word-open, Word-save, crash/stale-owner, and reconnect matrix before changing.

Finding **W2-12-F06 (known shared-account limitation):** the browser session is the same-account/platformOperator surface used by the launch audit. It does not prove a second human role, independent credential, cross-device claim, or multi-user conflict.

## Browser-first permission and preset guidance

From Settings → Files and devices:

1. Pair/connect the device, then use Add folder and the Windows-native folder picker.
2. Choose `Both` for normal editable work that must remain a regular local file and be available in Spectra.
3. Choose `Keep on this computer` for device-local storage where other devices may list the item but need this PC available.
4. Choose `Keep in Spectra` for cloud-first storage; if a physical copy already exists, Spectra stops updating it rather than deleting it.
5. Use item-level `Read, don’t change` / linked behavior for protected originals. Treat this as a write-safety policy, not a collaboration-role permission.

Do not interpret `Connected` or `Ready` from a cached page as cloud proof; require fresh Bridge + web/Convex health and a native-byte/hash/readback record. Physical deletion should remain approval-gated and end in Recycle Bin verification.
