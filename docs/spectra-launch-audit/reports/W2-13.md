## Result

Windows source, unit-test, and release compilation checks pass. The Bridge now
has explicit Tauri `app`/DMG targets, deterministic icon generation, embedded
release deployment coordinates, a manual Windows/macOS artifact workflow, an
unsigned friend-Mac overlay, a Mac runbook, quiet Windows startup, and working
diagnostic-log wiring in both the tray and embedded window.

This is Mac build preparation, not a Mac launch result. No Mac, Apple
Developer account, signing certificate, notarization credential, GitHub
Actions run, updater publication, or public release was available or used.

The shared live runtime was read only. At the time of the final readback the
web health endpoint was HTTP 200 but `not_ready`, Convex did not answer,
Convex port 3002 refused the connection, while the existing gateway and
loopback Bridge endpoints answered. The runtime was not restarted,
reconfigured, or repointed.

## Scope and current architecture

The app is a Tauri 2 Bridge shell in `bridge/bridge-app`. Pairing and setup
remain browser-first; the native window is hidden after startup and the local
service is exposed at `127.0.0.1:47615`. The existing autostart path is kept,
including the Windows repair path and the cross-platform autostart plugin.

The package config now requests `nsis`, `app`, and `dmg` bundles and lists the
generated platform icon set (`bridge/bridge-app/tauri.conf.json:14-22`). The
workspace emits build output under `bridge/target`, which is reflected in the
release runbook (`bridge/bridge-app/RELEASE.md:21-34`).

## Findings

### W2-13-F01 — Mac public-launch gate remains open

- Severity: P1 launch blocker. Confidence: high. Status: open / explicitly
  bounded.
- Chain: Windows can compile the Rust binary, but cannot prove a signed Mac
  app, notarization, Gatekeeper acceptance, LoginItems/LaunchAgent behavior,
  Keychain, APFS identity, provider behavior, or native-writer behavior.
- Evidence: no Mac or Apple credentials were available; only the Windows
  release executable was produced. The runbook calls out the required Mac
  gate at `bridge/bridge-app/RELEASE.md:68-74`.
- Remedy: run the unsigned friend-Mac smoke test first, then produce a signed
  and notarized candidate and repeat the full gate before calling the public
  launch ready.

### W2-13-F02 — Release/autostart deployment coordinates were not explicit

- Severity: P1 before fix. Confidence: high. Status: fixed in this commit,
  hosted integration still unproven.
- Chain: an installer or autostart entry may not inherit a developer's shell
  environment; without `SPECTRA_CONVEX_URL` and `SPECTRA_ORIGINS`, pairing and
  sync cannot target the hosted deployment.
- Fix/evidence: `configure_embedded_release_environment` embeds only the
  explicit release-build values while preserving process-environment
  overrides (`bridge/bridge-app/src/main.rs:157-170,2194-2195`). The manual
  workflow requires and validates hosted inputs (`.github/workflows/bridge-desktop.yml:72-96`),
  and the runbook requires the same coordinates (`bridge/bridge-app/RELEASE.md:12-19`).
- Limit: no authoritative hosted URL was supplied for a packaging run, so
  this fix has source/build coverage but no hosted Mac readback.

### W2-13-F03 — Windows release console violated quiet-start intent

- Severity: P2 before fix. Confidence: high. Status: fixed.
- Chain: the Tauri binary could open a console window on Windows even though
  the intended behavior is a quiet tray service.
- Fix/evidence: `#![cfg_attr(windows, windows_subsystem = "windows")]` is now at
  `bridge/bridge-app/src/main.rs:1`; the release binary compiled successfully.

### W2-13-F04 — Logs action was dead and Pause was misleading

- Severity: P2 before fix. Confidence: high. Status: fixed with bounded
  behavior.
- Chain: tray/embedded “Open logs” actions did nothing, while implementing a
  real Pause would require core sync semantics that are not present.
- Fix/evidence: `open_logs_impl` writes the last 200 journal diagnostics and
  opens the OS-native file handler (`bridge/bridge-app/src/main.rs:2146-2191`);
  the command is wired to the embedded button (`bridge/bridge-app/ui/index.html:28,60`)
  and tray menu (`bridge/bridge-app/src/main.rs:2445-2458`). The misleading
  Pause menu item was removed rather than presented as functional.
- Limit: the OS file opener was source-compiled but not clicked in a live
  Tauri window.

### W2-13-F05 — Mac folder-picker copy was falsely Windows-only

- Severity: P3. Confidence: high. Status: fixed.
- Evidence: the copy now says “Your computer uses its native folder picker”
  at `src/features/spectra/bridge/bridge-settings.tsx:349`.

### W2-13-F06 — Provider stability test was not portable

- Severity: P2 before fix. Confidence: high. Status: fixed at the test level.
- Chain: raw `C:\...` strings are one path component on Unix, so the existing
  test did not exercise provider recognition on macOS/Linux.
- Fix/evidence: the test now constructs provider paths from components at
  `bridge/bridge-core/src/watcher.rs:780-800`; all 11 watcher tests pass on
  Windows. This improves cross-platform test validity but is not a Mac runtime
  provider proof.

### W2-13-F07 — Updater endpoint and signatures are not release-proven

- Severity: P1 for public distribution. Confidence: high. Status: open.
- Chain: the base config enables updater artifacts and names
  `https://updates.spectra.school/bridge/{{target}}/{{arch}}/{{current_version}}`,
  but no feed response, artifact signature, key rotation, or publication was
  verified. A syntactically configured endpoint is not distribution proof.
- Fix/evidence: friend builds merge
  `bridge/bridge-app/tauri.friend-test.conf.json:1-6` to disable updater
  artifacts; public-candidate workflow runs require Tauri signing inputs and
  upload artifacts/signatures without publishing (`.github/workflows/bridge-desktop.yml:98-140`).
- Remedy: configure the real signing key and hosted feed, inspect generated
  `latest.json` and signatures against the exact artifacts, then add a
  separately approved publication step.

### W2-13-F08 — Shared runtime was not ready during final live probe

- Severity: P1 evidence limitation. Confidence: high. Status: observed,
  not attributed to this patch.
- Evidence: `runtime-health.txt` records web `not_ready` with “Convex did not
  answer,” gateway dependencies not ready, healthy loopback Bridge JSON, and
  refused `127.0.0.1:3002`.
- Remedy: the owner should restore the approved baseline runtime and repeat
  browser pairing/setup verification; this task intentionally did not restart
  or reconfigure shared services.
