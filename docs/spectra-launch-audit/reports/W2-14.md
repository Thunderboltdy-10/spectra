# W2-14 — onboarding invitations and class selection

## Result

The invitation source flow is structurally sound for invitation-only entry: the token is hashed at the server boundary, preview is account-authenticated, acceptance requires the exact verified invited email, an active school, and the single-school membership invariant, and accepted-token replay is idempotent. School creation is a platform-operator setup path that creates a school, initial-admin invitation, limits row, onboarding saga, and audit event; acceptance of that initial admin invitation completes the saga.

The live ordinary-user walkthrough could not be completed because the shared local Convex deployment became unavailable during the named browser session. The available saved session is explicitly not ordinary-user authorization evidence: it displays a student label but also has platform-operator access. No external invitation/email, production account, ManageBac write, or shared runtime restart was performed.

Three bounded defects were fixed in the audit worktree and committed as `50a83b8400b175ba7ae4a007c1803829edba9060`:

1. Expired invitation acceptance previously patched the invitation and then threw; Convex rolled back the patch, leaving the invitation `pending`. Acceptance now persists `expired` and returns an explicit terminal result that the join UI renders without opening the workspace.
2. The sign-in/sign-up tabs dropped `redirect_url` during an invitation flow, which could strand a user who switched auth mode. Both tabs now preserve the invitation return URL.
3. Join preview failures were swallowed, and the “Join school” button remained enabled while preview was loading or had failed. The UI now shows the error, disables acceptance until preview succeeds, and clears terminal invalid/expired school-invitation cookies.

The class picker has distinct loading, not-connected, identity-required, empty, ready, and error states, and later editing supports add/release operations. Its current-year wording is not yet backed by a current-year data contract: the server filters tombstones and `archived`, but does not select by `academicPeriodKey` or another verified current-period field. That remains a precise W2-15/W2-16 integration decision, not a safe W2-14 UI-only change.

### Source and harness evidence

Source inspection at the wave baseline confirms the following behavior:

- The raw token is never sent to Convex as an accepted credential. The administration route hashes it before calling `memberships:previewInvitation` or `memberships:acceptInvitation`.
- Preview returns school name, invited role, exact normalized-email match, and whether the current account is already a member. It rejects unknown, revoked, expired, or unavailable-school invitations.
- Acceptance rejects wrong-account use before membership creation; a pending accepted token for the current school returns `alreadyMember` on replay rather than duplicating membership. A different existing school membership is rejected by the single-school invariant.
- `SignedInContinue` recovers the cookie before the ordinary `/workspace` fallback, and `joinTokenFromSearch` gives a URL token precedence over a stale cookie.
- Initial-admin invitation acceptance calls `completeOnboardingIfInitialAdmin`; a matching `schoolOnboardingSagas` row moves from `invited` to `ready` and records an audit event.
- `ClassShelfPicker` treats missing integration as `not_connected`, an unmapped account as `identity_required`, zero candidates as `empty`, a thrown fetch as `error`, and nonzero candidates as `ready`. Loading is separate and keeps the submit control from firing while the fetch is in flight.
- `ClassShelfOnboarding` preselects already linked classes, materializes only newly selected record IDs, and allows “Skip” to move the preference out of `pending`. `ClassShelfEditor` computes add/remove deltas and exposes both materialization and release.

### Current-year and ManageBac coverage

The class candidate query returns `academicPeriodKey` internally on source records but the candidate result and `ClassShelfCandidate` UI type do not expose it. Candidate selection is currently based on:

1. active authenticated school membership and verified personal mapping;
2. mapped or accessible class membership records;
3. non-tombstoned class records;
4. one best record per provider class ID; and
5. `normalized.archived !== true`.

There is no source-supported guarantee that a non-archived historical class will be excluded, and the wording “Choose this year’s classes” therefore overstates the current contract. Actual provider payload fields, academic periods, current/history duplicates, mapping state, personal route visibility, first sync, and later materialization were not available in the live runtime. I did not alter this policy because choosing a current-period rule belongs with W2-15/W2-16 and can affect source projections and sync semantics.

## Findings grouped by root cause

### W2-14-F01 — Expiry patch was rolled back by the throwing mutation

- **Severity:** important operational integrity; not an access-control bypass. **Confidence:** high; reproduced in `convex-test`.
- **Consequence:** an expired invitation was rejected, but its database row remained `pending`. Admin readback could show a stale invitation and repeated expiry checks would redo the same failed path. No membership was created.
- **Code chain:** `convex/memberships.ts:99-106` previously called `ctx.db.patch(... status: "expired")` and then threw `INVITATION_EXPIRED`. Convex mutations are transactional, so the throw rolled back the patch. The added harness initially failed by observing `pending` after the rejection.
- **Fix:** the mutation now patches and returns `{ expired: true, schoolId }`; `src/app/join/page.tsx` treats that explicit result as terminal, clears the cookie, and shows “This invitation has expired.” This keeps persistence and UI behavior consistent without pretending an expired invitation was accepted.
- **Neighbor checks:** wrong-email rejection remains a throw before any write; accepted replay still returns `alreadyMember`; school-unavailable, revoked, and invalid paths remain terminal errors.

### W2-14-F02 — Switching auth mode could lose the invitation return URL

- **Severity:** important for first-user invitation completion. **Confidence:** high from source; the live auth round trip was unavailable.
- **Consequence:** the sign-in page’s “Sign up” tab and the sign-up page’s “Sign in” tab linked to bare auth routes. A user who followed an invite, chose the other auth mode, and completed Clerk’s flow could land on the default workspace instead of returning to `/join?token=...`.
- **Code chain:** both pages received `redirect_url` and passed it to Clerk, but their cross-links were hard-coded `/sign-in` and `/sign-up`. The cookie helped only after `/join` had rendered; it did not make the tab switch itself preserve the intended path.
- **Fix:** `authHrefForRedirect` in `src/lib/invitation-session.ts` builds a correctly encoded auth link, and both auth pages use it. The unit test asserts both directions and the no-redirect fallback.
- **Neighbor checks:** the existing URL-over-cookie precedence and `SignedInContinue` full-document return remain unchanged.

### W2-14-F03 — Join preview failure/loading state was not truthful or safe to retry

- **Severity:** small-to-important UX correctness. **Confidence:** high from source and the baseline browser state; terminal invite-specific live readback was blocked by Convex outage.
- **Consequence:** while preview was pending, or after preview failed, the page could render an enabled “Join school” button with generic school-invitation copy. Clicking before preview completed or after a transient/backend failure sent an avoidable acceptance request. Expired/revoked/invalid preview failures were not shown until a second action.
- **Code chain:** `src/app/join/page.tsx` previously set `preview` to `null` in the catch path and left `status` as `ready`; the disabled expression did not include preview loading/error. The live `[REDACTED]` page showed this generic enabled state while `/api/spectra/administration` returned 500 because Convex was down.
- **Fix:** the page now tracks `idle/loading/ready/error`, disables acceptance while loading or after a preview error, renders the preview error message, and clears the cookie for terminal invalid/expired/unavailable-school errors. The backend remains authoritative for any direct mutation.
- **Limit:** there is no dedicated retry button; a reload or the sign-in return path retries preview. A real expired/revoked browser run after the primary runtime is restored is still required.

### W2-14-F04 — “Current classes” is not yet a verified current-year contract

- **Severity:** important if historical and current records coexist. **Confidence:** high source / unverified provider data.
- **Consequence:** a historical class that is not marked archived may be offered during first onboarding or later editing. The user-facing heading says “Choose this year’s classes,” but the query only filters tombstones and the normalized archived flag.
- **Code chain:** `convex/managebac.ts:3413-3450` carries `academicPeriodKey` while de-duplicating by provider class ID, then filters only `!archived`. `class-shelf-picker.tsx` maps only record ID, title, program, grade and workspace ID, so the UI cannot show or validate period identity.
- **Affected neighbors:** W2-15 live sync/materialization, W2-16 ManageBac source/isolation fixes, related assignments/resources filtered by academic period, and any existing class shelves keyed by provider-period identity.
- **Bounded remedy:** choose a provider-backed current-period contract using actual tenant payloads (explicit active-period field/date window/configured school year), expose enough period identity for readback, and test same-ID current/history candidates before changing the query. Do not infer currentness from title, fetch time, or UI copy alone.

### W2-14-F05 — Ordinary-user and real integration proof remains blocked

- **Severity:** launch evidence gap, not a source defect claim. **Confidence:** high.
- **Consequence:** this wave cannot state that a first ordinary student or teacher can complete a real invite, see the configured personal ManageBac classes, choose shelves, or edit them later. The only reusable session is platform-operator capable; live Convex went down before identity/class reads completed.
- **Evidence:** `RUNTIME.md` explicitly disqualifies the saved student-labelled session as ordinary-user authorization proof. The `launch-w2-14` request log recorded Convex WebSocket refusal and multiple API 500s. W1-09/W1-13 also marked browser invitation, ManageBac, teacher, and second-student coverage untested.
- **Required remedy:** use a disposable membershipless verified account, an active ordinary student, an ordinary teacher, a school admin, and a wrong-email account after runtime recovery; use `convex-test` only as harness evidence, never as a live first-user pass.
