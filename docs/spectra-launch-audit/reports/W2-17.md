# W2-17 — Shared native Office authorization seam

## Result

The owner-only native payload/lens seam is fixed in the worktree. Artifact capability now forwards through shared native reads and writes: an active same-school `modify` collaborator can read cloud Office bytes, activate a lens, queue a write to that collaborator’s own Bridge replica, and complete the write; a read-only, revoked, or unauthorized foreign-school actor cannot. Owner-local Bridge filesystem metadata remains private.

A second revocation seam was also fixed: a Bridge write that was queued/claimed before a grant was revoked cannot complete afterward, and Bridge payload-upload boundaries re-check artifact `modify` authority. Domain-restricted anonymous links remain unsupported until a trusted viewer-domain delivery context exists.

## Scope and current architecture

The path under test is:

| Surface | Authority boundary | Native/Bridge flow |
|---|---|---|
| Artifact | `authorityShared.evaluateAccessForActor` / `requireActorArtifactCapability` | owner, direct grant, same-school inherited grant, lifecycle and school boundary |
| Replica truth | `replicas:forWork`, `replicas:payloadForWork`, `replicas:activateLens` | artifact capability → cloud/local truth → verified payload or lens projection |
| Stored payload | `payloads:get` | account/hash lookup stays private; shared lookup requires an explicit artifact `workId` and read capability |
| Native routes | DOCX, Office, native export, and media helpers | server-side helper calls the work-scoped replica/payload contract |
| Bridge | credential → device/account actor, then artifact modify capability | local replica writes and external payload ingestion remain restricted to the device account and active artifact authority |

The important privacy boundary is that shared artifact authority does not imply access to another account’s device, mount, or filesystem path. `replicas:forWork` therefore presents cloud truth plus the caller’s own local replica; it does not return owner-local `deviceId`, `mountId`, or `relativePath` to a peer.

## Findings grouped by root cause

### W2-17-F01 — Native payload and lens functions did not forward shared artifact authority

**Severity:** Launch blocker for shared native Office workflows (fixed in worktree)  
**Confidence:** High  

Before this change, `authorityShared` granted a `modify` peer `read, modify, restore, use, comment`, but native routes reached owner-only `replicas:payloadForWork` and `replicas:activateLens`; historical base recovery also called hash-only `payloads:get`. This made a legitimate shared DOCX/XLSX/PPTX peer appear as `WORK_NOT_FOUND` at the native boundary.

The bounded fix is capability forwarding, not an ACL change: `payloadForWork` requires artifact `read` and selects only cloud or caller-account local replicas; `activateLens` requires artifact `modify`; `payloads:get` accepts an explicit `workId` for an artifact-authorized lookup while preserving account/hash-only privacy for unscoped callers; native DOCX/Office base recovery passes the work ID. Owner-local Bridge paths are excluded from peer responses.

Affected neighbors checked: artifact access, read-only materialization denial, queue targeting, media/native helper call chains, foreign-school denial, and existing Bridge chaos tests. Remaining limit: no live ordinary-account browser proof and no macOS Bridge run.

### W2-17-F02 — Queued Bridge writes were not reauthorized after artifact grant revocation

**Severity:** Important for revocation correctness (fixed in worktree)  
**Confidence:** High  

Before this change, `replicas:queueMaterialization` checked `modify`, but a device credential could continue through Bridge upload/claim/complete calls using a request created before grant revocation. That could allow a stale local save/readback transaction to mutate replica truth after artifact authority ended.

The bounded fix re-checks artifact `modify` at Bridge payload upload begin/commit, pending payload claim, missing-resource reconciliation, existing-resource discovery, write claim, and write completion. A revoked pending/claimed write is failed as `permission-revoked`, its dependent operation/transition is failed, and its replica is marked error; `completeWrite` returns without patching the cloud replica. Device/account ownership and policy checks remain in place.

The regression test proves claim-before-revoke then complete-after-revoke, and checks request/local/cloud readback. Mount availability and device revocation behavior were not broadened or changed.

### W2-17-F03 — Domain-restricted public links have no trusted anonymous viewer-domain context

**Severity:** Important for the restricted-link product mode (open)  
**Confidence:** High  

`convex/authority.ts` correctly compares a stored normalized `domainRestriction` against an optional `viewerDomain`, but `src/app/api/spectra/public/route.ts` calls `authority:publicProjection` with only the token hash. Restricted links therefore cannot resolve through the current anonymous route. This is not a bypass: omitting the domain fails closed.

Do not repair this by forwarding `Host`, `Origin`, or a client-supplied domain as authority. The supported fix needs a trusted authenticated school-domain/session assertion or another signed, domain-bound delivery context. Until then, keep this mode documented as unsupported rather than claiming parity.

## Small fixes completed

Source changes are in the W2-17 worktree and are intentionally limited to the native payload/replica contract, native base forwarding, and Bridge reauthorization. No sharing policy, invitation semantics, public-link ACL, ManageBac, or production runtime state was changed.

- `convex/replicas.ts`: shared read for `payloadForWork`, shared modify for `activateLens`, and caller-account filtering for local replica metadata.
- `convex/payloads.ts`: explicit work-scoped, read-authorized payload lookup; unscoped hash lookup remains account-private.
- `convex/bridgeSync.ts`: artifact `modify` rechecks and stale-write compensation at Bridge content mutation boundaries.
- `convex/replicas.test.ts`: owner/modify-peer/read-peer/revoked/foreign matrix plus Bridge revoke-after-claim regression.
- `src/features/spectra/lenses/native-payload-server.ts`, DOCX route, Office route: work ID forwarded when fetching stored native bases.

## Decisions for parent/Pablo

- Accept the capability-forwarding shape: artifact `modify` controls native write/lens operations, artifact `read` controls retained bytes, and local Bridge paths stay account-private. This matches the existing capability table and avoids exposing another account’s device credentials/filesystem.
- Keep hash-only payload lookup tenant-private; require the artifact work ID for shared native base recovery. This is the narrowest way to support retained projection bases without creating a global hash oracle.
- Treat domain-restricted anonymous links as a product decision, not a host-header patch. Evidence supports fail-closed behavior today but not intended viewer success.
- Do not call the shared Office workflow launch-ready until live two-role Windows evidence and a macOS plan/build are available.
