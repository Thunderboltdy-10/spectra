# W2-19 — Overloaded layouts, navigation, and understandable errors

## Result

The Windows live baseline exposed two concrete responsive navigation defects: the nine-item mobile rail renders past the viewport, and shared section rails visually collapse labels into clipped icon/initial fragments at narrow widths. The live primary runtime was also unavailable at the Convex boundary, which provided consequential evidence that the main overview error is safe and retryable while several data surfaces could not be exercised with real artifacts.

I made a contained shell/panel patch in the isolated worktree. Mobile navigation now keeps four primary destinations and an explicit labeled More menu. Shared section navigation keeps complete labels and reduces to three primary sections at ≤639px. The chat browser now distinguishes a failed request from a successful empty result, offers retry, and becomes a full-screen mobile dialog with focus containment and opener restoration. Route-side artifact/thread failures now use the shared safe failure formatter with an actionable retry toast. The patch is not in the live primary runtime.

## Scope and current architecture

This task covered the authenticated shell, Library/Workspace/secondary-route framing, shared section navigation, the generic chat browser and route-side openers, error/empty-state language, and responsive/focus behavior. `/chat`-specific behavior remains with W2-24; the action dispatcher remains with W2-06; Bridge setup copy remains with W2-13. Office editing, backend policy, and the universal K-bar were not expanded.

## Findings grouped by root cause

### Responsive navigation has no bounded priority model

#### W2-19-F01 — Mobile destination rail renders outside the viewport

- **User consequence:** At 320–390px, Calendar, Agents, School, Analytics, Workspaces, Alerts, and any role-gated destinations are outside the initial viewport. A student who does not know the K-bar or the horizontal-scroll gesture can conclude those destinations do not exist.
- **Severity:** important / P1 responsive discoverability.
- **Confidence:** high. Confirmed in live baseline snapshot geometry at 390px and 320px; source directly mapped all items into a fixed bottom rail with horizontal overflow.
- **Source chain:** `app-shell.tsx` mobile nav originally used `coreDestinations.map(...)` followed by two additional 62px-minimum buttons inside `overflow-x-auto`.
- **Bounded remedy:** Four primary destinations retain direct links; remaining routes, Workspaces, and Alerts are offered through the existing labeled Radix overflow menu. The active state is reflected on More for non-primary routes or open sheets. This does not remove any destination or attempt a full command bar.
- **Affected neighbors:** shell shortcut discoverability, notification/workspace sheets, role-gated Admin/Super Admin links, mobile keyboard/screen-reader navigation.

#### W2-19-F02 — Narrow section rails visually clip labels

- **User consequence:** ManageBac, Settings, and other shared section rails expose accessible names that are not visually readable. In the 320px screenshot, `Files and devices` becomes an icon/initial fragment; a user cannot tell which section is selected or what is in More without prior knowledge.
- **Severity:** important / P1 responsive and navigation comprehension.
- **Confidence:** high. Live screenshots and snapshot boxes show the current behavior; the source used `min-w-0 shrink` plus `truncate` with five primary sections.
- **Source chain:** `product-section-nav.tsx` defaulted to `primaryCount=5`; every caller uses the default. The active item could be swapped into the fifth slot, but surviving buttons were still allowed to shrink.
- **Bounded remedy:** At ≤639px, the same priority order shows three full labels, active-section swapping uses that responsive count, and whole tabs move to the portal overflow. Wider surfaces keep the caller's five-item priority. This preserves information architecture and avoids horizontal label clipping.
- **Affected neighbors:** ManageBac's eight sections, Settings' six sections, School/admin rails, deep-link active state.

### Error and focus contracts are inconsistent at panel boundaries

#### W2-19-F03 — Chat request failure was indistinguishable from an empty chat list

- **User consequence:** A server/auth/network failure could render `No chats found / Try a different search or filter`, encouraging a user to change filters when the real recovery is to reconnect or retry. This is particularly harmful when returning to an old thread.
- **Severity:** important / P1 trust and recovery.
- **Confidence:** high for source; medium for live visual reproduction because the shared data service failed before the Library chat browser could be opened.
- **Source chain:** `ChatBrowserPanel`'s list effect caught any failure with `setThreads([])`. Its render path only tested `loading` and `groups.length === 0`.
- **Bounded remedy:** Separate `loadError` from the successful empty state, preserve the error through the render, and retry the same bounded request. The recovery copy is human-facing and avoids internal server language.
- **Affected neighbors:** W2-24 chat history, Library/Workspace artifact recovery, auth/session errors, telemetry of empty versus failed states.

#### W2-19-F04 — Mobile chat browser had no protected focus/dismissal contract

- **User consequence:** The panel was an absolute dock capped at `calc(100vw - 24px)` with only an Escape listener. On mobile, the underlying Library/composer remained visually and potentially interactively present; Tab could leave the panel, and closing did not restore the opener.
- **Severity:** important / P1 accessibility and recovery.
- **Confidence:** high for source; not live-mounted because the data service prevented reaching the browser.
- **Source chain:** `ChatBrowserPanel` returned an `aside` with `aria-label` only, no dialog role/scrim/inert or focus management. The historical W1 reports and source both identify the same boundary; this task did not alter `/chat`'s separate history/dock surface.
- **Bounded remedy:** Desktop remains a docked `aside`; at ≤767px the browser renders a modal scrim and full-screen dialog, auto-focuses search, traps Tab, closes on Escape, and restores the previously focused element. This is intentionally limited to the generic chat browser.
- **Affected neighbors:** Library panel open buttons, route-side panels, screen-reader navigation, mobile Live Dock/composer layering.

#### W2-19-F05 — Generic route-side open errors leaked raw messages and had no retry

- **User consequence:** Opening a work or conversation from School/ManageBac/Settings could expose `error.message` directly in a toast. Users received no stable next action and could not repeat the same open without navigating back to the source control.
- **Severity:** small / P2, promoted to important when data failures are common.
- **Confidence:** high for source; live route-side open was blocked by the unavailable overview/data service.
- **Source chain:** `RouteSidePanelHost.loadWork` and `loadThread` called `toast.error(error.message)` in their catch blocks.
- **Bounded remedy:** Use the existing `describeFailure` safe formatter, show a short opaque reference, and make the toast action repeat the original artifact/thread request.
- **Affected neighbors:** ProductErrorState copy contract, permissions/not-found semantics, global toast behavior, W2-24 thread opening.

### Cross-shell panel density needs an explicit product decision

#### W2-19-F06 — Local pane allocator does not own every simultaneous surface

- **User consequence:** A realistic user sequence can combine shell chrome, Library organizer/list, artifact studio, route-side thread/studio, Live Dock, run detail, and bottom composer. The primary artifact/editor can lose useful width or lower controls can sit underneath persistent dock content.
- **Severity:** important / P1 if persistent in clean student sessions; future architecture package otherwise.
- **Confidence:** medium-to-high. Source confirms separate mount authorities; W1-11/W1-15/W1-16 captures show the density pattern. This task could not reproduce a clean live artifact sequence because data loading failed.
- **Source chain:** `AppShell` renders `GlobalRouteWorkbench` and `RouteSidePanelHost` beside route children; `SpectraShell` owns its local split allocator and mounts ChatBrowser/LiveThread/RunDetail alongside its lower composer/dock. The authorities are not one registry.
- **Bounded remedy:** Do not add more width heuristics in this patch. Parent should adopt a single priority policy: primary artifact/content first; one high-cost secondary surface second; run detail/chat browser promoted to overlay on narrow widths; composer/dock collapses or gains a reserved, scroll-safe band; route-side opening minimizes a competing global dock. Every promotion needs one labeled close/minimize path and focus return.
- **Affected neighbors:** W2-24 `/chat`, W2-06 action dispatcher, Live Dock, comments, native/AI result cards, route workbench persistence.

#### W2-19-F07 — Settings Files and devices content also exceeds the narrow content box

- **User consequence:** Even after section-nav labels are fixed, device details and controls can extend beyond the visible 320px content region. Important Bridge setup/readback controls can be clipped behind the viewport or composer.
- **Severity:** important / P1 for mobile setup; not a Bridge protocol verdict.
- **Confidence:** high for the captured layout geometry, medium on all settings states because the shared data service was degraded.
- **Source chain:** The live snapshot showed inner settings blocks wider than their parent at 320px. The surrounding settings/Bridge layout requires a broader audit than the shared section-nav component.
- **Bounded remedy:** Add a settings-specific narrow-layout pass: enforce `min-w-0` through card/grid children, stack action rows at the content breakpoint, preserve 44px controls, and reserve composer safe area. Pair with W2-13's Bridge setup copy review; do not change native pairing semantics here.

### Positive findings

- The desktop shell has a visible skip link, named navigation landmarks, `aria-current` route semantics, an existing platform-correct Ctrl/Command shortcut hint, and a real collapse control.
- Wide `/managebac` content and its 300px context rail remained legible at 1536px. The section overflow is a portal menu and does not push the rail onto a second row.
- The primary overview failure at `/library` is materially better than the chat-browser failure path: it states that Spectra did not load, explains the connection/retry expectation, and provides `Try again`.
- ManageBac's visible copy distinguishes school connection/setup from ordinary verified data instead of fabricating populated class records during the backend failure.
- The existing `ProductSectionNav` active-item swap and `OverflowMenu` portal were good extension points; the patch reuses them instead of introducing a second navigation model.
- The local workbench allocator already provides a sensible basis for the parent panel policy: it reserves content width, prioritizes open work, promotes to overlay, and uses hysteresis. The gap is cross-shell registration, not a reason to replace it.

## Decisions for parent/Pablo

- **Recommendation:** Keep four direct mobile destinations (Chat, Workspace, Library, Calendar) and the explicit More menu from this patch. It is a stable novice mental model and avoids hidden horizontal navigation. If analytics later shows a different primary order, change only the four-item priority list, not the overflow contract.
- **Recommendation:** Treat `ProductSectionNav`'s compact three-label rule as the default shell contract at ≤639px. It preserves full words and uses the already-established overflow portal; adding more adaptive counts per page would recreate competing heuristics.
- **Recommendation:** Adopt one cross-shell panel priority policy before expanding comments/run/artifact combinations. Primary content should keep a readable reserve; only one high-cost secondary surface should be in-flow, with other surfaces promoted to modal/overlay or minimized. Preserve the existing local allocator as the row-level implementation and add a shell-level arbitration boundary around it.
- **Do not claim:** The live 500s are not proof of an empty user account or a ManageBac disconnected tenant. The source fix is not in the runtime. No full K-bar, true two-user thread recovery, Office editing, or Mac runtime was validated here.
- **Evidence that could change these recommendations:** Healthy runtime with a clean mobile account, a real user task-frequency sample, and a mounted focus/readback pass could justify a different primary order or a less modal desktop/mobile panel contract. The current evidence does not support hiding more routes or promising cross-shell search.
