Date: 2026-09-08

## Executive result

The active Office and AI attachment paths now have explicit request, file, aggregate, archive-expansion, member-count, and PDF-page budgets before expensive parser work. The previous direct upload finalizers now verify stored size, digest, and MIME metadata independently of HTTP-route checks; mismatches delete the candidate and quarantine imports where that state exists. The legacy duplicate attachment preparer now delegates to the bounded compute preprocessor.

The dependency baseline is still not launch-clean: `npm audit --omit=dev --audit-level=moderate` reports 18 production advisories (10 high, 8 moderate, 0 critical). No dependency was upgraded in this wave because the safe fixes split across a Next patch, a Convex/helper compatibility alignment, and major parser/export changes. The remaining dependency decision is recorded below rather than hidden behind an audit override.

### PDF.js interpretation

The audited server paths only extract text or render selected pages. They do not create a PDF annotation layer or intentionally enable document scripting. The source now sets `disableFontFace`, `enableXfa:false`, `maxImageSize`, and `stopAtErrors`, and caps pages at 200. Those settings reduce renderer work but do not remediate the vulnerable installed PDF.js version. A private upgrade must cover the other browser/library consumers found by the trace, not only the AI route.

### PPTX/image-size interpretation

The uploaded PPTX intake uses `fflate` to unzip selected XML and media. `pptxgenjs` is used for generated exports, so the high audit edge is not the same as the incoming-package parser. The image-size advisories have no patched installable version; upgrading or overriding without a controlled export regression would be misleading.

## Intake bounds implemented

### Office multipart route

`POST /api/spectra/imports/office` now rejects a declared request larger than 22 MiB before `formData()`. After multipart parsing, it rejects files outside 1–20 MiB before the existing `file.arrayBuffer()` call. The route continues to own the existing format selection and Office lens dispatch.

Residual: a chunked request with no trustworthy `Content-Length` can still be buffered by the platform’s `formData()` implementation before the file-size check runs. Closing that gap needs a streaming multipart parser or platform-level body limit; it was intentionally not introduced as a transport rewrite in this wave.

### AI run request and attachment preparation

`/api/spectra/run` now reads the request body through a bounded stream reader with a 96 MiB ceiling and declared-length preflight. The active preprocessor enforces:

- at most four attachments;
- 64 MiB aggregate decoded attachment bytes;
- exact declared-vs-decoded byte equality for binary base64 attachments;
- per-file ceilings: image 8 MiB, PDF 10 MiB, DOCX 8 MiB, XLSX 12 MiB, PPTX 20 MiB, text 2 MiB;
- non-negative safe-integer declared sizes;
- bounded UTF-8 text byte counting rather than trusting the declared size.

The visual evidence path in `loop/intake.ts` reuses the declared size and per-format maximum when it decodes the prepared payload a second time, so rendering and embedded-media extraction do not reopen an unbounded base64 path.

### ZIP expansion and PDF work

Before ExcelJS, Mammoth, or `fflate` receives an Office package, the guard parses the ZIP end record and central directory and rejects:

- more than 2,000 entries;
- any member whose declared uncompressed size exceeds 32 MiB;
- more than 128 MiB total declared expanded bytes;
- ZIP64/sentinel sizes and multi-disk archives;
- malformed central-directory structure.

This is a budget preflight, not a replacement for Office parser semantics. ZIP64 rejection is deliberate because current intake byte ceilings are far below the safe 32-bit budget. PDF parsing is capped at 200 pages and the PDF document is destroyed in a `finally` block.

## Integrity finalizers

`convex/artifactImports.ts:finalizeUpload` now independently checks stored size, storage digest, and normalized MIME against the import job. A mismatch deletes storage, marks the job `quarantined`, records a reason, and raises `IMPORT_UPLOAD_INTEGRITY_FAILED`. The existing HTTP PUT route still hashes the full request body before upload; the Convex finalizer is now an independent storage-side check rather than trusting the route.

`convex/payloads.ts:put` now enforces a 100 MiB payload ceiling and verifies stored size, digest, and MIME before creating or replacing a payload object. It deletes a mismatched candidate and raises `PAYLOAD_INTEGRITY_FAILED`.

`convex/bridgeSync.ts:commitPayloadUpload` now normalizes media types, enforces the same 100 MiB bridge payload ceiling, verifies the stored digest and size, and verifies MIME when Convex storage metadata provides it. A mismatched candidate is deleted before `PAYLOAD_INTEGRITY_FAILED`. The bridge transport was not moved: Rust still sends the declared `Content-Type` to the Convex upload URL and then commits through the existing mutation. The missing-content-type allowance is retained for Convex’s in-process storage test double, which does not populate that optional metadata; production bridge uploads provide the header.

Because Convex’s test runtime exposes storage SHA-256 metadata as base64 while the documented application contract is hexadecimal, the shared `convex/storageIntegrity.ts` helper accepts either representation and compares the decoded digest to the validated hexadecimal request hash.

## Findings and disposition

### W2-21-F01 — dependency baseline contains active high-risk paths

Severity: High / release gate.  
Evidence: 18 production findings; direct paths listed above.  
Disposition: Source guards reduce intake exposure, but no package advisory is claimed closed. Minimum next actions are a private Next patch test and Convex/helper alignment. PDF.js and PPTX/Excel parser upgrades remain report-only until compatibility work is funded and tested.

### W2-21-F02 — Office and AI bodies could be consumed before declared bounds

Severity: High.  
Disposition: Fixed for the active stream/run and file paths with 413 responses, exact decoded sizes, aggregate budgets, and parser preflight. Chunked multipart remains explicitly residual.

### W2-21-F03 — archive expansion and repeated visual decoding lacked a shared budget

Severity: High.  
Disposition: Fixed for active compute and visual evidence paths with ZIP central-directory budgets, page limits, exact/max re-decode, and parser cleanup. Cross-format parser behavior remains library-owned.

### W2-21-F04 — storage finalizers did not consistently bind bytes/digest/MIME to the declared upload

Severity: High.  
Disposition: Fixed for imports, native payloads, and bridge commits with deletion/quarantine on mismatch. The HTTP import route’s pre-upload hash remains in place as a defense-in-depth check.

### W2-21-F05 — major or unavailable dependency fixes need compatibility evidence

Severity: Medium / release process.  
Disposition: Report-only. `pdfjs-dist` 6.x, PPTXGenJS major changes, ExcelJS changes, and any `image-size` workaround require private install, build, parser fixtures, and export regression coverage. No `npm audit fix` or lockfile rewrite was used.
