# W3-01 — Runtime recovery, live coordination, and operator restoration

## Result

All live Wave 3 testers W3-02 through W3-12 completed and published reports. The
primary instance-1 runtime stayed healthy throughout the tester batch on the
four required readiness endpoints. Several testers reproduced one-second
Convex function timeouts, browser connection interruptions, and one application
import-completion HTTP 500 while those health probes remained green; these were
classified as application/capacity symptoms rather than a dead runtime, so no
runtime recovery was performed during the live cases.

After the last live tester closed, the temporary student-mode operator
configuration was restored with the documented helper (`role-mode.mjs restore`,
exit 0). The first controlled restart exposed a missing installed
`@hocuspocus/server` package and a web health HTTP 500. Recovery stopped that
unhealthy launch, rebuilt `node_modules` exactly from the existing
`package-lock.json` with `npm ci`, and relaunched the preserved instance with
the pinned private Node 24.20.0 runtime. The final runtime is healthy, the
authenticated `/superadmin` surface loads, and the identity endpoint returns
HTTP 200 with `platformOperator: true`.

W3-01 made no source-code changes and created no source commit. The instance-1
database, bridge pairing, mounts, and live tester artifacts were preserved.

## Findings grouped by root cause

### W3-01-F01 — One-second function timeouts under shared live concurrency

- Severity: important reliability risk; confidence: high for the observation.
- Multiple live testers hit the Convex maximum-duration message, request
  interruption, or a token/connection error while the Convex instance, web
  readiness, gateway, and bridge probes were simultaneously healthy.
- The evidence is distributed across W3-02, W3-04, W3-05, W3-06, W3-09,
  W3-10, and W3-12, with sanitized checkpoints in `readiness.log`.
- Treat this as a shared capacity/query-latency issue until isolated under a
  quiet window. Do not infer a dead backend from a single timed-out function
  when the required process/service probes remain ready.

### W3-01-F02 — Service health is necessary but not sufficient for UI readiness

- Severity: important launch-readiness distinction; confidence: high.
- Green health probes coexisted with browser-level query timeouts, auth
  hydration gaps, an import completion 500, and a false `/chat` error state.
- Health checks should be paired with a minimal authenticated route/readback
  probe during high-risk live windows; the health endpoints alone should not
  be treated as proof that every user action can complete.

### W3-01-F03 — Targeted dependency repair can create a second runtime failure

- Severity: important operational recovery risk; confidence: high.
- After the first role-restoration restart, the installed tree was missing
  `@hocuspocus/server`, and a targeted install changed hundreds of packages.
  The resulting web bundle surfaced `this.load is not a function` and returned
  HTTP 500 even after Convex/gateway readiness.
- Stopping the unhealthy stack and rebuilding from the existing lockfile with
  `npm ci` restored a consistent tree and allowed the pinned restart to pass.
- Future recovery should use a lockfile-consistent rebuild when a declared
  package is absent; avoid treating a partial package install as a stable
  runtime baseline.

### W3-01-F04 — Temporary operator configuration was restored and verified

- Severity: release-safety requirement; confidence: high.
- The documented role helper completed with exit 0 before the final restart.
- After restart, the authenticated administration identity endpoint returned
  HTTP 200 with `platformOperator: true`, the `/superadmin` link was present,
  and the Platform administration page loaded in the named audit session.

## Decisions for parent/Pablo

- Treat W3-01-F01 as an important shared reliability issue, not as proof that
  the backend is dead. Keep the exact saved checkpoints and run isolated
  retries before changing the deployment or query architecture.
- Treat health endpoints as a required baseline gate, then add authenticated
  route/readback probes for user-facing readiness.
- Prefer the lockfile-clean dependency recovery path if a declared runtime
  package is absent. The first targeted install was not a stable recovery
  baseline; `npm ci` restored the working tree without changing the lockfile.
- Integrate the owner source commits only after parent review and the live
  verification gates described in their reports. None of the W3 source patches
  is live in the final primary runtime.
- Leave the full deletion architecture unresolved until the cascade graph has
  explicit ownership and durable readback coverage.
- Temporary operator mode is restored and verified. The final browser session
  is closed; no temporary operator state should be re-enabled for follow-up
  testing without a new explicit authorization.
