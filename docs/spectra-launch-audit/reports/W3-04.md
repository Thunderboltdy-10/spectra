## Findings grouped by root cause

### W3-04-F01 — Exported charts are visual shapes, not native chart parts

- Severity: important parity gap; confidence high.
- Consequence: a downloaded deck can show the bars, but a PowerPoint user cannot rely on a native chart object, chart data workbook, or native chart editing round-trip.
- Evidence: the imported Office-authored fixture has `ppt/charts/chart1.xml` and `ppt/embeddings/Microsoft_Office_Excel_Worksheet1.xlsx`; the live export has no `chart*.xml` and no embedding, while its slide XML contains multiple bar-like geometries.
- Bounded remedy: treat as a chart architecture/package-writer work item, explicitly outside this repeat. Do not paper over it with another visual fixture.

### W3-04-F02 — Image insertion fails at the shared asset boundary

- Severity: important; confidence high.
- Consequence: users cannot insert an image through the presentation Insert → Image path; the UI shows a generic failure banner.
- Evidence: SVG is rejected by `verifyAssetBytes` as `ASSET_CONTENT_MISMATCH`; a valid PNG passes the HTTP route but Convex finalization returns `ASSET_UPLOAD_INTEGRITY_FAILED` and HTTP 500 after runtime recovery.
- Bounded remedy: repair and retest shared asset storage/finalization first, then repeat presentation image insertion. No generic asset route or Convex change was made in this task.

### W3-04-F03 — Shared org-tree query timeout interrupted the live repeat

- Severity: important shared-runtime reliability issue; confidence high.
- Consequence: the studio temporarily rendered “Something went wrong” and paused unrelated dock runs.
- Evidence: browser readback captured the exact `Q(orgTreeBoard:column)` 1-second timeout. W3-01’s recovery status confirmed all readiness endpoints healthy without a runtime restart; the presentation artifact was still readable afterward.
- Bounded remedy: retain the existing W3-01 recovery path and keep presentation findings separate from this shared outage.

### W3-04-F04 — Font and notes export are sound for the exercised case

- Severity: none found in this coverage; confidence high for the tested title.
- Evidence: live DOM and reload readback retained Georgia; the downloaded package retained Georgia run font and native notes XML. This also aligns with the existing baseline font-forwarding change in commit `81cf6a66`.
