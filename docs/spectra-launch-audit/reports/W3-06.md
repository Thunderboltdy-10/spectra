## Findings grouped by root cause

### W3-06-F01 — Research provenance was not forwarded into the agent artifact path

- Consequence: the research run could find public evidence, but the artifact quality gate saw no verified `document.sources`; citations could not be durably tied to evidence handles.
- Severity: launch blocker for source-backed research/document workflows. Confidence: high.
- Chain: pre-fix `executeAgentReadTool` → `conductParallelResearch` → snippets/bare URLs → model operation; the existing `buildResearchEvidence`/`SourceRecord` path was not invoked. The quality rubric then rejected the document for missing verified source metadata.
- Evidence: [`research-progress-3.yml`](<local-workspace> [`research-sources-open.yml`](<local-workspace> and source paths noted above.
- Bounded remedy: `f6653cc3` forwards exact verified source records, bounded evidence spans, canonical URLs, provenance, and partial-state truth; it does not invent citations or redesign the research engine.

### W3-06-F02 — Planned/generated content can be reported before canonical artifact readback is useful

- Consequence: users see `22-block document` and creation progress, but reopening shows only the default placeholder. This makes the Library summary and progress channel overstate the saved artifact.
- Severity: launch blocker for reliable creation. Confidence: high.
- Chain: progress/summary derived from planned or intermediate work → artifact shell remains readable → canonical body is placeholder; `verifyCommittedOutcomes` does not compare the claimed population with the reopened body.
- Evidence: [`research-details.yml`](<local-workspace> [`research-artifact-open.yml`](<local-workspace> [`sheets-artifact-open.yml`](<local-workspace>
- Bounded remedy: add a post-commit artifact population/readback assertion per blueprint, especially for documents and sheets; do not treat a plan or summary count as persisted content.

### W3-06-F03 — Supplied-data Sheets creation lost the requested workbook semantics

- Consequence: the six source rows, formulas, graph, interpretation, limitations, and requested name were not present after reopen; the title was reduced to `Six-Week`.
- Severity: launch blocker for AI-created workbook workflows. Confidence: high.
- Owner/neighbor: Sheets/editor parity should be handled with the W3-03 workbook work package; this repeat supplies additional readback evidence but does not patch Sheets here.
- Evidence: [`graph-progress-5.yml`](<local-workspace> [`sheets-artifact-open.yml`](<local-workspace>
- Bounded remedy: verify canonical cell/formula/chart state after each AI workbook creation and preserve the exact requested title before reporting success.

### W3-06-F04 — Presentation run hit shared runtime/function failures after healthy readiness probes

- Consequence: the requested deck could not reach artifact creation, so native chart, notes, slide readback, and export parity remain untested by this repeat.
- Severity: important, with infrastructure dependency. Confidence: high for the observed run errors; low for attributing them to presentation code.
- Evidence: `presentation-progress-0.yml` records the file-list failure; `presentation-retry-0.yml` records the 1-second function timeout. The same-time health probes returned ready.
- Bounded remedy: investigate the shared API/function timeout and file-list dependency in the isolated runtime before changing presentation layout/export code. Repeat with a clean run only after the runtime can sustain the expected duration.

- Consequence: the focused document remained a placeholder, but the follow-up did not create a duplicate artifact. This is safer than claiming a successful edit, but still fails the requested improvement.
- Severity: important. Confidence: high.
