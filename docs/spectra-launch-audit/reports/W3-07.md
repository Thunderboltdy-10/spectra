# W3-07 — Repeat onboarding, invitations and ManageBac

## Result

The healthy primary runtime was reachable for a real ordinary-student repeat, but the configured ManageBac provider returned `no_match` for the authenticated school email. That is an external/provider-data boundary, not evidence of an empty personal dataset. The live run therefore proved the identity gate, the truthful refusal to sync before identity resolution, terminal invalid-invitation handling, and the current navigation/recovery gap; it did not prove populated classes, selected-class polling, derived tasks/calendar/resources, source removal, or completion/notes survival after refresh.

I completed bounded source repairs in worktree commit `79e036b1` (`fix(w3-07): harden onboarding and ManageBac recovery`). The patch adds retry only for transient invitation-preview failures, keeps terminal invitation errors non-retryable, makes ManageBac sync history/provenance inspectable before identity verification, exposes stage/error/recovery actions in sync history, and maps source-removal conflicts to the backend-supported `detach`/`archive_projection` actions. It is not integrated into the primary runtime, so these repairs are source/harness evidence only until the parent applies the commit and rebuilds the app.

## Scope and current architecture

The live entry point is `/managebac`, rendered by `src/features/spectra/pages/managebac-integration-shell.tsx`. Its actions call the same-account web boundary at `/api/spectra/managebac`, which reads/writes through the local Convex integration and configured ManageBac provider. Identity resolution is an actual provider GET through that route; it accepts exactly one verified-email match and does not expose a selectable provider student ID. Class candidates and personal records are then read through the authenticated account/integration boundary. The sidebar exposes School but not a separate ManageBac destination; the ManageBac route is directly reachable and contains its own sections, with Sync history and Provenance under More ManageBac sections.

Invitation preview and acceptance are `/join?token=...` in `src/app/join/page.tsx`, using `src/lib/invitation-session.ts` for the token cookie and auth-return URL, then the administration API and membership Convex mutations. `convex/schools.ts:create` creates a school, its disabled-by-default school limit policy, a pending initial-admin invitation, an onboarding saga, and an audit event in one mutation guarded by a stable idempotency key. The new fixture test exercises that boundary without sending mail or contacting a remote school.

## Findings grouped by root cause

### W3-07-F01 — Provider no-match prevents the connected populated journey

Severity: external evidence limit / pending, not a launch defect by itself. Confidence: high for this local run.

The real identity action returned `status: "no_match"` for the authenticated school email. The UI correctly did not reveal alternative student IDs or fabricate classes. This prevents live proof of current classes, class selection, tasks, calendar, resources, source removal, and overlay preservation. It is not valid to call the result “no personal data” until a disposable connected provider fixture or an authorized temporary mapping returns a unique match. A second real account is unavailable and would be out of scope.

### W3-07-F02 — History and recovery were hidden behind the identity gate

Severity: important. Confidence: high; reproduced in the primary baseline.

The More menu exposes Sync history, but the student-facing render path applied the same unverified-mapping blocker to every non-admin tab. The live history snapshot therefore showed the active Sync history tab alongside “Match your verified school account” and no run table. That prevents a student from inspecting the status, stage, sanitized error, or available recovery action after a failed identity/sync attempt. This is separate from correctly blocking provider-derived Classes, Calendar, Tasks, and Period map before identity.

The bounded remedy in `src/features/spectra/pages/managebac-integration-shell.tsx:749` and `:854-1210` allows History and Provenance to render while leaving data-bearing tabs gated, and adds stage/error/recovery controls. It is source-only until commit `79e036b1` is integrated.

### W3-07-F03 — Class workspace materialization and detail polling use different selection contracts

Severity: important. Confidence: high from source inspection; live readback pending.

`convex/managebac.ts:listMyClassCandidates` filters tombstoned/archived records and returns candidates, while workspace materialization uses the accessible class IDs. However, `src/app/api/spectra/managebac/route.ts` builds sync fan-out from `accessibleClassIds`/year-group sets discovered from membership/catalog ingestion, not from the set of class workspaces the student selected. Therefore “choose which classes get their own workspace” cannot currently be interpreted as “restrict all detail polling to those selected classes”. The parent should preserve this distinction in the next connected fixture and decide whether selection is only a materialization preference or an explicit polling/privacy boundary.

The same path exposes `academicPeriodKey` in workspace identity but the candidate filter has no explicit current-period contract beyond tombstone/archive checks. Current/history provenance and period-map behavior remain unverified and should be tested with two periods before launch claims.

### W3-07-F04 — Timetable refresh has a calendarItems/legacy-artifact identity mismatch

Severity: important. Confidence: high from source chain; live readback pending.

`ensureTimetableProjection` stores a `calendarItems` ID in `externalProjections.projectionId` for a `timetable_event`, while `safelyRefreshProjection` treats that value as an `artifactId#eventId` pair and returns `false` when it cannot find a timetable artifact. A changed timetable source can consequently become a false conflict instead of refreshing the existing official calendar event. The source-removal path already normalizes a timetable projection as a `calendarItems` ID, reinforcing that two representations currently coexist. This needs a representation-aware refresh branch and a focused changed-event/source-removal test; it was deliberately left open rather than making an untested backend mutation during this repeat.

### W3-07-F05 — Conflict/recovery affordances did not match backend suggested actions

Severity: small-to-important depending on source-removal frequency. Confidence: high from source/backend comparison.

The previous student conflict UI always offered `Keep mine` and `Rebase`, while the backend can return source-removal suggestions `detach` and `archive_projection`. Those labels do not explain the actual safe choices for a removed source and could send the wrong resolution intent. Commit `79e036b1` now reads `suggestedActions` and exposes `Keep local copy` / `Archive source` when appropriate, plus retry/identity recovery in history. The focused ManageBac honesty test asserts these controls. It is not live until integrated.

### W3-07-F06 — Invitation preview had no transient retry affordance

Severity: small. Confidence: high from source inspection and focused test.

Preview errors had no retry path, while transient integration/network failures are recoverable. Terminal `INVITATION_INVALID`, `INVITATION_EXPIRED`, and `INVITATION_SCHOOL_UNAVAILABLE` errors must remain non-retryable and clear the token cookie as already implemented. Commit `79e036b1` adds `invitationPreviewCanRetry` and a `Retry invitation check` button only for non-terminal preview errors. The live invalid token repeat confirmed “This invitation is unavailable” with disabled Join school, so the terminal path remains truthful.
