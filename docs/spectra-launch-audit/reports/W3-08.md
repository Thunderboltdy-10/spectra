# W3-08 — ordinary student and peer authority boundaries

## Result

The ordinary student boundary is behaving as a restricted school member in the live runtime: the student can use the library, open an owned quiz/document, and view personal ManageBac and agent-library surfaces, while school overview capability is explicitly denied and `/admin` does not expose an admin shell. The live owner share flow shows no collaborators by default, creates a read-only public-link mode, and a fresh public link resolved before revocation and returned 404 after revocation.

The Convex authority matrix is covered by new fixture tests: read peers receive only `read/use/comment`, foreign-school actors are denied, revocation removes access, and both live and pinned embed projections re-check source access after revocation. No source authorization change was needed. Domain-restricted anonymous links remain intentionally fail-closed through the current public HTTP route because it has no trusted viewer-domain context.

This is evidence for authority boundaries, not a whole-product launch verdict. A second ordinary live account was not available, so live invitation acceptance and peer browser parity remain unverified.

## Findings grouped by root cause

### W3-08-F01 — Anonymous domain-restricted public links have no trusted viewer-domain context

**Severity:** Important for the restricted-link product mode; open
**Confidence:** High

`convex/authority.ts:1230-1315` correctly normalizes and compares an optional `viewerDomain`; an exact trusted-domain argument resolves, while an absent or wrong domain returns no projection. However, `src/app/api/spectra/public/route.ts:13-16` and `:30` pass only `{ tokenHash }`. The route does not derive a trusted domain from an authenticated identity and must not forward `Host`, `Origin`, or a browser-supplied body value as authority.

The consequence is that a domain-restricted link created in the UI/Convex layer cannot succeed through the current anonymous HTTP delivery path. It fails closed rather than bypassing the restriction. The fixture test and route test document both halves of this behavior; the live unrestricted-link test confirms create/read/revoke semantics.

**Bounded remedy:** choose a trusted domain-bound delivery contract (for example, a signed platform assertion or an authenticated school-domain session) before enabling this mode. Until that exists, label restricted anonymous links unsupported or omit the option. Do not patch this with request-header or client-domain forwarding.

No other authority defect was found in this scope. Peer read/modify capability separation, same-school invitation checks, foreign-school denial, revocation, owner-local metadata hiding, and embed source reauthorization are covered and behaved as expected in fixture/live evidence.

## Decisions for parent/Pablo

- Keep the current read-level capability set (`read/use/comment`) separate from authored-content modification and sharing. The fixture read peer can participate in the read surface without gaining `modify` or `share`.
- Keep foreign-school access denied unless there is a deliberate, explicit account grant; do not treat school-level membership or a shared embed as cross-school authority.
- Preserve the public route’s fail-closed behavior. A client-controlled domain or raw request header is not acceptable evidence of trusted school-domain access.
- Treat the live ordinary result as partial: it proves the student UI boundary and own-resource path, not a second-account peer browser flow.
