## Findings grouped by root cause

### W3-09-F01 — Fixed Library rail collapses the narrow workboard

- **Severity:** important; **confidence:** high; **type:** repeatable live layout defect.
- **User consequence:** at 390px only 118px of the board is visible beside the 248px folder rail; at 320px only 48px is visible. The 244px cards and their controls are clipped into an internal horizontal scroll area, so a student cannot comfortably browse or understand the selected work without a near-hidden gesture.
- **Code chain:** `OrganizerRail` is `w-[248px] shrink-0`; `WorkBoard` keeps a minimum max-content column layout and relies on `overflow-x-auto`. The outer document correctly avoids overflow, but the usable primary allocation is not responsive.
- **Evidence:** the 390/320 Library captures and measurements above; artifact, comments, related-chat and active-run checks show the dense surface is real rather than an empty-state artifact.
- **Bounded remedy:** make the rail collapsible or a narrow modal/sheet at the existing overlay boundary, with an explicit return path to the board. Do not change the global allocator or universal K-bar in this task.

### W3-09-F02 — Compact section labels still compete for narrow width

- **Severity:** important; **confidence:** high; **type:** repeatable live readability defect.
- **User consequence:** the Settings 390 baseline visually clips the third compact label to `Files and d...`; relying on a clipped label makes section choice ambiguous even though the More menu remains reachable. Three full labels are not a safe assumption at 320px.
- **Code chain:** `ProductSectionNav` shows three primary items at compact widths and a More menu for the rest. The baseline gap allocation was too generous for long labels.
- **Evidence:** `LA-W3-09-settings-390-baseline.png`; More is still readable/reachable in the 390/320 snapshots.
- **Bounded remedy applied in worktree:** compact nav and button gaps are reduced through `data-[compact=true]:gap-2` and `data-[compact=true]:gap-1`. This is source-only until integrated into the primary runtime; the captured live screenshots remain baseline evidence. A deployed repeat should verify whether label clipping is fully resolved or whether a compact label/scroll treatment is still required.

### W3-09-F03 — Chat read failures masquerade as a new conversation

- **Severity:** important; **confidence:** high; **type:** repeatable live harness defect with a committed bounded repair.
- **User consequence:** when the `/chat` data request fails, the baseline renders `New conversation` plus welcome copy. A student can reasonably believe an existing conversation is empty or has been lost, and receives no retry affordance.
- **Code chain:** the prior `ChatShell.refresh` converted a selected-thread detail rejection to `null`; the URL effect then treated the result like a missing thread, while list/overview failures only produced a toast and left the welcome empty state mounted.
- **Evidence:** forced-500 baseline snapshots above; old-thread healthy reopen proves the route itself is valid.
- **Bounded remedy applied in worktree:** `ChatShell` now lets selected detail failures reject, stores a load error, renders `ProductErrorState`, and retries the same requested thread. Missing-thread redirect behavior remains unchanged. The existing `createApplicationCommandDispatcher` wiring is preserved.

### W3-09-F04 — Chat history close does not restore focus

- **Severity:** important; **confidence:** medium; **type:** live accessibility interaction gap.
- **User consequence:** after opening and closing Runs & chats at 390px, focus lands on `BODY` rather than the Open runs button. Keyboard users lose their place.
- **Code chain:** `ChatShell` history is a plain complementary panel; no unconditional desktop focus trap/aria-modal change was made, in accordance with the assignment boundary.
- **Evidence:** history open/closed snapshots and DOM readback `tag: BODY`.
- **Bounded remedy:** use the existing modal boundary only for the narrow/mobile presentation and add opener capture/return there; keep desktop artifact/chat simultaneously usable. Add a focused keyboard test before integrating.

Positive coverage: the visible primary navigation, labelled More menus, desktop panel composition, artifact/comments/true-empty related-chat state, active-run readback, old-thread route and intentional no-second-chat-panel rule all behaved as designed in the repeat. No universal K-bar or global allocator claim is made.
