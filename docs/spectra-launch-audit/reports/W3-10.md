## Result

The append-before-checkpoint native projection gap is fixed in the assigned worktree. Native room load now compares the durable append head (`nextSequence - 1`) with `lastProjectionSequence` in addition to comparing state-vector hashes. When the replayed Yjs state is current but the artifact projection checkpoint lags, the gateway sends a bounded checkpoint repair. The Convex mutation verifies the active room generation, durable head, prior projection sequence, and live state-vector hash; stale repairs return without overwriting a newer projection, and an already-applied retry is idempotent.

The requested live repeat also ran against the healthy local stack. Two named browser sessions created/opened one unique document, propagated an appended marker, and read the content back after refresh. Both sessions used the saved signed-in student identity, so this is a same-account collaboration result—not a second-user permission or authority result. Browser refresh also exposed transient Convex query/token failures; the content recovered, but the UI was not uniformly transport-healthy.

## Findings grouped by root cause

### W3-10-F01 — State-vector equality did not prove native projection currency

Severity: important before this fix. Confidence: high.

After an ordinary native Yjs update is durably appended, the gateway can replay the new state before the idle projection checkpoint runs. The observed and stored state-vector hashes can already be equal in that window, so the previous load branch skipped recovery while `lastProjectionSequence` remained behind the durable head. Artifact detail, Library metadata, and embed projections could remain stale until another checkpoint-triggering edit.

The bounded fix is at `scripts/collaboration-room-state.mjs:94`, `scripts/collaboration-gateway.mjs:1144-1218`, and `convex/collaborationGatewayStore.ts:1113-1255`. It repairs only when the durable head is ahead, passes the stored room generation and expected head, and reloads the stored document after the mutation. The source tests read back repaired content, duplicate safety, stale-head refusal, and retired-room refusal.

### W3-10-F02 — Repair must not overwrite a newer editor projection

Severity: important. Confidence: high.

The repair request is now a compare-and-set operation over active room ID, `nextSequence`, `lastProjectionSequence`, and live state vector. The mutation returns stale before writing when any expected value no longer matches. Exact duplicate content/vector/sequence is accepted as a duplicate so a retry after a later append does not become a false conflict.

This keeps the repair bounded to the durable head observed by the loader and leaves newer editor content authoritative. The race is source-tested, not live-crash-tested against the primary runtime.

### W3-10-F03 — Selective native restore preserves neighbors only when the target structure is stable

Severity: important for restore trust. Confidence: high.

The existing selective restore path was extended with focused presentation and sheet regressions. A selected sheet cell changes while its neighbor and sheet ID remain current. A presentation theme/root descriptor changes while another slide and object remain current; a changed slide ID fails closed with `NATIVE_PARTIAL_RESTORE_STRUCTURE_CHANGED`.

This is model/source evidence, not a claim that every rich document, whiteboard, or dense spreadsheet browser workflow has been live-verified.

### W3-10-F04 — Live UI transport was intermittently degraded during refresh

Severity: launch evidence blocker for a uniformly healthy live repeat; not classified here as a collaboration data-loss defect. Confidence: high.

The required health endpoints were ready at the final snapshot, but the browser observed a Convex `orgTreeBoard:column` timeout and a collaboration token 500. A’s artifact surface recovered through the in-app retry, and B’s refreshed surface retained the document content while showing `Reconnecting`. The user-visible screenshots and console-derived observations are preserved under the evidence root.

The runtime owner should investigate the slow/timeout-prone metadata/token path before using this run as a clean launch-health result. No restart/reset/re-pair was performed by this task.

### W3-10-F05 — Embed row-before-node drift remains a future lifecycle seam

Severity: future medium. Confidence: high for the code sequence.

`artifactEmbeds.create` inserts the server row before `reference.insert` commits the editor node. The current catch removes the row only when the same in-process command returns an error. A tab/process interruption can leave an active orphan row, and a retry can duplicate it because `create` has no idempotency key. This task intentionally did not broaden embed lifecycle/retention behavior; the exact trace is handed off for the lifecycle task.
