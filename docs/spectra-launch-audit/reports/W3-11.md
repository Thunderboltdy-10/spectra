# W3-11 — Repeat educational artifact workflows

## Result

The W3-11 repeat pass established that quiz, flashcard, planner, document/Sheets live references, whiteboard, agent follow/use, and read-only file opening are reachable in the shared local runtime. ## Findings grouped by root cause

### W3-11-F01 — Floating Live Dock captures pointer events over editor controls

- Severity: important. Confidence: high.
- User consequence: enabled controls can look usable but cannot be clicked normally; this affects at least Quiz submit, Planner checklist/add-step controls, and Whiteboard add/edit controls.
- Repro/code chain: while the target control was visible and enabled, `document.elementFromPoint` resolved to the Live Dock (`.spectra-run-tab-strip` / `.spectra-workbench-live-stack`) at the target coordinates. Normal Playwright clicks timed out; raw DOM activation completed the action.
- Evidence: `quiz-submitted.png`, `planner-scheduled-complete.png`, `whiteboard-smoke.png`, `whiteboard-smoke-edited.png`.
- Affected neighbors: all editor surfaces sharing the bottom live stack, including Quiz, Planner, and Whiteboard.
- Bounded remedy: reserve bottom composer clearance and/or correct stacking/pointer-event ownership across every affected surface. The worktree fix adds the existing `spectra-composer-clearance` class to the Quiz editor body; it needs primary integration and live pointer verification.

### W3-11-F02 — CodeMirror body-edit event path does not commit content

- Severity: important. Confidence: high.
- User consequence: a user can open a Code artifact and type through the visible editor, but the source remains `<main></main>` after the interaction and reload.
- Repro/code chain: Code surface reached; `.cm-content` was contenteditable. Both a direct fill and click/Control+A/type sequence produced no durable text change.
- Evidence: `code-smoke.png`, `code-smoke-keyboard.png`.
- Affected neighbors: Code artifacts and any save/autosave path that depends on the CodeMirror change event.
- Bounded remedy: trace the editor adapter’s `onChange`/transaction listener and persist a minimal source edit; add a reload assertion for source text before touching richer code features.

### W3-11-F03 — Sheets chart insertion does not materialize a chart object

- Severity: important. Confidence: high for the observed baseline; root cause not isolated.
- User consequence: selecting a valid 2×2 data range and invoking Insert chart changes the inspector to Chart, but there is no visible chart object and chart controls remain disabled.
- Repro/code chain: `Stage / ATP` plus `Cellular / 42` was entered, the range was selected, and Insert chart was invoked. DOM inspection found no `.sheets-chart-object`; reload did not produce one.
- Evidence: `sheets-source-chart.png`, `sheets-source-updated.png`.
- Affected neighbors: spreadsheet visualization, document embeds of chart objects, and chart removal/history coverage.
- Bounded remedy: make chart insertion return/create a persisted object ID, render it in the grid, and expose delete/update controls only after object creation. Add create→reload→remove coverage.

### W3-11-F04 — Auth hydration can lag a fresh route after a live embed

- Severity: important. Confidence: medium-high.
- User consequence: a fresh Document route can display the sign-in boundary and an `AUTH_NOT_SIGNED_IN` query error even while service health is green; the user must rehydrate the named session and reload.
- Repro/code chain: after the Sheets live-reference/source-update flow, the fresh Document route loaded sign-in; `state-load` followed by reload restored the same authenticated artifact and the updated value `84`.
- Evidence: `document-embed-reload-84.png` (failed first read), `document-embed-reload-84-auth-restored.png` (successful read), plus health checks above.
- Affected neighbors: any route that immediately runs artifact/embed queries during auth bootstrap.
- Bounded remedy: gate authenticated artifact queries behind session hydration or retry the query when auth becomes ready; add a fresh-route live-embed reload test.

### W3-11-F05 — Agent school-wide publish is role-gated, not proven broken

- Severity: future/coverage gap. Confidence: high for this identity, not a cross-role product verdict.
- User consequence: the student owner can create and use an own draft, but Publish is disabled and there is no Discover/shared agent to install or follow.
- Repro/code chain: account chrome identified `Pablo MD · student`; Foundry Release showed `Release to yourself` disabled and `Publish` disabled; `platformOperator: false` was present in captured state.
- Evidence: `agent-release.png`, `agent-release-state.yml`.
- Affected neighbors: school directory, install, and peer-follow workflows.
- Bounded remedy: repeat with an authorized teacher/operator identity before filing an implementation defect. Preserve the student-role behavior as an explicit permission boundary.

### W3-11-F06 — Calendar drag scheduling and history semantics remain unverified

- Severity: future. Confidence: medium.
- User consequence: planner due-date scheduling and completion persisted, but dragging the task into Calendar did not produce a durable scheduled block in this pass, so calendar scheduling/history parity cannot be claimed.
- Evidence: `planner-calendar-scheduled.png`, `planner-final-complete.png`.
- Affected neighbors: Planner ↔ Calendar integration and any schedule-history expectations.
- Bounded remedy: define the canonical drag target and expected readback first, then repeat with a fresh Calendar reload and verify whether history should preserve or replace prior placements.
