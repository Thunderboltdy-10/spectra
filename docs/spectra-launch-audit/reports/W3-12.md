# W3-12 — Repeat cost, lazy-loading and deletion measurements

## Result

The connected repeats produced three useful results. The primary local runtime served Library, Workspace, Chat, artifact editing, Trash, and permanent deletion while all four health checks remained ready at the final check. Browser navigation reached ready state with seven logical API reads; closed inspector/run surfaces did not add version or asset requests. Deployment-wide Convex windows were still far above the diagnostic idle budgets, and a shared-load one-second timeout occurred during a fixture retry, so these numbers are amplification signals rather than per-user cost or an SLO.

The live deletion contract passed for two own disposable documents. Direct permanent deletion returned HTTP 200 and removed the small artifact fixture. A second fixture with a live reference embed and version-history marker moved to Trash, remained visible as one retained item, required an explicit irreversible confirmation, and left Trash empty after purge. This proves the reachable UI path and small-fixture readback, not complete cross-domain garbage collection.

The source audit found one bounded duplicate artifact read in workspace hydration. The worktree fix reuses the discovery row across authority evaluation and inherited-access evaluation, with a focused Convex test. It is committed as `f4e7f063` but was not deployed or rebuilt into the primary runtime; live measurements are therefore baseline evidence.

The important cost boundary remains authority plus projection, not only HTTP response size. Summary mode omits canonical content and full last-run detail from the returned workspace packet, but `hydrateWorkNode` still authorizes each item, scans direct grants and workspace projections, and hydrates serially. The fix reduces one full artifact fetch for each discovered work node; it does not add pagination, a summary index, or a parallel hydration redesign.

Deletion also has two front doors. Direct deletion calls `tombstoneArtifactEmbeds`, purges source nodes, versions, known imports/assets/builds/links, selected run descendants and memory projections, then deletes the artifact and summary. Trash purge tombstones embeds and removes placements, user state, links, and the artifact, after a collaboration drain; it does not yet share the direct path's complete row-family/storage cleanup. W2-22's cross-domain retention findings remain open.

## Findings grouped by root cause

### W3-12-F01 — Workspace hydration redundantly loaded the artifact for authority

Severity: small. Confidence: high from source inspection; live benefit unverified because the patch is not deployed.

Before the patch, `hydrateWorkNode` first called `ctx.db.get(artifactId)` to determine artifact/agent type, then called `evaluateAccess`, whose `loadResource` fetched the same full artifact again. The inherited-access branch could fetch it a third time for non-owners. On a large or numerous workspace, this inflates Convex reads even when the caller only needs an allowlisted summary.

The committed remedy adds `evaluateAccessForActorWithLoadedResource`, passes the existing row through the common authority evaluator and inherited-access check, and passes the actor rather than only its account ID into hydration. It preserves owner, direct grant, cross-school, deleted-resource, workspace-inheritance, and artifact-exception branches through the same evaluator. The new test checks owner access semantics against a preloaded fixture. The focused test could not run because of missing local dependencies; syntax and diff checks passed.

Affected neighbors: summary/full workspace contracts, access overrides, direct grants, agent detection, and any future summary-index work. The fix does not change authorization outcomes by design, does not eliminate grant/workspace reads, and is not live until integrated and rebuilt.

### W3-12-F02 — Summary response shaping is useful but is not a complete lazy-loading boundary

Severity: important for large workspaces. Confidence: high from source; live response-shape attribution is limited to the primary baseline.

The explicit summary mode prevents the Library/Workspace packet and bounded AI context map from returning canonical artifact content and full last-run detail. The open/closed browser comparison also found no hidden versions/assets request while those panels were closed. However, each discovered work node still runs authority evaluation and serial hydration, and `workspaceContextNodes` remains a collection rather than a cursor. A smaller HTTP response can therefore coexist with high Convex document/index I/O.

Remedy: keep the explicit summary/full contract and the closed-panel guards; measure the patched build with a large-body fixture, then design cursor/summary-index work separately. Do not silently make full `read_workspace` calls summary-only or cap versions/assets without a cursor contract.

### W3-12-F03 — Shared runtime load creates timeouts and masks causal cost

Severity: important reliability signal; not a per-user launch blocker proven by this run. Confidence: high for the observed timeout and usage totals, low for attribution.

The first second-fixture creation attempt failed with Convex request `15e7a76255bc4f1b` and `spectraArtifacts:create` execution timeout at the one-second maximum. During later artifact retries the browser showed reconnecting state and an `orgTreeBoard:column` timeout. Health endpoints remained ready, and the second creation succeeded after the shared runtime quieted. The 30-second windows likewise recorded 164–239 executions and 4.9–12.2 MB DB I/O in only 20–30 seconds, with Bridge payload polling prominent even while the dock was closed.

User consequence: a normal persistence action can surface a generic error or remain reconnecting even though process health is green. The measurement consequence is equally important: deployment-wide windows cannot be converted into a school invoice or attributed to the Library/dock alone. Remedy: obtain a quiet isolated usage window or test deployment, preserve request IDs and function chains, and define retry/idempotency behavior for one-second Convex actions.

### W3-12-F04 — Visible dock guards work, but residual shared traffic is not evidence of a hidden dock subscription

Severity: small observation. Confidence: high for DOM/request state, medium for backend attribution.

The open snapshot showed the Runs & chats panel; the closed snapshot removed it. The closed request/usage evidence still showed `spectraRuns:listRecent`, Bridge claims, replica reads, authorization, and board-column work. Because the account had other live collaboration/run activity, the residual calls cannot be assigned to the unmounted dock. No closed-panel version-history or asset-gallery fetch was observed.

Remedy: retain the existing conditional mounts and visibility guards. If billing attribution is needed, repeat with all other sessions and Bridge jobs quiesced or attach a test correlation ID to the measurement harness.

### W3-12-F05 — Direct delete and Trash purge are reachable, but their cleanup graphs still diverge

Severity: important for retention correctness. Confidence: high from source; live low-fixture deletion proof is high only for the front-door UI and observed fixture disappearance.

The direct route successfully removed the own fixture and returned placement/run counts. Trash purge successfully retained, confirmed, and removed the second fixture, including a live reference embed in the exercised path. The final browser state and forbidden follow-up reads prove that the small fixture is no longer visible through the normal account read path.

The source paths still differ. Direct permanent deletion collects and cleans known versions, runtime builds, import originals, assets, links, selected AI rows, memory projections, and summaries in one broad transaction. Trash purge drains collaboration rows, then removes source nodes, user states, links, the artifact, and summary through `purgeOwnedWorkRecord`; it does not enumerate every direct-delete row family. Neither live fixture contained the full W2-22 graph of replicas, payload references, bridge requests, conflicts, claims, room history, imports in every state, and AI descendants, so no complete lifecycle claim is warranted.

Remedy: make both front doors invoke one capability-checked, resumable deletion coordinator with explicit tombstone/retain/delete decisions, page cursors, idempotency, collaboration/claim handling, and shared-payload reference proof. Keep account-placement removal separate from owner-object deletion.

### W3-12-F06 — Deletion remains transaction-sized for large histories

Severity: future/important at scale. Confidence: high from source; not stress-executed against user data.

The direct path uses multiple `.collect()` calls and performs storage deletion, metering, row deletion, and summary cleanup inside one mutation. The current Trash owner path is page-drained for some families but still sits behind a single user-facing mutation and does not share the full direct graph. Small fixtures passed, but the one-second Convex timeout seen during creation demonstrates why a large deletion should not depend on an unbounded atomic transaction.

Remedy: create a deletion job after capability/protection checks, record phase/cursor/count/deletion generation, terminalize active operations, and expose retry/progress. Define the final artifact-row tombstone/absence contract before implementing broad cleanup.

## Decisions for parent/Pablo

- Integrate the read-coalescing patch after the focused Convex test is runnable; it is narrow, preserves the public full/summary contract, and directly addresses a confirmed duplicate full-row read.
