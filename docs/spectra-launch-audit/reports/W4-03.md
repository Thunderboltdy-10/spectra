## Findings grouped by root cause

### W4-03-F01 — stale or failed chat reads can change the visible conversation

- Severity: important; confidence: high.
- User consequence: a slower prior route load could publish an old detail or a failed refresh could make the current conversation look like a new empty chat.
- Repair: `ChatShell` increments a route generation, checks it before publishing list/detail/artifact state and in polling, and keeps the detail on background refresh failure. The error banner explains that displayed messages are the last loaded copy and offers `Try again`. Confirmed missing threads still use `/chat?new=1`.
- Regression evidence: six passing chat-shell tests, including deferred old/new route completion and preserved-message failure cases.

### W4-03-F02 — fixed dock shell captures underlying controls

- Severity: important; confidence: high from W3 live baseline.
- User consequence: W3 showed normal clicks on visible Quiz, Planner and Whiteboard controls resolving to the dock/stack; DOM activation was needed to complete actions.
- Repair: the fixed stack, row, run strip and Live Dock root are pointer-transparent; visible dock controls, hover panels, command bar, selection and composer opt back in. The shared composer safe-area class is applied to Quiz, Planner and Whiteboard bodies so controls are not placed beneath the band.
- Evidence: source/build contract passed. Normal pointer verification remains pending because protected surfaces could not render in the authenticated preview.

### W4-03-F03 — fixed Library rail leaves unusable narrow board width

- Severity: important; confidence: high from W3 live measurements.
- User consequence: the 248px rail left only 118px at 390px and 48px at 320px for the board.
- Repair: at max-width 767px the rail is collapsed into an existing Sheet boundary with a 320px maximum, explicit title/description, labeled folder navigation and opener focus restoration. Desktop keeps the inline 248px rail and side-by-side layout.
- Evidence: TypeScript/build and organizer/workbench focused tests pass. Narrow live geometry/focus recapture is pending the same auth prerequisite.

### W4-03-F04 — compact nav selector did not match its items

- Severity: small; confidence: high.
- User consequence: the compact gap rule was declared on the item selector but the item buttons lacked the matching `data-compact` attribute.
- Repair: primary and More navigation buttons now expose `data-compact=true` when compact, activating the existing spacing contract without changing the information architecture.

### W4-03-F05 — CodeMirror persistence needs a real authenticated reproduction

- Severity: important baseline boundary; confidence: high for W3 observation, not isolated here.
- User consequence: W3 could type in a CodeMirror surface but the source remained unchanged after reload.
- Inspection: after the dock repair, the existing `yCollab(Y.Text)` path remains transaction-owned by the per-file collaboration model; the editor callback updates only the local projection when shared text is active and does not overwrite the whole project. Native Yjs adapter tests pass.
- Decision: no speculative editor patch. Repeat with a fresh authenticated state, recording actual editor focus, CodeMirror transactions, Y.Text content, provider synchronization, and reload readback before changing the adapter.
