## Repairs completed

- ManageBac sync now rejects a second active sync for the same account with a stable `INTEGRATION_SYNC_BUSY` error. The UI prevents duplicate actions while a sync is queued/running and translates internal stage/status/error codes into readable recovery copy.
- Sync history and provenance remain inspectable while identity is unresolved, while Classes, Tasks, Calendar, Resources, and other personal data remain identity-gated. Conflict actions now say `Keep in Spectra` and `Archive projection`, matching the backend `detach` and `archive_projection` semantics.
- Timetable projection refresh is representation-aware. Current `calendarItems` projections update in place only when the owner, school, source provider, source record, and source lock match. Legacy `artifactId#eventId` projections refresh the artifact and reuse the migrated calendar row before upgrading the projection ID. Source removal marks the valid calendar/artifact representation stale or removed without crossing account boundaries.
- Invitation preview retry is capped at two attempts and only applies to transient failures. Invalid, expired, and school-unavailable invitation errors remain terminal and non-retryable.
- Added `scripts/local/managebac-provider-fixture.mjs`, a deterministic loopback ManageBac-shaped HTTP fixture with revision 1/2 responses and an in-memory request log. The route allows only the exact configured fixture origin, only in test mode, and only over loopback HTTP; normal production HTTPS/public-host/SSRF checks remain unchanged.
- Added a real-route test that uses the local HTTP fixture, the actual Next route, authenticated identity/account/integration setup, and a local Convex harness. It verifies identity resolution, class/task/timetable/resource polling, revision-2 task persistence, outbound route coverage, and the real sync boundary. No provider token or payload is written to the report.
