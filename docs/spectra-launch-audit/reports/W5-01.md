# W5-01 — lossless bounded thread reads and complete result UI

## Result

Implemented the W5-01 thread-read/result-consumer slice on the private remediation base. Initial thread reads are bounded, older messages/list rows/backfill rows are traversed with scoped opaque Convex cursors, trace families are loaded on demand, and the chat/dock conversation surface now consumes saved operations/cards/artifacts plus a live active-execution subscription.

This is a private candidate, not an integrated or live-runtime launch claim.

## Scope and current architecture

The source path is:

| Surface | Path | Change |
| --- | --- | --- |
| Convex history/list/backfill/traces | `convex/spectraThreads.ts` | Real `.paginate()` traversal, versioned/scoped cursors, authoritative context projections, on-demand trace-family pages |
| Required index | `convex/schema.ts` | Additive `by_account_school_status_updated` index for owner/school/status list traversal |
| Thread metadata maintenance | `convex/spectraRuns.ts`, `convex/spectraShared.ts`, `convex/spectraArtifacts.ts`, `convex/spectraWorkspaces.ts`, `convex/orgTreeShared.ts` | Set read metadata/version on actual create, message, placement, title, artifact, workspace and retained-agent mutation paths |
| HTTP/data clients | `src/app/api/spectra/route.ts`, `src/features/spectra/data/api.ts` | Forward opaque list/message/trace cursors and selected trace family |
| Chat and dock consumer | `src/features/spectra/components/conversation-surface.tsx` | Live `getActiveExecution` subscription, explicit saved-run disclosure, result/operation rendering, independent family fan-out and “load more” continuation |

The Convex runtime permits one paginated query per function execution. `getRunTrace` therefore paginates exactly one selected family (`operations`, `cards`, or `events`) per request; the UI fans out three bounded requests when a saved run is exposed and then requests only families with remaining cursors. This avoids fixed `take(limit+257)` horizons and keeps continuation tokens family/order/run scoped.

## Findings grouped by root cause

### W5-01-F01 — fixed-window reads dropped retained history

- Consequence: long conversations, lists and migrations stopped at a fixed read horizon; cursors could omit rows and document-ID string ordering was not a valid index-order substitute.
- Severity: launch blocker for lossless history; confidence high from the parent counterexample and new private depth tests.
- Remedy: use Convex pagination directly on the indexed query, with versioned cursors scoped to owner/query/order/thread/run/family. Numeric legacy message cursors and string legacy event cursors fail with reloadable errors instead of silently guessing.

### W5-01-F02 — saved results were disconnected from the conversation

- Consequence: `get` returned `traces: []`, so existing saved operation/card/artifact UI could not recover historical results; active execution changes were not independently observed.
- Severity: important; confidence high from source inspection and the component behavior test.
- Remedy: retain a small initial thread/message projection, add on-demand family paging, render all persisted result cards/operations/artifacts, and subscribe directly to `getActiveExecution` from the shared conversation surface used by `/chat` and the dock.

### W5-01-F03 — list context hydration could duplicate full artifact work

- Consequence: list response construction performed a second artifact summary path after authority checks and could spend work outside the bounded thread page.
- Severity: important; confidence high from source inspection.
- Remedy: authoritative capability checks remain per referenced context, but the list projection uses the already-loaded artifact title and omits inaccessible/deleted contexts. No full artifact content is loaded for the list.

## Decisions for parent/Pablo

- Integrate the product commit as one candidate with the additive index and tests; do not split the cursor/UI contract because the old `traces: []` consumer and backend pagination failure are coupled.
- Preserve the one-family-per-query trace contract. It is required by Convex’s single-`.paginate()` execution limit and keeps each continuation independently bounded.
- Do not interpret the passing fixtures or response sizes as hosted database read-byte, billing, production performance, or live authority proof.
