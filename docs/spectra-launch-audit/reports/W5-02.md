## Implemented contract

- Replaced ambient `fetch` source retrieval with a direct Node `http`/`https` transport. Each request receives a validated address through the supported `lookup` hook, while the logical hostname remains `hostname`, `Host`, and HTTPS SNI/certificate identity. `agent: false`, explicit `Connection: close`, and no proxy agent prevent implicit proxy or stale pooled-socket paths. Address retries are limited to three already-validated candidates.
- Rejected credentials and unsupported schemes; normalized IPv4, IPv6, and mapped IPv4 forms; rejected private/special-use DNS answers; revalidated every redirect before connecting; and closed redirect/failure/final response resources.
- Added one deadline/cancellation signal across URL validation, DNS, connection, body streaming, decompression, and PDF extraction. Response bytes, decompressed bytes, normalized text, redirect count, PDF pages, and evidence are bounded. PDF page counting includes empty pages, so empty pages cannot bypass the page cap.
- Added explicit normalized content identity and provenance (`requestedUrl`, final URL, content hash). HTML and PDF text use the same whitespace representation. Evidence spans are created from exact normalized substrings, with actual bounded offsets and hashes; partial extraction becomes unverified. Failed/snippet-only fallback records stay unverified, and citation verification now checks evidence hash/range integrity.
- Added bounded account-independent `SourceCache` storage for complete public unauthenticated content only. Keys include canonical request URL, extraction version, and content negotiation; cache freshness uses explicit `Cache-Control`/configured freshness, stale entries send validators, 304 preserves identity, and changed content atomically replaces the cached identity. No cancellation/failure is cached as verified content, and no in-flight promise or request signal is shared.
- Preserved three workers and added round-robin evidence allocation with per-source and total caps so one source cannot consume the entire evidence budget.

## Evidence category and limits

All new transport/lookup/TLS assertions are deterministic injected-fixture or mocked evidence. They do not open a real socket, contact a private service, or claim a live TLS handshake. The implementation uses Node's documented `http.request`/`https.request` `lookup`, `signal`, and `servername` capabilities and `dns.promises.lookup`: [HTTP](https://nodejs.org/api/http.html#httprequestoptions-callback), [HTTPS](https://nodejs.org/api/https.html), [DNS](https://nodejs.org/api/dns.html#dnspromiseslookuphostname-options). Native DNS lookup itself has no AbortSignal parameter; the bounded race stops the source operation and prevents transport from starting after cancellation/deadline, while the underlying OS resolver may finish independently.
