## Implemented

- Replaced reachable `unzipSync` intake with `shared/parser-limits.ts` and `@ariadng/office/zip` central-directory validation plus bounded deflate streaming. The helper caps input, entry count, declared/observed expansion, per-entry output, work, compression ratio, encrypted/unsupported entries, CRC/size mismatches, traversal, and canonical-name collisions.
- The helper stops a stream when actual output crosses its limit and re-emits only the bounded, CRC-checked bytes. Downstream Office readers therefore receive a sanitized package instead of getting a second unbounded chance to inflate the original stream.
- Hardened AI attachment intake in the run loop and attachment preprocessor with pre-decode Base64 size checks; DOCX, XLSX, PPTX, PDF and package-media extraction use the bounded results.
- Hardened native DOCX/XLSX/PPTX lenses and their media routes. Native carries preserve the original payload for semantic no-op byte identity while storing a separate validated package for parsing/mutation.
- Hardened ordinary DOCX/PDF import, Library DOCX/ODT/PDF import, presentation/ODS/quiz/flashcard/code ZIP imports, Sheets import, and the Spectra package reader. Updated the package harness for the async bounded reader.
- Upgraded `pdfjs-dist` to `6.2.108` and overrode transitive `@xmldom/xmldom` to `0.9.12`; refreshed the lockfile. The PDF.js cleanup API was updated at affected call sites. ExcelJS was not changed because its reachable nested `uuid` advisory requires the incompatible `exceljs@3.4.0` downgrade path.
