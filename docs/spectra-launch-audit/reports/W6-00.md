# W6-00 — scoped W5 integration into primary

## Result

Integrated the safe W5-01 through W5-04 product slices into primary `main`. The integrated product keeps the existing auth, W4, intake, deletion and Bridge trust boundaries, while adding bounded thread/result reads, pinned source evidence transport, bounded Office/PDF intake, and wake-aware Bridge polling. The unsafe combined candidate `e492458466cbb38788e5af2e20f007631b71b753` and D01/D02 wholesale changes were not merged.

## Scope and current architecture

| Area | Integrated entry points | Bounded behavior |
| --- | --- | --- |
| Thread history/results | `convex/spectraThreads.ts`, `src/features/spectra/components/conversation-surface.tsx` | Initial message page, opaque older cursors, on-demand operation/card/event families, compact active execution projection |
| Thread metadata | `convex/schema.ts`, `convex/spectraRuns.ts`, existing W5 mutation paths | Additive read metadata and message ordinal fields; legacy message counts remain unknown rather than triggering a backfill scan |
| Public sources | `src/features/spectra/sources/research/full-source.ts`, `source-record.ts` | Validated address set, pinned DNS/TLS identity, bounded redirects/body/decompression, immutable content identity and honest unverified fallback |
| Office/PDF intake | `shared/parser-limits.ts`, intake/import/lens call sites | Archive entry/output/ratio limits, bounded PDF bytes/pages/text, cleanup on the affected readers |
| Bridge | `bridge/bridge-app/src/polling.rs`, `bridge/bridge-app/src/main.rs` | Active/idle/failure schedules, 15-second sleep cap, coalesced local wake and no duplicate journal side effects |

The list context projection reads at most 48 unique workspace rows and 48 unique artifact rows per page, then evaluates authority against the loaded metadata before returning titles. Artifact content remains co-located in the artifact row, so this is a bounded row fan-out and response projection, not a claim of byte-level storage savings. Active execution responses expose only `_id`, status, phase and `updatedAt`, although Convex still reads the underlying run row.

## Findings grouped by root cause

### W6-00-F01 — unsafe candidate read amplification was not suitable for integration

- Consequence: the combined candidate still relied on full-row capability helpers, broad message collection for legacy counts, and large active-run projections in paths intended to be cheap.
- Severity: launch blocker for the bounded-read slice; confidence high from the W5/W6 source audit.
- Remedy: integrated only the four scoped W5 product commits, then added compact projections, bounded unique context hydration, monotonic request guards and scan-free legacy backfill in `3f4b9886`.

### W6-00-F02 — cross-switch async responses could overwrite the selected thread

- Consequence: returning A→B→A could let an old trace response match a reset per-key request number; older history and saved results could then appear for the wrong view.
- Severity: important; confidence high from the deterministic component regression.
- Remedy: use a component-lifetime trace request sequence and preserve monotonic older-history request IDs. The new A→B→A test passes.

### W6-00-F03 — authenticated runtime parity remains unverified

- Consequence: the public browser smoke check cannot prove signed-in thread history, saved results, source evidence, rich import initiation or Bridge pairing/readback.
- Severity: important follow-up, not an observed regression; confidence high.
- Boundary: no credentials, account mutation, file sync, provider run or production deploy was attempted.
