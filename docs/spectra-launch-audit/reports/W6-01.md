# W6-01 — trusted uploads and causal import commits

## Result

Implemented the W6-01 intake boundary on the private W6 candidate base. Asset and import-original uploads now use server-issued, purpose-separated HMAC attestations bound to the authenticated actor, target, receipt, storage object, byte count, digest, MIME type, expiry and replay nonce. Storage is inspected before promotion; mismatches quarantine the attempt, foreign objects are never deleted without exact trusted proof, and terminal retries return the existing result or clean up only a verified duplicate.

Parsed imports remain distinct from canonical saves. Import begin captures the artifact version/state-vector base plus root collaboration-room identity, append head and projection head. The canonical `changeGroups` commit fences all of those facts before creating a version and returns a durable causal receipt.

This is private candidate evidence, not a shared-runtime or launch claim.

## Findings grouped by root cause

### W6-01-F01 — storage provenance was not previously a trusted commit fact

- Consequence: a public finalizer could be presented with a storage ID without a signed server-side binding to the authenticated actor, upload receipt, declared object facts and the exact storage object.
- Remedy: route-side generated-URL uploads are hashed/count-tracked as they stream, then signed with an existing bridge secret under a new purpose-separated key. The Convex action verifies the signature, fresh actor identity, artifact capability, receipt/object binding, storage bytes/digest/MIME and content signature before calling the internal promotion mutation. Nonces make promotion once-only while exact terminal replay stays safe.

### W6-01-F02 — large uploads were coupled to byte-array action transport

- Consequence: the old direct `v.bytes()` action path imposed an artificial small transport ceiling even though product ceilings are 100 MB for assets and 80 MB for import originals.
- Remedy: public asset/original routes use generated storage URLs and streamed bodies, retain those product ceilings, and attest the observed object. Existing direct actions remain compatibility paths; route traffic no longer depends on their byte-array transport.

### W6-01-F03 — parsed import status did not prove the causal save base

- Consequence: parsed content could be treated as imported before a canonical version existed, and a later save could overwrite newer append/projection activity.
- Remedy: `complete(imported)` records `awaiting_commit`; `commitImport` checks target version/state-vector facts and root room ID/append/projection heads in the same mutation before version creation. It records `operationId` and returns `{ importJobId, artifactId, versionId, commitReceipt }` plus a typed receipt. Exact version retries are idempotent.

## Direct neighboring risks and limits

- W6-02 owns deletion/retention and embed insertion. This change only quarantines untrusted intake candidates and does not claim storage garbage collection.
- Rich imported content still carries the existing authenticated content URL marker for current UI compatibility, alongside its durable `assetId`. W6-03/native writers must consume `assetId` through `resolveArtifactAssetBytes` and never package the authenticated URL.
- The Convex generated API declaration was updated consistently for the new action module, but hosted codegen was unavailable because this worktree has no `CONVEX_DEPLOYMENT`; no runtime schema/action deployment was attempted.
- Local Convex tests use the disposable `convex-test` storage adapter and the route test mocks the storage POST, so these results do not establish hosted storage metadata behavior, browser transport limits, billing/read cost, or production auth/session propagation.

## Integrated acceptance steps

1. With an ordinary student account, upload an asset above the old byte-array limit and an import original near their product ceilings. Confirm route streaming, actual byte/hash attestation, active/uploaded promotion and an exact retry response with no duplicate version/object.
2. Submit a foreign storage ID, altered digest/size/MIME, expired proof, and a different actor. Confirm rejection, honest quarantine for the active attempt, no deletion of the foreign object, and no capability bypass; repeat for representative audio/video/font files.
3. Begin an import, parse it to `awaiting_commit`, and save once with unchanged version/vector/room heads. Confirm the canonical version and causal receipt; repeat the exact save and confirm the same terminal result. Advance an append or projection head first and confirm `ARTIFACT_IMPORT_CAUSAL_BASE_STALE` without a new version.
4. In the W6-03 document writer path, pass the persisted `assetId` through the resolver and verify returned bytes/digest before package insertion; confirm the resulting DOCX/XLSX/PPTX contains bytes, not an authenticated application URL.
