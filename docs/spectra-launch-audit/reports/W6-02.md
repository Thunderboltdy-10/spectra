# W6-02 — Lifecycle and durable embed audit

## Outcome

Implemented the W6-02 cleanup slice in product commits `3ad39842` (`fix: make artifact deletion lifecycle durable`) and `9bdb332` (`fix: verify run attachment retention before release`). The deletion coordinator now uses versioned, generation-bound cursors with one paginated family per worker invocation, explicit child cursors for nested collections, stale-schedule protection, bounded retries, and idempotent cleanup/release receipts.

The slice also makes payload and snapshot release reference-aware, verifies storage metadata before deletion, retains ambiguous intake rows for reconciliation, preserves mixed AI runs, and wires canonical embed confirmation to committed artifact versions. Provisional editor embeds expire unless a canonical writer confirms the exact embed/operation/region identity; UI callers no longer forge insertion receipts.

## Changed surfaces

- `convex/spectraArtifactDeletion.ts`: resumable lifecycle coordinator across embeds, placements, versions, intake, runtime builds, comments, memory, links, replicas, sync, Bridge, collaboration, and AI runs; run attachments are released only after exact storage-size verification.
- `convex/payloadLifecycle.ts`, `convex/artifactSnapshots.ts`, and `convex/artifactIntakeLifecycle.ts`: shared-reference release, snapshot reconciliation, storage verification, and retention evidence.
- `convex/artifactEmbeds.ts`, `convex/changeGroups.ts`, and the document/whiteboard embed callers: canonical version receipts, provisional expiry, and removal of fabricated confirmation callbacks.
- `convex/orgTreeShared.ts`: bounded embed tombstoning and deletion-generation alignment for Trash purge scheduling.
- `convex/schema.ts`: provisional placement expiry metadata.

## Known limits

- No deployed Convex smoke test was run because this worktree has no `CONVEX_DEPLOYMENT`; local codegen/runtime validation is therefore deferred to the integration environment.
- Storage with missing or mismatched metadata is intentionally retained with a reconciliation reason rather than deleted speculatively.
- Retention evidence walks the durable reference sets and can be work proportional to the number of pins/versions/builds; this favors correctness over silent release.
