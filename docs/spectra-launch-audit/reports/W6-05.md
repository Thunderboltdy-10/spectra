# W6-05 — Rich presentation editing and native PowerPoint output

## Result

W6-05 adds a single PPTX projection path for ordinary import/export and retained native edits. Presentation text now carries paragraphs and runs, including native family names, point sizes, bold/italic/underline/strike, colour, alignment, levels and bullets. The native writer emits real editable PowerPoint text, table graphic frames/cells, image metadata/crops, notes, basic shapes, and native chart parts with embedded workbook data. Slide insertion uses the deck's existing layout; duplication, deletion, reordering, object deletion/grouping/visibility/order, geometry, alt text, theme fonts, table cells, charts and speaker notes are represented as typed PPTX operations.

The native path remains preservation-first. It edits the affected slide, chart, table, theme, notes or media XML parts through `@ariadng/office`; transitions, timing trees, masters, layouts, unknown drawing children, and unrelated package relationships remain in the retained package and are checked by the existing preservation guard at the route boundary.

## Published S6-OFFICE-BRIDGE contracts

| Contract | W6-05 boundary |
| --- | --- |
| Writer | `buildPresentationPptx(content, assets)` creates native `p:sp` text/shape nodes, `p:graphicFrame` tables, and PptxGenJS chart parts plus their slide relationships and embedded workbook. `pptxLens.materialize()` computes typed operations from the same projection and `pptxLens.mutate()` applies them to the retained package. |
| Target | Slide IDs are `pptx:slide:/ppt/slides/slideN.xml`; object IDs are `${slideId}:shape:${p:cNvPr/@id}`. Shape edits target the slide part and native shape ID. Tables target `a:tr/a:tc` row/column; charts resolve the slide `r:id` to `ppt/charts/chartN.xml`; theme fonts resolve the presentation theme relationship; notes resolve the slide notes relationship. |
| Chart | Supported types are `bar`, `column`, `line`, `pie`, and `area`. The chart part owns title, category cache, series name/category/value caches, legend, axis titles, and the supported embedded workbook. Spectra source linkage is an extension under namespace `urn:spectra:office-bridge`, URI `{7C2F2D16-5F5B-4D07-9EA9-SPECTRA-BRIDGE}`, with `artifactId`, `chartId`, `revision`, `kind`, and `live` attributes. |
| Receipt | The native bridge should wrap the existing materialization response in a durable receipt: `{ kind: "pptx-native-write", operationId, artifactId, basePayloadHash, resultPayloadHash, baseRevision, resultRevision, targets: [{ slideId, shapeId?, partNames, regionIds }], semantic: { title?, text?, chart?, table?, notes? }, preservedPartNames, state }`. `state` is `unchanged`, `cloud_saved`, `pending`, `applied`, or `conflicted`. The current route already returns `state`, `hash`, `requestId` and status; S6-OFFICE-BRIDGE owns attribution/verification and should add the base/result semantic envelope without moving conversion logic into the bridge. |

The receipt is deliberately separate from the canonical Yjs save acknowledgement. A native write is only complete after the target-side package hash and semantic values are read back; an equal ZIP hash is an `unchanged` result, not proof that a requested semantic change was applied.

## UI readback steps for parent integration

Use a unique school/research deck in the existing Presentation Studio after the parent checkout is integrated:

1. Import a PPTX containing a title/body with mixed fonts, a 4:3 or custom layout, one image with an existing crop, a formatted table, a native chart, speaker notes, a transition/timing tree, and at least one unsupported/native-only drawing part. Save the canonical projection and reopen it.
2. Through normal controls, edit title/body text, font family/size, bold/italic/list/alignment, shape fill/stroke/corner/opacity, image crop focus, table cell text/fill, chart title/series values/legend/axis title, notes, object visibility/order, grouping, and slide title/duplicate/delete/reorder. Confirm narrow-width workbar controls remain usable and that unsupported capabilities explain the affected region locally.
3. Save, wait for the native materialization acknowledgement, then inspect the downloaded/retained package: slide order and `p:cNvPr` targets, rich `a:rPr` runs, `a:tbl` cells, `a:srcRect`, chart relationships/parts/caches/embedded workbook, notes XML, and theme font slots. Reopen the file in Presentation Studio and compare every edited semantic value.
4. Change the linked Sheets source revision and refresh the chart after an unrelated collaborator edit. Confirm the source artifact/chart identity, revision and live flag remain attached, the chart cache/workbook values update, and the unrelated edit does not enter the chart target.
5. Run a second edit cycle on the reopened deck. Compare untouched transition/timing, master/layout, media, unknown drawing and unrelated relationship members before/after; then perform one keyboard undo/redo cycle and confirm the canonical projection and native receipt remain causally aligned.

## Direct neighboring risks and limitations

- This pass does not provide a native Office/macOS rendering run. The parent should treat Office GUI readback as a required acceptance step, especially for chart-type changes, group geometry, theme inheritance and layout placeholders.
- Hyperlink fields are carried in the rich-run schema but new hyperlink relationships are not authored by the PPTX writer yet; preserve-only hyperlink behavior should remain explicit until S6-OFFICE-BRIDGE adds it.
- New image replacement/masking, shadows, object locking, advanced animation authoring, SmartArt/equations, and new non-text native shapes remain bounded/strict-native cases. Existing unsupported package content is preserved rather than rasterized or flattened.
- The current chart writer updates existing series caches and supported embedded workbook cells. Series-count changes and complex chart-specific formatting need the parent Office bridge acceptance pass.
- Duplicate-slide native copy preserves the source slide's relationship graph and notes through raw package copy; chart relationship isolation and any chart-specific Office fixup should be checked before treating duplicate-and-edit as fully equivalent to PowerPoint's own copy command.
- The existing shared asset upload/finalization issue from W3-04 was not changed. Image crop/readback is implemented at the lens boundary, but a real uploaded image path still needs the shared asset repair and browser readback.
