## Delivered behavior

### Browser-first setup and trust

The existing Files & devices settings surface remains the normal setup path for
health, discovery, pairing, folder selection, retry, and removal. It now adds a
compact trust presentation with three explicit choices:

| Browser choice | Canonical policy | Meaning |
| --- | --- | --- |
| Managed copy | `spectra` | Start isolated; do not write back to the original file |
| Native write & sync | `both` | Opt in to approved local writes and two-way sync |
| Advanced controls | unchanged custom policy | Keep exact direction, discovery, structure, cloud-content, filters, timing, and protected-original fields visible |

The browser shows local and cloud previews for the selected choice. Native write
requires an explicit second confirmation. Changing the account preset does not
move or silently rewrite existing folders; existing items remain a separate
review/transition concern. The safe managed-copy preset is the initial default
when no effective policy has loaded, and trust controls remain disabled until
the effective account policy is available.

Setup, retry, and trust changes use typed `SpectraCommands` and the existing
application dispatcher/bus. The registered Bridge setup/trust commands are
human-only (`aiAuthority: prohibited`) and cannot be performed by AI. Invalid
`retry-folder` commands are rejected unless they include a grant id.

### Quiet native shell and diagnostics

- The Tauri main window is created hidden and skipped from the taskbar; the
  service continues to run from the tray/loopback process.
- Windows scheduled-task repair launches the GUI executable directly with
  `--autostart`. The PowerShell repair child uses `-WindowStyle Hidden` and
  `CREATE_NO_WINDOW`, and the old Run-key value is removed after registration.
- The launcher records bounded runtime errors in the existing journal and makes
  them available through the Bridge log action. Production `eprintln!`/console
  writes were removed from the app launcher path.
- Startup logs use platform-specific per-user locations: `%APPDATA%` on
  Windows, `~/Library/Application Support` on macOS, and
  `~/.local/share` on other Unix systems.

### Packaging and runbook

The manual packaging matrix explicitly covers Windows x64, Apple Silicon via
`macos-14`, and Intel via `macos-15-intel`. The workflow remains manual and
requires explicit hosted Convex/origin inputs. The runbook now labels friend
artifacts as unsigned and documents the expected macOS first-launch Gatekeeper
step. The current Intel label should be checked against GitHub's runner catalog
before a future run: [GitHub-hosted runner labels](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job).

## Friend-Mac acceptance sequence

Run this on a real Apple Silicon and Intel Mac with disposable fixtures and the
authoritative hosted URL/origin. Do not use localhost values for a release
artifact.

1. From `bridge/bridge-app`, set `SPECTRA_CONVEX_URL` and
   `SPECTRA_ORIGINS`, install the locked Tauri CLI, generate icons, and run
   `cargo tauri build --bundles app,dmg --config tauri.friend-test.conf.json`.
2. Launch the unsigned `.app`; check `http://127.0.0.1:47615/v1/health`, the
   per-user startup log, the absence of a terminal/console window, and the
   LaunchAgent/login-start path.
3. From hosted Spectra Settings → Files & devices, pair the Mac, select a
   disposable folder, approve the permission prompt, and verify `Ready` with
   the expected file count. Confirm the browser can recover truthful
   not-running, outdated, offline, and pairing-failure states.
4. Verify Managed copy first. Then explicitly choose Native write & sync and
   confirm the local/cloud preview; test disposable DOCX/XLSX/PPTX save/readback,
   offline/reconnect, conflicts, retries, browser reload, and session resume.
5. Exercise folder remove/re-add, native-window close/hide, tray log opening,
   quit/restart, login launch, uninstall cleanup, filesystem permission prompts,
   keychain persistence, and Gatekeeper behavior. Treat an unsigned artifact as
   a friend test only, never as a public launch result.

## Neighboring risks and handoff boundaries

- The product commit deliberately does not implement the deep native writer or
  reconcile algorithm. Safe, verified DOCX/XLSX/PPTX native writes remain the
  S6-OFFICE-BRIDGE boundary.
- Account-level trust changes do not migrate existing folder/item policies.
  The UI says this explicitly; item-level transition and conflict review still
  need the owning Bridge/native-write work.
- No actual Mac runtime, Gatekeeper, launch-at-login, keychain, permission,
  APFS identity, or Office readback claim is made from this checkout.
- The workflow covers the requested platforms but was not executed here; a
  future release run must re-check runner labels, hosted configuration, signing,
  notarization, updater metadata, and artifact retention before any public
  candidate decision.
