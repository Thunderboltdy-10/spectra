## Implemented behavior

- Added a single surviving-placement ownership predicate. Source deletion records `sourceUnavailableAt`; only `removedAt` ends placement ownership. Actual container deletion marks `removed` and releases a pinned version only after the last surviving placement is gone.
- Replaced synchronous `spectraArtifacts.permanentlyDelete` cleanup with the durable deletion coordinator. The worker now has an explicit final artifact phase, keeps deleted artifacts as anchors while pinned content or unknown storage candidates remain, and starts a bounded new generation after last-pin release.
- Added dispatch/attempt/recovery fencing. A dispatcher claims one page attempt, schedules processing and timeout recovery separately, and uses generation/phase/cursor/attempt checks. Page failures are allowed to roll back the whole Convex mutation; retry accounting is written by the separate recovery mutation.
- Made snapshot release reconcile exact surviving version references and transition shared objects hot/cold correctly. Intake, runtime-build, payload, and AI-attachment storage release requires trusted size plus digest (and MIME where available); unknown legacy bindings remain attached with `legacy-reconciliation-required` instead of deleting a same-sized foreign object. Metering uses stable idempotency keys.
- Preserved pinned source content in embed projections after source tombstoning, with `sourceUnavailable: true`. Canonical confirmation still requires exact operation/region identity, removed provisional rows cannot be confirmed, and expiry is state/operation fenced. Restore validates pinned version content and restores placement ownership consistently.

## Integrated acceptance sequence

1. Delete an image-bearing source through `spectraArtifacts.permanentlyDelete`; verify the job is queued, source embeds have `sourceUnavailable` semantics, actual container placements alone receive `removedAt`, and the pinned version/image bytes remain.
2. Remove one pin and then the last pin; verify the second deletion generation reconciles the snapshot, intake row, storage object, receipt, and meter exactly once.
3. Inject a failure after the first write of a 40-row request page; verify all page writes and cursor changes roll back, then verify duplicate dispatch is fenced and all 65 requests/links drain across pages.
4. Create a provisional document embed, commit the matching operation/region into a canonical version, confirm and reload it, then run both an early expiry and an expired provisional expiry.

## Remaining material limits

- Unknown legacy storage bindings are intentionally preserved and marked for reconciliation; this change does not invent provenance or silently repair them. The deleted artifact remains the bounded reconciliation anchor.
- Verification is `convex-test` plus TypeScript/ESLint in the private worktree. V7’s later real local-Convex compact sequence remains the native-runtime verification step; no local deploy or provider was used in this wave.
