## Scope completed

This slice connects durable uploaded PNG/JPEG assets to actual retained DOCX materialization and adds native image, section, and header/footer operations with semantic readback. Asset bytes are resolved server-side through the authenticated artifact-asset path, checked against the declared media type and stored digest, and embedded into the package; cookie-bound or data-URL package media is not used.

- Authored images can be uploaded, inserted, replaced, resized, cropped, and given alt text. Retained DrawingML images remain editable, including beside changed mixed text; shared media parts are not destructively removed.
- Basic section size, orientation, margins, columns, and section-specific header/footer text are native operations. Shared header/footer parts are cloned before section-specific edits so another section is isolated.
- The DOCX route now resolves assets, materializes the native package, reopens it, and rejects a semantic readback mismatch covering text, formatting, images, page setup, or header/footer state.
- Human editor image upload/export uses durable asset identities and truthful unavailable/revoked feedback. Capability IR and command bindings expose the implemented native operations while retaining explicit refusals for unsupported wrapping/removal and advanced Word-only behavior.
- Rich paragraphs and table cells preserve editable text/equations/images; native locators are excluded from semantic digests but retained for the writer.
