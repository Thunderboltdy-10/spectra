Date: 2026-09-12

## Delivered

PowerPoint native editing now owns the full mutable dependency graph of a duplicated slide. Chart parts and their embedded workbooks are cloned with deterministic names and relationship remapping; layouts, masters, themes, media, external links, and other safe shared dependencies remain shared. Removing a slide releases only unreferenced owned descendants, including chart/workbook pairs, while shared targets stay intact.

Native hyperlink support now covers external `http(s)`/`mailto` URLs and internal slide targets for rich DrawingML runs and supported shape/picture objects. The model, projection schema, inspector, command bindings, import path, writer, retained native path, and materialization path all carry the link. Relationship cleanup removes stale hyperlink and internal-slide relationships without rewriting neighboring run formatting.

Sheets-linked charts now use one shared resolver. It reads only the explicitly bound, authorized Sheets artifact at its committed `currentVersionId`, projects categories plus all numeric series, persists the revision when refreshed/materialized, and exports the resolved values as an editable native chart. Pinning stores the complete series/category snapshot. If a live source is unavailable, the canvas, inspector, export, and native materialization preserve and report the last saved chart content instead of inventing fallback values. The server route fetches only the distinct source artifact IDs referenced by the deck.

The normal PowerPoint materialization route continues to open the retained payload, apply native operations, independently reopen/read back the result, and run preservation checks before queueing. The exporter and reopen path retain native text, tables, charts, media, layouts/masters, notes, dimensions, theme fonts, transitions, animations, and unknown untouched parts through the existing preservation seam.
