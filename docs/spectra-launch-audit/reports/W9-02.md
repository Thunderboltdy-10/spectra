## Scope and implementation

| Area | Change | Authority boundary |
| --- | --- | --- |
| Calendar discovery | Added compact calendar item rows plus indexed UTC-day overlap buckets. `calendar:overview` uses one bounded indexed range page, bounded secondary reads, opaque continuations, exact item identity/title lookup, and a bounded canonical `get` only for an exact item still missing from backfill. | Existing `getAuthenticatedActor` account/school ownership is unchanged. No student/operator grant was added. |
| Planner/timetable metadata | Added compact per-task planner rows and compact migration rows. Planner task identity, title, notes/personal intent (capped), due time, completion, scheduled state, source record and plan revision are maintained from artifact, calendar-item, external-projection and migration writers. | Canonical planner/timetable bodies are read only by their existing writer/repair paths, never by ordinary Calendar mount/read. |
| Calendar writers | The `calendarItems` trigger maintains item/bucket rows for source, human, AI and migration writes. Move, resize, complete, archive/delete and restore paths therefore update the same model; removed item tombstones retain exact identity while their range buckets are deleted. | Existing source-lock and ownership checks remain in the canonical mutations. |
| Repair/migration | Added cursor-based `backfillItemReadModels` (max 100 items/page) and `backfillArtifactReadModels` (max 50 artifacts/page). `ensureLegacyMigration` now processes at most 100 embedded events per invocation and persists `eventOffset`; it is resumable and does not collect the full timetable set. | No reset, global in-query migration, provider change or storage change. |
| Run projections | `orgNodeMutation.ts` compares old/new projected observable run facts with `updatedAt` removed. Heartbeat/lease-only changes do not fetch or rewrite tabs/cards; lifecycle, approval, clarification and outcome fields remain observable. | Existing run projection functions and policy/authority paths are reused. |
| Read-tool adapter | `read_calendar` accepts exact target IDs/titles, bounded cursors and a capped limit; the Calendar route forwards the same exact-target parameters. | The adapter calls the existing `calendar:overview` query and does not create an AI-only authority path. |

## Local instrumented evidence

Evidence is from `convex/calendar-bounded.test.ts` using `convex-test`, not the shared runtime or a hosted deployment. The fixture contains 80 off-range history rows, an exact named item outside the visible week, overlap/all-day/unknown-time cases, one planner body and one calendar note body with 20,000-character payloads. `calendar:overview` returns only the bounded read model.

| Scenario | Compact queries | Indexed range rows | Canonical queries/gets | Serialized response |
| --- | ---: | ---: | ---: | ---: |
| 80 off-range rows, exact target/title lookup | 14 | 6 | 0 / 0 | 4,543 bytes |
| 160 additional off-range rows (same visible range and target) | 14 | 6 | 0 / 0 | 4,543 bytes |

The first bounded item repair performed 177 compact writes; adding the 160-record off-range corpus performed 160 more compact writes. The extra write in the first case is the second day bucket for the cross-midnight overlap fixture. Large canonical body markers do not cross the read boundary; compact notes are capped at 1,200 characters. Exact-target fallback is covered separately and is limited to one owner-checked canonical `get`.

Controls in the same focused test file show schedule → move → resize → complete keeps the compact work-block row current, personal removal leaves zero range buckets, a 105-event legacy timetable completes as 100 + 5 events across two calls with `eventOffset=105`, and heartbeat-only changes do not rewrite intentionally stale tab/card dependent rows. The existing source-isolation and content-checkpoint controls also pass below.

These are engineering measurements of local database calls and serialized bytes. They are not hosted billing, projected dollars, production SLA or provider/storage evidence.

## Migration and repair commands for V9-00

After the additive schema is deployed, run each bounded internal repair with an explicit cursor. Do not reset the database or invoke a whole-table `collect` migration.

```text
internal.calendar.backfillItemReadModels({ cursor: null, limit: 100 })
internal.calendar.backfillArtifactReadModels({ cursor: null, limit: 50 })
```

Repeat each command with its returned `cursor` until `done=true`. For legacy timetable content, an authenticated account can call:

```text
calendar.ensureLegacyMigration({ cursor: null, limit: 25 })
```

Repeat with the returned cursor; when a single artifact has more than 100 events, repeat the same artifact call until it returns `done=true`, because its durable `eventOffset` advances independently of the artifact-page cursor. These commands are bounded per invocation and safe to retry.
