# Whiteboard capability inventory

**Unit:** P12.I3

**Leaders compared:** Miro, FigJam, Excalidraw

**Baseline at unit start:** 28 registered whiteboard `CapabilityDefinition`s

**P12.I3 final IR census:** 90 definitions (`85 ship`, `4 refuse-honestly`, `1 defer-with-owner`)
**Disposition vocabulary:** `ship`, `refuse-honestly`, `defer-with-owner`

This is the P12.I3 contract under CANON R6, R7, and R26. A `ship` row must be reachable through the whiteboard capability IR by people and AI, use the same availability sentence on every path, and have a focused contract test. A refusal is a visible disabled capability with the sentence recorded below. There are no silent omissions.

## Mechanical closure rules

- Every ID above is registered in `capabilities/studio-whiteboard.ts`; refusal/defer rows carry the same disposition and plain-language reason in the IR.
- Every shipped mutating definition declares a whiteboard manifest operation, and the AI skill names the same operation families.
- `capability-conformance`, whiteboard operations, schema migration, keyboard/dispatcher, narrow-overflow, and frame-export tests grade the contract.
- The final census replaces the baseline above in the P12.I3 close-out after all definitions are registered.
