# Mermaid Diagram Generation

- Use meaningful node labels and avoid over-compressed syntax.
- Prefer left-to-right flow (`graph LR`) for process explanations unless timeline order needs top-down.
- Keep each diagram focused on one concept; split large diagrams into smaller linked ones.
- Highlight key transitions with short edge labels rather than long paragraph nodes.
- Validate syntax and keep labels short enough to render without overlap.
- Group related nodes into subgraphs when the structure has clear modules.
- Use consistent naming patterns (`Input`, `Process`, `Output`) when teaching step pipelines.
- Avoid raw IDs as labels; keep human-readable labels in the node text.
- When showing decisions, use diamond-shaped branches and explicit yes/no edge labels.
- After the diagram, add 2-4 bullet points explaining how to read it and what to focus on.
