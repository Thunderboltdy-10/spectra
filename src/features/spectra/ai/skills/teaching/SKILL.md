# Teaching

Use this when the user wants to learn or to help others learn: notes, explanations, revision
material, quizzes, flashcards, lesson plans. The goal is understanding the learner keeps, not
text that looks complete.

## Find the starting point

- Ask yourself what the learner already knows. Use the user's level (year group, course,
  exam board) from the conversation or their school data; if it matters and is unknown, ask
  once.
- Name the learning goal in one sentence before writing: "Explain why the seasons happen,
  using axial tilt, not distance from the Sun."

## Explain well

- **Concrete before abstract.** Start with an example or a phenomenon the learner has seen,
  then name the idea, then give the general rule.
- **One step at a time.** Introduce new terms one by one, each defined where it first appears.
- **Worked examples** for procedures: show every step with a short reason, then give a similar
  problem with less help (faded examples).
- **Contrast** for subtle distinctions: put the two ideas side by side (mitosis and meiosis,
  weather and climate) and point at the difference that matters.
- **Name misconceptions.** State the common wrong idea and why it is wrong ("Heavier objects
  do not fall faster in a vacuum").
- **Dual coding.** A simple diagram beside the words helps for processes, structures and
  relationships. Use a whiteboard, a chart or a widget when it explains better than prose.
- Keep it as short as the goal allows.

## Make them think

- **Retrieval practice** beats rereading: end longer material with a few questions that make
  the learner recall, not recognise.
- **Spacing:** suggest revisiting a topic after a day, then a week, rather than cramming.
- **Interleaving:** in practice sets, mix problem types once each type is understood.
- **Elaboration:** ask "why" and "how" questions that connect the new idea to what they know.
- Feedback explains the right answer and the reason the tempting wrong one is wrong.

## Honesty and integrity

- Never invent facts, dates or quotations. If unsure, say so or look it up.
- Help students do their own graded work: explain, question and give feedback, but do not
  write coursework for them to submit as their own.

## Shapes that work

| The learner wants | Make |
| --- | --- |
| To understand a topic | A document: hook, explanation, worked example, misconception, 3 check questions |
| To revise for a test | Flashcards for facts, a quiz for application, a short summary sheet |
| To practise a skill | Graded problems with worked solutions that fade |
| To see how something works | A widget or code visualisation with one interaction |
| To plan revision | A timetable with spaced sessions per topic |
