# Approach C: Focal Lenses

## Positioning

This is the most guided and premium-feeling shell.

It is useful if the team wants:

- stronger visual control,
- easier first-use comprehension,
- a more curated sense of focus,
- less reliance on raw spatial wandering.

It is less "pure canvas" than Approach B, but still uses the same engine.

## Core Metaphor

The user is looking through a lens.

- The world still exists beyond the lens.
- The active workspace is intensified.
- Nearby content is still present but optically demoted.
- The UI is not changing worlds. It is changing focal depth.

## Why it exists

Your concern about earlier Approach C was correct:

- a permanent bar can consume too much room,
- over-structuring the viewport can suffocate the active workspace.

This revised version fixes that by moving away from a permanent heavy dock and instead using floating lens utilities.

## Spatial Structure

```text
 overview world
 -------------------------------------------------------------
   faint workstreams              faint workstreams

                [ active focal lens ]
                Biology HL enlarged
              threads / docs / widgets emphasized

   faint workstreams              faint workstreams
 -------------------------------------------------------------
 floating utilities stay outside the lens boundary
```

## Lens Behavior

When a workstream is entered:

- its widgets sharpen,
- its color treatment strengthens,
- unrelated content softens,
- background workstreams remain in the same world but lose contrast,
- the lens boundary is implied through blur, lighting, and scale, not a hard frame.

## Distinct Visual Language

This shell should feel the most cinematic.

- layered translucency,
- localized sharpening,
- muted background scene,
- content that becomes fully legible only when brought into focal emphasis,
- utilities revealed inline by expansion rather than docking.

This is the shell where glass, blur, and depth are appropriate, but they must remain readable.

## Utility Model

This shell should use floating controls rather than edge-heavy behavior.

- command surface as a centered floating pill,
- timer as a corner chip,
- deadline utility as a small pulse badge,
- workstream shortcuts as a compact floating rail.

Utilities can still be pinned, but this shell favors elegance over maximal edge expression.

## Best Use of Categories

Categories should appear through scene depth:

- threads closer to the user on the left,
- documents slightly deeper,
- widgets and visual tools slightly offset,
- all still draggable.

This makes organization legible without needing visible containers.

## Right Panel Story

The right panel here should feel native to the lens.

- opening a widget causes the lens to bias toward the right,
- the panel emerges from the focal boundary,
- command surface transfers inward,
- closing the panel restores the lens balance.

### Motion Character

- scale and focus changes,
- strong foreground/background contrast shifts,
- less snapping than B,
- less drifting than A.

## AI-Native Behavior

This shell is strongest when AI is framed as an enhancer of attention.

Examples:

- "Bring revision tools forward."
- "Dim everything except exam prep."
- "Promote urgent deadlines into focus."
- "Reduce visual clutter in this workspace."

AI does not just create widgets. It can re-focus the lens state.

## Failure Modes

- can feel over-designed if the lens effect is too obvious,
- may reduce the sense of true freeform canvas,
- risks becoming visually beautiful but overly curated,
- if blur and opacity are overused, readability suffers.

## What Works

- easiest shell for immediate clarity,
- easiest shell to make feel expensive and polished,
- strongest first-use comprehension,
- very good for teacher flows and presentation-centric work.

## What Does Not Work

- weakest preservation of "I am in one infinite world",
- highest risk of giving away too much canvas freedom,
- can end up feeling like a controlled mode switch rather than a natural workspace,
- easy to make impressive in demos but restrictive in real usage.

## Verdict

Keep it as the most curated alternative.

This shell should influence visual focus and onboarding clarity, but it should not become the default if preserving the infinite canvas feeling remains a core product differentiator.

## Where it shines

- first-time users,
- users who want strong clarity immediately,
- teacher flows where presentation and lesson planning need visual control,
- high polish demos.
